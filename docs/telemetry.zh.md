# 匿名使用统计

[English](telemetry.md) | 简体中文

这份文档说明使用统计会上报什么、何时上报，以及怎样关闭或恢复上报。准备修改统计行为，或者想确认是否保留这项功能时，可以先读这里。

## 每个进程每天最多上报一次，而且要等宿主放行请求

服务端每个运行中的进程每天最多上报一次，而且只在宿主放行一个请求之后才发送。到这一刻，插件才能确定自己正在被使用。启动时不上报，关闭这项功能后也不上报。

上报只回答一个问题：有多少台机器真的在运行这个面板，分别运行哪个版本。它不需要账号，不需要我们自己的服务器，也不使用第三方 SDK。

## 这些数据是伪名化数据，不是法律意义上的匿名数据

准确的说法是**伪名化数据、无 IP、以随机 install id 关联**，不是法律意义上的匿名数据。不同时间的上报可以通过同一个 id 关联起来，所以它只用于估算装机量和版本分布，不用于计费或安全判断，也不用于对外公布精确数字。

## 请求体只包含这些字段

整个请求体如下，不会夹带其他内容：

| 键 | 值 |
|---|---|
| `v` | 载荷版本，固定为 `1` |
| `pkg` | `dsh-lingualab` |
| `version` | 这个包的 `package.json` 中的版本号，宿主加载时读取 |
| `id` | 随机生成的 UUID v4，只生成一次，保存在插件的 `installId` 配置字段中 |
| `node` | 只发送 Node 的主版本号，例如 `v22` |
| `os` | `linux`、`darwin` 或 `win32`；其他系统一律为 `other` |
| `arch` | `x64` 或 `arm64`；其他架构一律为 `other` |
| `metrics.episodes` | 媒体库根目录下的剧集文件夹数量，分为 `0`、`1-5`、`6-20`、`21+` 四档 |
| `metrics.ffmpeg` | 宿主能否找到 `ffmpeg` |

**绝不发送**文件名、目录路径、剧集标题、笔记、字幕、用户名、邮箱、token、session id、主机名或 IP 地址。

请求体通过 `POST` 发到 `https://t.hi-ruofei.com/v1/ping`，目标主机是 `t.hi-ruofei.com`。限时 5 秒，不重试、不写日志，也不等待结果。上报失败时不会提示；触发上报的那次请求早已返回，不会因为上报而等待。

## 使用统计默认关闭，可以从两个入口打开

上报**默认关闭**。要打开它，把插件 profile 条目里的 `telemetry` 字段设为 `true`，可以在「插件」页修改，也可以改 `cordis.patch.yml`。要关掉，把同一个字段设为 `false`。关闭状态下，插件不会生成 id，不会列出媒体库，也不会发送任何请求。

插件会把随机 id 写进 `installId`，让重启前后仍使用同一个 id。这个字段不是供你选择的配置值，所以界面会隐藏它。

## install id 不合约定时，插件既不上报，也不覆盖

如果 `installId` 里存的不是 UUID v4，无论是手动改错的，还是只写入了一半，插件都既不上报，也不覆盖原值。这样处理有三个原因：

1. 不符合约定的字符串不该计入统计。
2. 截断的值熵更低，与其他安装使用同一 id 的概率也更高。
3. 覆盖原值可能把同一次安装拆成两个身份，因为插件无法判断这个值是否曾经对应一个已经上报过的 id。

大写 UUID 仍表示同一个 id，插件会照常接受，只是上报时统一转为小写。

要恢复上报，可以把 profile 的 `cordis.patch.yml` 中这个字段改成 UUID v4，也可以清空字段，让插件生成新 id。清空字段会开始一个新的安装身份。修改后要等配置生效；如果直接改了文件，就需要重启。之后，下一个被宿主放行的请求就会触发上报，不用等满一天。
