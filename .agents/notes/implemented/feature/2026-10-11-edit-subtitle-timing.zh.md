# Agent Note: 调整一句的时间

Status: implemented

## Problem

网上找来的字幕，时间常常差一点：一句比人声早开始一拍，或者拖进下一句的第一个词。这一页是围着循环一句来做的，所以这不是小瑕疵。
每循环一遍，都会切掉半个词，或者带出下一句的一个片段；跟读停的位置也不对。读者除了用别的工具打开文件、猜毫秒数、再重新加载之外，
什么也做不了。

问题是逐句的，不是整个文件的：读者看到的是某一句不对，它前后的句子都没问题。整体偏移解决不了这种情况。

## Decision

**舞台上那一句的开头和结尾可以调整，改动写回字幕文件。** 这样别的播放器和 agent 读到的也是改好的文件，页面也不会多出第二个时间来源，
需要和文件对账。

**编辑器是舞台下面的一条横栏，从时间范围打开。** 舞台上已经显示这一句的时间范围（`00:18 – 00:22`）；点它、按 `T`，
或者在「更多」里选「调整这一句的时间」，都会打开一条横栏，精确到毫秒显示开头和结尾（`00:18.250`），各带微调按钮。
横栏打开时这一句一直循环，所以每次改动在下一遍就能听到。横栏打开时键盘归它：

| 键 | 作用 |
|---|---|
| `Tab` | 在开头和结尾之间切换 |
| `←` `→` | 把当前这一端微调 50 毫秒 |
| `Shift` + `←` `→` | 微调 250 毫秒 |
| `I` / `O` | 把开头 / 结尾设到当前播放位置，和剪辑软件的入点、出点一样 |
| `Space` | 播放或暂停 |
| `Enter` | 保存 |
| `Esc` | 不保存，关掉 |

没有波形（见
[2026-10-08-v1-without-waveform](../../implemented/simplification/2026-10-08-v1-without-waveform.zh.md)），
耳朵就是工具：靠循环，靠边听边按 `I` / `O`，定位一句的边界才可行。边界碰到相邻的句子时推着它走，而不是停住。
很多文件的句子是首尾相接切的，一句的开头就是上一句的结尾，人声提前开始的那一句，只有把开头挪进上一句才改得过来。
这时上一句的结尾跟着挪（结尾挪过下一句的开头时，下一句的开头也一样），横栏在按键说明下面写出来，保存时两句一起写。
推到相邻那句只剩 0.2 秒就停，每一句也都至少 0.2 秒长。原来就有重叠的文件，在边界推进重叠之前保留它已有的重叠。

**保存只改时间那一行，别的都不动。** host 在文件的字节里找到这一句的时间行，只替换其中的时间。序号、文本、样式标签、空行、
换行符和编码都不变。GBK 和 GB18030 的文件也是这样保住的：时间是 ASCII，在这两种编码里和 UTF-8 逐字节相同，
所以它周围的字节不需要解码再编码（Node 没有 GBK 编码器）。带 BOM 的 UTF-16 文件，借 Node 自带的 UTF-16 支持重写。
新的时间按那一行原来的格式写：毫秒前面用 `,` 还是 `.`，小时写几位，都和原来一样。

**按文件里写的内容定位一句，页面过期就拒绝。** 请求里写明文件、这一句原来的开始和结束（毫秒），以及在时间范围完全相同的几句里
它是第几句（几乎总是第一句）。请求还带着页面解析时那份字节的哈希。如果文件在那之后变过，host 回 `409` 并说明原因，
页面重新加载字幕，而不是覆盖一次它没见过的修改。写入先写临时文件，再 rename 到位，和进度文件一样，因为替换这个文件正是目的。
第一次写某个文件之前，host 把原文件复制一份到旁边的 `<name>.bak`，只复制一次，以后也不覆盖它。

**中文在另一个文件里的句子，两边一起改。** 页面按开始时间把中文轨折进英文轨，容差 0.6 秒。只改英文的开头，可能让配对失败，
中文那一行就丢了。所以中文来自单独的文件时，和它配上的那一句会在那个文件里做同样的改动，放在同一个请求里。
一个文件里同时有两种语言的双语文件，就是一个文件、一处改动。

**LRC 只有开始时间。** 一行在下一行开始时结束，所以只能改开头，结尾显示为下一行的开头，只读。

**只有库里的文件能改。** 文件剧集的字幕放在读者自己放的地方，不在这个插件会写入的文件夹里。对它们横栏也能打开，
但会说明为什么不能保存。文件夹剧集和库根目录下散放的文件都在库里。

**收藏跟着句子走。** 收藏按整秒加文本匹配。开头跨过一个整秒时，页面会在字幕保存成功之后，改写笔记里那条收藏的 `at`，
星标就不会掉。

**host 多一条写入路由。**

```ts
// POST /lingualab/subtitle-timing
export interface TimingEdit {
  /** The subtitle file's name inside the episode folder. */
  readonly file: string
  /** The cue as the file has it now, in milliseconds. */
  readonly from: { readonly start: number; readonly end: number; readonly occurrence: number }
  /** The new range, in milliseconds. For LRC only `start` is used. */
  readonly to: { readonly start: number; readonly end: number }
  /** SHA-256 of the bytes the page parsed, hex. */
  readonly expect: string
}

export interface TimingWriteRequest {
  readonly episode: string
  /** One edit, or two when the Chinese lives in its own file. */
  readonly edits: readonly TimingEdit[]
}
```

两处改动都检查通过之后，才会写任何一个文件，所以不会出现一句话在一个文件里挪了、在另一个文件里没挪的情况。

**不在这次范围内：** 整个文件的偏移和两点线性校正（读者遇到的问题是逐句的）；波形；拆分或合并句子；编辑文本；
以及 `.bak` 副本和「把旧时间再存一次」之外的撤销。

## Alternatives considered

- **把校正存在文件旁边，放在库根目录的一个隐藏 JSON 里，加载时套上。** 和格式无关，可以撤回，素材目录也只保留原来的三处写入。
  但别的播放器和 agent 都看不到这些校正，而且文件一旦被替换，页面就有两个各走各的时间来源。
- **解析整个文件、修改、再序列化。** 代码更简单，但解析器会丢掉它用不上的东西（序号、样式标签、解析不了的块），还会给句子排序，
  所以保存一次会把读者的文件改得远不止那一句，GBK 文件也会变成 UTF-8。
- **按解析后列表里的序号定位一句。** 解析器会排序、会丢块，页面里的序号不是文件里的序号。
- **先做整个文件的偏移。** 这是字幕工具里最常见的修正，但不是这里说的问题，而且以后可以在同一条路由上很容易加上。

## Consequences

- 素材目录多了第四处写入：库里的字幕文件和它们的 `.bak` 副本。`AGENTS.md` 和技能的约定 4 要把它列上。
- `T` 加入「更多」里的按键列表，「更多」里也多一项用来打开横栏；横栏自己的键（`I`、`O`、`Tab` 和方向键）写在横栏上，
  在那里才生效。
- 句子类型要带上每一句的出处（文件、原来的时间范围、第几句，以及配上的中文那一句的这些信息）。解析器和合并负责记下这些，
  返回给其他代码的内容不变。
- 新路由意味着 `dsh-plugin.naming.json` 和 README 的路由表都要改（`check-host.mjs` 拿记录和 `protocol.ts` 比对，
  不用另改），host 半边也要重启。
- 这一项排在复习收藏
  （[2026-10-11-review-kept-sentences](2026-10-11-review-kept-sentences.zh.md)）之前，因为逐句循环的复习依赖句子的边界准确。
- 页面用自己实现的 SHA-256 算哈希，不用 `crypto.subtle`：它只在安全上下文里存在，从另一台机器用普通 HTTP
  打开 dsh web 时，编辑器就永远存不了。
- 每一端都按文件里相邻句子另一端的时间限住；播放条换到别的句子（或循环某一句）时编辑结束，横栏不会去改一句没在播的边界。
