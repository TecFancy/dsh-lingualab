# Agent Note: 点一下就选好倍速

Status: implemented

## Problem

控制栏上的倍速按钮原来每点一下升一档，到最高一档后回到最低一档。一共十档（0.5、0.6、0.7、0.8、0.9、1、1.15、1.25、1.5、2），
所以要点几下取决于想去哪一档，而想调慢总要先绕过所有更快的档位：

- 从 1× 到 0.6× 要点六下，中途经过 2×；
- 从 2× 回到 1× 要点六下，把慢的档位全走一遍；
- 多点一下就要绕一整圈：还得再点九下，才能回到本来想要的那一档。

`[` 和 `]` 一档一档地调慢、调快，不会绕圈，用键盘时好一些，但远距离跳转仍然是一档按一下，而 iPad 上根本没有键盘。
对学习者来说，调倍速是很频繁的动作（遇到难句放慢，听完再调回来），所以这些点击次数每次练习都要付很多遍。

用户在 2026-10-23 提出这个问题。方案当天写下，也在当天分两步做完：先做选择框，再做 `=` 键。

## Decision

**倍速按钮弹出一个选择框，点一下档位就选中。**

- 按钮上照旧显示当前倍速。点它会在上方弹出一个弹层，十个档位排成三行小按钮：第一行是五个慢的档位，第二行只有 1×，
  占满整行，第三行是四个快的档位。1× 是用户最常回到的倍速，所以给它最大的点按区域。当前倍速带描边，并带 `aria-pressed`。
- 点一个档位就切到这个倍速，弹层随即关上，焦点回到倍速按钮。任何倍速都只要点两下，点错了再点两下就改回来。
- 倍速按钮在这一行的最左边，所以选择框从按钮的左边缘向右展开，宽度不超过视口。
- 关闭方式和「字幕」一样：在弹层外按下或按 `Esc`，之后焦点回到按钮。选择框和「更多」菜单共用一个「打开了哪个」的状态，
  打开其中任何一个都会关上「字幕」，所以同一时间只开一个弹层。
- 「在外面按下就关上」写成一个 hook，即 `widgets/control-bar/lib/usePopover.ts`，三个弹层都用它。它仍然在 `window` 上
  监听 `mousedown`，和它替换掉的那两段代码一样。
- 在触屏上，每个档位按钮至少 44px 宽、44px 高。档位按钮用自己的类名，不用这一行按钮的类名；调整时间时，
  隐藏这一行弹层的那条规则也不会藏掉它：倍速按钮是调整时间时唯一保留的控件，它的选择框在那时也能用。
- `nextSpeedWrapping` 不再有人调用，已删掉。

**`=` 回到 1×，再按一次回到之前的倍速。**

- 当前不是 1× 时，`=` 切到 1×。
- 当前是 1× 时，`=` 切到上一次用过的、不是 1× 的倍速，不管它当时是怎么选的（选择框、`[` `]` 或 `=`）。
  还没用过别的倍速时，这个键不归页面处理：键盘表什么也不返回，按键留给浏览器。
- 记住的倍速是播放器 store 里的 `lastSpeedIndex`，挨着 `speedIndex`。和当前倍速一样，换剧集时保留，刷新页面就没了。
- 改倍速时记住什么、`=` 切到哪一档，由 `features/media-player/lib/speed.ts` 里的两个纯函数算出（`chooseSpeed`、
  `speedResetIndex`），十个档位现在也放在这个文件里。store 里所有改倍速的动作都经过 `chooseSpeed`。
  键盘表通过上下文里的 `canResetSpeed` 知道 `=` 有没有地方可去，和 `V` 知道有没有视频的方式一样。
- 「更多」里的快捷键表把 `[  ]  =` 写成变慢、变快和正常速度。

## Measured

在链接了这个分支的 dsh web 0.2.1-rc.2 实例里，用一集素材的副本（496 句），视口 1400 乘 900：

- 选择框宽 326px，左边缘和按钮的左边缘对齐（501px）。三行分别是五个 57px 的档位、一个 300px 的档位、四个 72px 的档位，
  用鼠标时每个高 32px。
- 点 0.6×：按钮显示 0.6×，媒体元素的 `playbackRate` 变成 0.6，选择框关上，焦点留在按钮上。
- 先打开选择框再打开「更多」，只剩「更多」开着，反过来也一样。`Esc` 关上选择框，焦点回到按钮；在舞台上按一下也会关上它。
- 调整时间的面板开着时，选择框能打开，显示当前倍速；按两次 `Esc`，先关选择框，再关面板。
- 还没用过别的倍速时在 1× 按 `=`：什么都没变，事件没有被 `preventDefault`。然后按 `]`（1.15×）、`=`（1×）、`=`（1.15×）；
  在选择框里选 0.7×，`=`（1×）、`=`（0.7×）。`playbackRate` 每次都跟着变。
- 视口 768 乘 1024 时，选择框仍在视口里（101px 到 427px）。console 没有报错。

44px 的档位按钮只经过样式表测试检查，还没有在 iPad 上用手指试过选择框。

## Alternatives considered

- **在倍速两边放减号和加号按钮。** 点错了点一下就能改回来，但远距离跳转仍然是一档点一下：从 1× 到 0.6× 要点四下。
- **滑块。** 拖一下就能到任何倍速，但用手指很难正好停在某一档上，而且控制栏上没有它要的那么多空间。
- **把所有档位一直摆在控制栏上。** 完全不用弹层，但十个按钮和这一行的其他控件放不到一起。
- **选择框里十个档位排成一行，1× 和两边隔开一点。** 这是原来的方案。排成三行，1× 的点按区域和选择框一样宽；
  在一个和「更多」差不多大的弹层里，每个档位也还够手指点。
- **长按或双击按钮回到 1×。** 屏幕上没有任何东西告诉用户有这个功能；而且双击会先触发一次单击，倍速会先变一档再被重置。
- **只在几个常用倍速之间循环。** 点的次数少了，但要另加一个设置来选哪几个常用，而且常用之外的倍速就没法从按钮上选到了。
- **`=` 只回到 1×。** 更简单，但遇到难句放慢、听完调回原速的学习者，每次想再放慢都得打开选择框。
- **`=` 总是由页面处理，1× 且没有记住的倍速时什么也不做。** 键盘表的上下文少一个字段，但这个键会被吃掉却什么也不做，
  页面的其他键都不这样。

## Consequences

- 「正常速度」指的是 `DEFAULT_SPEED_INDEX`。如果默认倍速哪天不再是 1×，`=` 就会切到新的默认倍速，快捷键表的说明也要跟着改。
- `ControlBar` 函数缩短了一档，`.betterer.results` 里的 baseline 已经更新。这个文件本身已接近它所在档位的上限（460 行，
  按体量门的算法计），所以这一行再加控件时，要像选择框一样单独写成组件。
- `toggledMenu`、`escapeToClose` 和 `focusButton` 跟 hook 一起放进了 `usePopover.ts`，这一行如果再加第四个弹层，
  直接复用它们，不用再抄一遍处理函数。
- 播放器下面那一排按键提示仍然不显示倍速的键，`[  ]  =` 只列在「更多」里。
- 仓库的组件测试把组件渲染成字符串，所以「在外面按下」是通过 hook 的 effect 主体 `watchOutside` 测的，
  弹层之间的切换是通过 `toggledMenu` 测的，而不是真的去按按钮。
