# Agent Note: 把跟读做成复读机完整的核心闭环

Status: implemented

## Problem

这个面板的用途，是替代实体复读机来练听力和口语。复读机做的是一个闭环：放一句，留出时间让用户说，把用户说的和原声对比，
再往下走。听的那一半大多已经有了：单句循环（`L`）、带次数的 A-B 循环、十档变速不变调，还有提前起播。说的那一半只做了第一步。

跟读现在的行为（`features/media-player/model/store.ts` 里的 `onTime`）：模式打开且没开循环时，一句话播放期间英文是模糊的，
播完就停下，退回句首，同时设上 `revealed`，所以一停下英文就揭开了。按播放会再听一遍；切句会跳到下一句并开始播放。
由此有四个缺口，2026-10-14 对照 v0.11.5 核实过：

1. **没有录音。** 跟读那一步的提示（`stepTipShadow`）写着「开跟读，录一遍对比」，可源码里没有任何录音功能。
   拿自己的声音和原声对比，正是人们买复读机的理由。
2. **揭晓的时机和文案对不上。** `shadowHint` 和 README 都说「你先说，再按 R 揭晓」；store 却在停下时就揭开了，
   用户还没开口，答案已经在屏幕上。
3. **跟读和循环不能同时用。** 只有 `loopMode` 为 `none` 时才会停下，次数也只给 A-B 循环用。复读机最基本的程序
  「每句放两遍，每遍后停一下让用户复述，再到下一句」设置不出来，所以每一句都要用手去点。
4. **没有实体按键。** 页面没有 Media Session 处理函数。iPad 不接键盘时，`Space`、方向键和 `R` 都用不了；
   耳机或 AirPods 上的按键对句子也不起作用。

v0.8 以来的版本都花在布局、视频、主题和调整时间上。每一项都是合理的配套工作，但都没有推进上面这个闭环。
这篇 note 定下了今后衡量新功能的标准：一项改动值得做，要么增加了每分钟用耳朵听、用嘴说的时间，要么让手离开屏幕。
文本是答案，不是练习材料。

## Decision

分四块，按这个顺序做。每一块都能单独发布，用户不打开时，默认行为保持不变。

1. **把跟读做成按句执行的程序。**
   - 跟读模式下，「更多」菜单里提供三个设置：每句播几遍（1、2 或 3）；每遍之后留出的复述停顿
     （关、与这句一样长、这句的一倍半，后两种再加一秒）；以及要不要自动进入下一句。
   - 默认值（播一遍、不停顿、不自动下一句）就是现在的行为。
   - 决策放进一个和 `planLoop` 并列的纯函数（`planShadow`：给定时间、句子、第几遍和设置，返回播放、等待、
     退回、下一句还是停止），不用浏览器就能测试；store 只负责执行。
   - 每次重播都带上提前起播，和循环一样。`Space`、切句或点进度条，都会干净地结束程序当前这一遍。
   - 打开停顿和自动下一句后，页面就能完全不用手地运行下去；这也足够接近同步影子跟读，不必为它单独做一个模式。
2. **揭晓放在一次不看字幕的复述之后。** 英文在第一遍播放和它的复述停顿里都保持遮住，从第二遍起揭开；只播一遍时，在停顿结束时揭开。
   开了自动下一句时，揭开的句子会在屏幕上停留一个停顿的时长，再开始下一句。`R` 和按钮仍然随时可以揭开。提示和 README
   改写成实际的行为。
3. **录音并对比。**
   - 跟读设置里加一个麦克风开关。打开后，每段复述停顿都用 `MediaRecorder` 录下来；停顿结束时，页面先把原句
     再放一遍，接着放用户的录音。一个「对比」按钮（以及一个按键）之后还能重放这一对。
   - 每句只保留最后一次录音，存在内存里，只属于当前打开的这一集，关掉就丢弃：从不写盘，从不发给服务端，从不打分。
   - 录音在原素材暂停时，用一个临时的音频元素播放；那一个 `<video>` 元素仍然是原素材唯一的时间线。
   - 每次录完都关掉麦克风流，因为 iOS 在麦克风打开期间会压低播放音量。
4. **通过 Media Session 接入实体按键。** `play` 和 `pause` 切换播放，`previoustrack` 和 `nexttrack` 切句，`seekbackward`
   重放这一句，元数据写上剧集名和第几句。这样 AirPods、有线耳机的按键、iPad 锁屏和会发媒体键的蓝牙遥控器，就起到了
   复读机实体按键的作用。它不是键盘监听，所以不涉及「不占用宿主键盘」那条规矩。

## Alternatives considered

- **用识别器给发音打分。** 第一版的 note 没有做它，理由是它会「在习惯养成之前，就把听的习惯变成打分循环」；
  习惯仍然是重点，而分数会让人回去读文本，而不是再听一遍。口语上的反馈留在和 agent 的对话里。不在这份计划之内。
- **用分级提示（首字母、实词挖空）代替模糊。** 它们会在该用耳朵的时候把目光拉回文本上，这正是这篇 note 要防止的偏离。
- **靠检测静音来结束复述停顿。** 比固定停顿方便，但麦克风得一直开着、实时分析音频，而且结束时间无法预期的停顿，
  在不用手的时候更难依赖。等录音做出来、用过一阵再考虑。
- **整段录音，而不是一句一句录。** 复读机是按句对比的；一段长录音很难在里面找到位置，也没法放在它所属的那一句旁边。
- **把录音存进 IndexedDB 或剧集目录。** 要处理配额、清理，还要为本来就该丢掉的东西说明隐私问题。把录音发给 agent
  是以后另外的决定。
- **单独做一个同步影子跟读模式。** 不停顿加自动下一句的程序，已经是遮着英文一句接一句地放；第二个模式意味着第二套要学的规则。

## Settled details

- **顺序。** 程序和揭晓（第 1、2 块）先做：它们修正现在错误的文案，也让页面不用手就能用。录音（第 3 块）工作量最大，
  而且依赖程序产生的停顿。Media Session（第 4 块）很小，和哪一块一起发布都行。
- **控件放在哪里。** 「跟读」芯片留在播放行上；它的设置放进「更多」，挨着提前起播，播放行不变长。录音做出来之后，
  步骤卡片上跟读那条提示才符合实际。
- **第 1、2 块已经做好（2026-10-15）。**
  - `planShadow` 和 `shadowPauseMs` 在 `features/media-player/lib/shadow.ts`；停顿是 store 里的 `shadowWait`
    （哪一句、哪个阶段、何时结束），结束它的计时器在 `useMediaBinding` 里，所以停顿不会在程序或页面结束后还留着。
  - 做的时候定了三件事：
    - 停顿按播放速度计算，因为半速听到的句子，说出来也差不多那么慢。
    - 停顿期间播放按钮显示为暂停，按它会在句首结束程序，而不是跳过剩下的停顿，因为程序运行中伸手去按按钮的用户，要的是停下来。
    - 用别的方式开始或停止播放（点一行、复习、回首页）也会结束程序。
- **第 3 块已经做好（2026-10-15）。**
  - 麦克风开关就是 `ShadowSettings` 里的 `record`。录音只发生在复述停顿之内，所以这个设置跟着停顿联动，
    而不是在停顿关着时把开关禁用（那样用户会陷入一个得自己退出来的死胡同）：停顿关着时打开开关，会把停顿设成
    和这句一样长；把停顿关掉，开关也跟着关（`mergeShadow`，只在这一处，有测试）。
  - 录过音的停顿通过 `planShadow` 转入对比（传入 `compare`，得到 `{ do: 'compare' }`）。store 里的 `compare` 状态先用源媒体
    播放这一句，再用共享的录音 `Audio` 元素播放录音，这时源媒体停在句首等着；然后像停顿刚结束那样再问一次 `planShadow`，
    所以对比不算作一遍播放，程序接下来做的正是它本来要做的事。
  - `compare` 和停顿一样由 `IDLE_PROGRAM` 清掉，用户播放、切句、拖进度条或开循环时，录音和录音的播放就是这样停下的。
  - 浏览器相关的代码在 `features/media-player/lib/recorder.ts`（`MediaRecorder` 和 `getUserMedia` 放在一个
    环境对象后面，用假对象测试），由一个钩子 `useTakes` 驱动，因此 store 不碰浏览器对象。
  - 按键是 `D`，取按钮名「对比」拼音的首字母（`C` 已经用于中文显示）。
  - 每句最后一遍录音放在 store 里，随字幕列表、回首页和页面卸载一起丢弃；一个纪元计数器会丢弃在那之后才录完的录音，
    这样它不会落进下一集。
  - 用户提前结束停顿时，保留到那时为止说的内容；短于 0.4 秒的录音直接丢弃，免得误按一下就替换掉一遍好的录音。
  - 授权弹窗在打开开关时出现（试探一下，立刻释放麦克风），而不是在第一次停顿中间出现；授权在停顿结束之后才到的录音会被丢弃；
    任何失败都会把开关关上并给一句提示，程序保持原样。
  - 录音按正常速度播放，不管源媒体是什么速度。
  - 录音元素是一个共享的元素，而不是上面提案里每遍一个用完就丢的元素，并且在手势里解锁过。原因是：iOS Safari 只允许
    曾在手势里播放过的那个元素在之后不经手势发声，而免手动的程序要在最后一次触碰很久之后才播放录音，所以每遍新建一个元素
    每次都会被拒绝。
  - `primeTakeAudio` 在这个元素上播一小段静音，只有浏览器接受了才算完成，被拒绝的尝试会在下一次手势时重试。
    它在这些地方调用：麦克风开关、「对比」按钮、播放按钮、空格键和 `D` 键，还有面板容器上捕获阶段的一个监听（绝不挂在 `window`
    或 `document` 上），这个监听是给录音开关从上次就开着的用户准备的。播放按钮、空格键和容器监听只在录音开着时才调用它。
  - 播放录音时只是换这个元素的 `src`，释放时清掉处理函数和来源，但保留元素。
- **第 4 块已经做好（2026-10-15）。** `useMediaSession`（在 `features/media-player/lib/`，由页面调用）在练习视图打开期间
  接管 Media Session，视图关闭时交还，不论是回首页还是页面卸载：处理函数、元数据和状态（`'none'`）都会清掉。它注册
  `play`、`pause`、`stop`（和暂停一样处理）、`previoustrack` 和 `nexttrack`。没有设置项，因为没有处理函数时，浏览器的默认行为
  会绕过 store 直接播放或暂停媒体元素；而复述停顿正是程序运行中媒体暂停的状态，默认行为恰好会在程序最关键的地方出错。
  浏览器相关的代码在 `media-session.ts`，放在一个环境对象后面（`navigator.mediaSession` 可能不存在，`setActionHandler`
  遇到浏览器不认识的动作会抛错，所以每一次调用都包了 try/catch），用假的 session 测试。store 不碰浏览器对象。做的时候定了这些：
  - **只有一个切换入口。** `togglePlayback`（`lib/transport.ts`）由播放按钮、`Space`、调整时间横栏里的 `Space` 和 Media Session
    处理函数共同调用：录音开着时先解锁录音元素（从处理函数里调用没有坏处，浏览器接受了才算数），再执行 store 的 `toggle`。
    所以在复述停顿或对比期间按耳机，会像按按钮一样在句首结束程序。`isRunning` 是「按钮显示为暂停」的唯一定义
    （正在播放、正在等停顿结束，或正在对比）。
  - **播放和暂停带条件，而不是直接切换。**
    - `pause` 和 `stop` 只在有东西运行时才起作用。
    - `play` 在没有东西运行时起作用；程序在运行而媒体停着时（复述停顿里，或对比中正在放录音）也起作用，这时和按钮一样结束程序。
      原因是 iOS 可能根据媒体元素的状态决定发哪个键，而媒体在那时是停着的，所以用户想停下的那一下会以 `play` 的形式到来。
    - 只有媒体真在播放时收到的 `play` 才被忽略。（最初的版本在程序运行时一律忽略 `play`，那样在复述停顿里按一下就会没有反应。）
  - **上一首、下一首和方向键的行为一致。**
    - 练习时它们前进或后退一句，并清掉舞台上的选中，和按钮、方向键一样。
    - 复习进行时按键作用于队列，所以耳机的上一首在队列里后退，下一首跳过当前这条；复习结束后的小结（按键不处理的对话框）也不处理。
    - 调整时间横栏打开时，方向键是在微调一条边，这在耳机上没有意义，所以上一首、下一首像横栏自己的按钮一样切句。
    - 只和焦点有关的情况（浮层打开、设置抽屉）对耳机不适用。
  - **不注册 seek 处理函数；`seekbackward` 和 `seekforward` 明确设为 `null`，`seekto` 从不注册。** 这和提案不同，
    提案里 `seekbackward` 用来重放这一句。在 iOS 上，注册 seek 处理函数会让锁屏和 AirPods 显示并发送「跳过 N 秒」，
    取代上一首、下一首，句子步进就没了；而跟读在句首停下之后，按播放本来就是重放这一句。明确清掉这两个，
    也是为了防止页面上别的代码注册了处理函数。
  - **元数据。** 标题是这句的位置，用的是顶栏已有的措辞（「第 12 / 80 句」、"Sentence 12 of 80"），艺术家是剧集名，
    打开了某一段时后面再加上段名，专辑是插件的名字。还没有哪一句处于活动状态时，用剧集名代替标题。`sessionMetadata`
    是纯函数，有测试；只有其中的文字变了才会重建对象。
  - **播放状态。** 程序运行时（正在播放、复述停顿、对比）是 `'playing'`，否则是 `'paused'`，由对 store 的订阅保持同步，
    值变了才发送。复述停顿期间报告 `'playing'`，是为了让锁屏在程序运行时显示「暂停」，这样按一下是结束程序，
    而不会被当成开始。

  四块都做好了，所以这篇 note 从 `proposed/` 移到了 `implemented/`。还没完成的是下面那份清单，需要真机验证。
- **第 3、4 块算完成之前，要在真 iPad 上核实：**
  - Safari 里 `MediaRecorder` 录的是 `audio/mp4`；
  - 关掉麦克风后播放音量能恢复；
  - 录音能免手动播放；
  - AirPods 的 Media Session 动作能到达页面，AirPods 和锁屏显示的是上一首、下一首（而不是跳过几秒），复述停顿期间显示的是「暂停」；
  - 线上站点通过 HTTPS 提供，因为 `getUserMedia` 拒绝不安全的来源（localhost 例外）。
