# Agent Note: 在页面里播放视频剧集

Status: implemented

## Problem

第一版有意不做视频（[第一版不带波形、视频和跟读评分](../simplification/2026-10-08-v1-without-waveform.zh.md)）：
视频放在 NAS 上，文件大，内嵌就意味着要经过家里的上行带宽做 Range 请求。方法里的「无字幕盲看」那一步是在外部播放器里做的。

2026-10-12，一集的视频被复制进了工作区，和它的音频、字幕放在一起（`S01E01/MDJT S01E01.mkv`，1.1 GB，23 分钟），
复制方式和音频一样（[剧集素材留在工作区](../architecture/2026-10-08-media-stays-in-the-workspace.zh.md)）。
文件到了本地，NAS 那条理由就不成立了，于是问题变成：页面能不能播放它。

照现在的样子不能，而且不只是因为扫描不认视频。探测这个文件，能看出一集下载来的视频通常长什么样：

| 轨道 | 编码 | 浏览器里 |
|---|---|---|
| 视频 | H.264 High，1280×720 | 能播放 |
| 音频 | DTS 5.1 | **没有任何浏览器能解码 DTS** |
| 字幕 | SubRip，中文和英文，内嵌 | `<video>` 不显示 |

Chromium 对 Matroska 容器也只是部分支持。把这个文件直接交给 `<video>` 元素，最好的结果也只是有画面没声音。
视频必须先转换一次，页面才能播放，而这正是这个功能里需要做决定的部分。

## Decision

**视频是同一段的另一个来源，在读者要求时转换一次，放进隐藏的缓存。**

- **认哪些文件。** `mkv`、`mp4`、`webm` 和 `mov` 作为视频加入扫描。视频按词干归到它的段上，规则和字幕用的是同一条（`src/shared/stem.ts`），
  所以 `MDJT S01E01.mkv` 属于 `MDJT S01E01.mp3` 那一段，这个文件夹仍然是一集一段。旁边没有音频文件的视频自己算一段。
  剧集卡片和分段列表上显示一个小的视频标记。
- **转换前先探测。** host 对文件跑一次 `ffprobe`。浏览器能原样播放的视频（`mp4` 或 `webm`，里面是 H.264、VP9 或 AV1，
  配 AAC、Opus 或 MP3）直接播放，什么也不写。其他的都要先准备。
- **准备是换封装，不是重新编码。** `ffmpeg` 原样复制视频轨，只转换音频，转成双声道 AAC（取第一条英文音轨，没有就取第一条），
  输出成索引放在文件开头（`+faststart`）的 `mp4`，这样一开始就能通过 Range 请求拖动。这个文件大约要一分钟，而不是一集的长度。
  视频本身的编码浏览器解不了的（HEVC、MPEG-4 Part 2、VC-1），不重新编码：在这台机器上重新编码 23 分钟的画面，比看完它还慢，不在这次范围内。
  准备这样的视频时只提取它的声音，所以一段即使没有自己的音频文件，也照样能靠耳朵练。
- **准备好的文件放在隐藏缓存里**：`<集>/.lingualab/<词干>.mp4`，只能保住声音时是 `<词干>.m4a`。扫描本来就跳过以点开头的名字，所以缓存不会作为单独的文件出现。
  它先写成 `.part` 再改名到位，属于插件自己，删掉这个文件夹只意味着要重新准备。源视频永远不会被改动。这是写进媒体库的第五处，
  和 `notes.md`、进度文件、导入、字幕时间并列，做的时候技能里列出的写入清单要加上它。
- **由读者发起。** 打开一段视频还没准备好的段时，舞台上显示「准备视频」操作，附上预计大小。准备一次只跑一个 host 任务，
  报告进度（用 `ffmpeg -progress` 对照探测到的时长），可以取消，期间音频照常能播。崩溃或重启留下的 `.part` 下次清掉。
- **只有一条时间线。** 一段有了能播放的视频后，播放器就用它，它的声音就是这次练习的声音。字幕、循环、收藏和时间调整都照常工作，
  因为它们都按这条时间线上的秒数定位。如果视频和音频文件的时长差了一秒以上，页面提示字幕可能对不上，但照样播放。
- **舞台上的画面。** 视频放在舞台顶部，当前句在它下面；舞台字幕仍然是我们自己画的，所以显示模式、点词气泡和舞台字号都照样有效。
  `V`（以及播放卡片上的一个按钮）在三种状态间切换画面：**显示**，**大画面**（画面占满舞台，句子文本隐藏，用于盲看那一步），
  **隐藏**（舞台和现在一样，声音仍然来自视频）。这个选择按设备记住，和其他设置一样。
- **ffmpeg 属于 host，而且可选。** host 在 `PATH` 里找 `ffmpeg` 和 `ffprobe`，或者读一个可选的 `ffmpegPath` 配置项。
  没有它们时，能直接播放的视频照样播放，需要准备的会说明情况，并给出安装命令。两个程序都用参数列表启动，从不经过 shell，
  路径都是 host 自己解析出来的。
- **只限媒体库内。** 准备要写进媒体库，所以从工作区别处打开的视频，只有能直接播放时才播放，边界和字幕时间划的一样。
- **导入接受视频**，规则和音频相同：不覆盖、2 GB 上限、先写 `.part`。

这一轮不提取内嵌字幕。常见情况下视频旁边已经有字幕文件了（这一集就有），而提取字幕是另一处写入，有它自己的问题
（图片字幕怎么办，已有文件和内嵌轨哪个优先）。

## Alternatives considered

- **直接播放 `.mkv`。** 不用写文件，也不用 ffmpeg，但 DTS、AC-3、TrueHD 音频都没有声音，而下载来的素材大多是这些，容器的支持也不完整。不采用。
- **用 ffmpeg 实时转码、边转边传。** 磁盘上没有缓存，但管道流没有长度，回答不了 Range 请求，每拖动一次都要重启一个进程，
  而整个方法就是在拖动。不采用。
- **静音的画面跟着现有的音频文件走。** 保住了字幕当初对照的那份音频，但两个媒体元素会漂移，每次拖动、变速、循环都要做两遍并保持同步。
  一个元素一条时间线更简单，而时长检查能抓住两个文件真的不一样的情况。
- **把准备好的 `mp4` 写在源文件旁边。** 看得见、好找，但它是读者自己的文件夹里第二个同词干的媒体文件，插件会用一个读者没放进去的文件把文件夹弄乱。
- **导入时转换，或者后台批量转换。** 省一次点击，但会在可能几周都不学的剧集上花掉一分钟和一个 GB 的磁盘。打开剧集时再准备，
  符合素材那篇 note 定下的「一次一集」的习惯。
- **继续用外部播放器看。** 不花任何成本，在没有 ffmpeg 时也仍然是后备，但盲看那一步，连同它的计时和勾选，就一直留在页面外面。

## Settled details

2026-10-12 的设计那一轮，在动手之前定下了这些。

- **画面跟着五步走，但只经由计时。** 开始盲看那一步的计时，画面切到大画面一次，提示里带「撤销」；暂停这个计时或者标记这一步完成，
  恢复切换之前的状态。打开页面或者打开五步抽屉都不会切换。开始计时就是读者在说「我现在做第一步」，而撤销只要点一下。
- **大画面状态下用 `R` 看一眼这一句。** 它和跟读模式里的揭晓是同一个键、同一个意思：当前这一句被藏起来的英文显示出来，
  作为画面上的一行字幕，下一句开始时自动收起，所以盲看不会悄悄变成看字幕。
- **放不了的视频只完整说明一次。** 第一次舞台上显示带原因的完整卡片。之后舞台保持普通的音频布局，顶部只留一个小标签
  「视频放不了 · 详情」，点开能再看到原因。不设「不再提示」开关，因为那是为一条始终有用的信息多存一份状态。
- **尺寸。** 显示状态下，画面在 1440 宽的页面上是 608×342，随舞台缩放；大画面状态下，画面占满播放卡片以上的舞台。
  剧集卡片和分段列表上有一个小的视频标记，视频还要准备时带「未准备」。
- **没有 `ffprobe` 就什么也验证不了。** 这时 `mp4` 和 `webm` 照直接播放给出，浏览器说解不了的话，页面退回音频文件并给出放不了的卡片；
  `mkv` 和 `mov` 则说需要 ffmpeg。像素格式是浏览器解不了的 H.264（10 位、4:4:4）算作放不了的画面，因为把它复制进 `mp4` 也没有用。
- **视频属于文件夹剧集。** 文件剧集（从工作区里挑的单个音频文件）没有视频，选择层也不列视频文件；这两点都来自「准备」要写进媒体库。
