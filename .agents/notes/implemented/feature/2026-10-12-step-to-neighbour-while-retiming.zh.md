# Agent Note: 调整时间时切到上一句或下一句

Status: implemented

## Problem

调整时间的面板一次只改一句。字幕文件不准时，很少只错一处：往往是连续一段句子都晚了差不多的时间。要修好它们，
就得改一句、保存、关掉面板、切到下一句、再打开面板，一段里每一句都要这样来一遍。另外两点让这件事更麻烦：

- 面板打开时，方向键用来微调边界，所以页面上平常切句子的办法（`←` / `→`）用不了；
- 面板不用的键也都被有意拦下，免得误按一个键就把正在改的句子换掉。

2026-10-12 提出的问题是：面板能不能自己切到上一句或下一句。计划当天就被采纳，2026-10-23 分两步做完：先做没改过时直接切，
再做改过时先保存再切。

## Decision

**在面板里按 `↑` 和 `↓` 切到上一句和下一句**，面板头部放两个小按钮给鼠标用，底栏加一条提示（`↑ ↓ 上一句 / 下一句`，
用的是页面已有的文案）。这两个键以前在面板里被拦下，所以不会改变任何现有按键的含义。

- **没改过：直接切。** 面板在相邻那一句上重新打开，和在那里打开面板一样：循环跟着过去，播放位置移到那一句的开头并开始播放。
  唯一的不同是聚焦的那一端会保留，因为一段不准的句子通常错在同一端。LRC 的一行结尾不能改，这时退回开头。
  手动打开面板时仍然从开头开始。
- **改过：先保存，再切。** 当前这一句像按 `Enter` 一样保存，等字幕重新读回来，面板在新列表里的相邻那一句上打开。
  - 重新读取期间面板一直留在页面上：决定面板是否挂载的那个「在场」状态，把正在进行的切换也算作打开。
    保存按钮显示「保存中…」，头部的两个按钮禁用。在相邻那一句打开之前，所有按键都被拦下、什么也不做，`Esc` 也一样。
  - 页面把播放位置恢复到相邻那一句的开头，不循环。这次保存推动了那一句时，用的是推动后的开头，
    所以相邻那一句打开时已经在新位置上，可以接着往下改。
  - 第一份不是保存时那份的列表到达时，相邻那一句才打开。保存不会改变句子的数量，所以序号仍然指向正确的那一句；
    列表长度变了，说明发生了别的事（比如换了一段），这次切换就放弃。
  - 头部用「已保存」（收藏面板已经在用的那条文字）代替循环状态，显示 1.5 秒。用户看不见的写入，事后容易让人怀疑。
    这条提示不会拖慢切换；下一次改动、切换或关闭时提前消失。
  - 保存被拒绝（文件已经变了，或者服务端的其他拒绝）时放弃切换：面板留在这一句上，改动和原因都还在，和按 `Enter` 被拒绝时一样。
- **不能保存的剧集，改没改过都直接切。** 这种剧集的面板本来是打开来听的，存不下的改动不值得为它停下来。
- **列表两端什么也不做。** 在这一集或这一段的第一句、最后一句上，对应的键不起作用，按钮也是禁用的。

规则都是这个 widget 的 `lib/` 里的纯函数（按键表、什么时候要先保存、会话、保存请求），跨过重新读取的那次切换在
`model/useStepAfterSave.ts`。保存之后页面恢复到哪里，是 `pages/lingualab/lib/retime.ts` 里的 `resumeAfterSave`。

## Measured

在链接了这个分支的 dsh web 0.2.1-rc.2 实例里，用一集素材的副本（496 句），窗口 1400 乘 900：

- 没改过、聚焦结尾时，在第 2 句按 `↓`，打开第 3 句，聚焦的仍是结尾，循环跟着过去。
- 把第 3 句的结尾从 08.400 挪到 08.500，再按 `↓`。每 20 毫秒采样一次：面板一直没有离开页面，按钮显示「保存中…」；
  约 200 毫秒后第 4 句打开，聚焦结尾，开头是 08.500（从 08.480 被推过来），「已保存」显示了 1.5 秒。
  两个字幕文件都只改了这两行时间，第一次写入前留了 `.bak`。
- 文件在磁盘上被改过之后，改动开头再按 `↑` 被拒绝：面板留在第 4 句，改动还在，显示原因和重新加载的按钮。
- 在第 1 句上，上一句的按钮是禁用的，按 `↑` 不起作用。console 没有报错。

## Alternatives considered

- **把好几句没保存的改动攒起来一起保存。** 服务端已经接受在一次写入里最多改六处，所以批量保存是做得到的。但跨句的草稿要处理草稿句之间的相互推动，
  而且文件一旦变了，整批都会被拒绝，一下子丢掉好几句的工作。逐句保存让每一步都小，出错也能恢复。
- **切走时丢掉没保存的改动，或者先询问。** 丢掉会让一次按键就丢失工作；弹确认框又会给这个本该很快的流程多加一个对话框。
  保存的代价更低，因为存下的边界还能用同样的办法挪回去。
- **只做「保存并到下一句」（`Shift+Enter`）。** 能覆盖最常见的往后改，但听了下一句发现上一句挪过头时，没法回去。
- **对一段句子整体偏移。** 一段句子偏差完全一样时更快，但调整时间那篇 note 已经没有采用它：实际的偏差是逐句不同的；
  而「字幕到处都晚一点」的情况，「更多」里的提前起播不改文件就能解决。
- **重新读取时让面板关掉再打开。** 更简单，但每次保存后切换，面板都会淡出再淡入，舞台也会跟着退出调时间模式再回来。

## Consequences

- 这次切换依赖新列表到达时页面上几个 effect 的顺序：先重置播放器，再由恢复位置的逻辑 seek，最后才是面板。
  `LinguaLabPage` 里就是按这个顺序声明的（重置的 effect、`useResume`、`useRetime`）；把 `useRetime` 挪到其中任何一个前面，
  重置就会清掉面板刚设好的锁定。
- 切换进行中按键不起作用。如果重新读取一直没带来新列表，这次切换会一直挂着，直到用面板的关闭按钮取消。
- `useTimingEditor` 现在是 199 行，它那一档最多 200 行。下次改它，要先挪出去一些。
- 还没在 iPad 上用触摸试过；触摸要靠那两个按钮。
