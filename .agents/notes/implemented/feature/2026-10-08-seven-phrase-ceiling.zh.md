# Agent Note: 每集 7 条的上限，两端都拦

Status: implemented

## Problem

这一页服务的那套方法规定每集最多记 7 条短语，而且是有意的：上限逼你决定什么值得留下。一个会
默默收下第 8 条的页面，等于把方法赖以成立的机制取消了。

## Decision

上限写在共用的笔记格式模块里，叫 `MAX_PHRASES`。host 在写文件之前检查它，面板在丢掉一次编辑之前
先问一句。面板显示还剩几条，写满时询问替换哪一条，而不是往后追加。host 收到超长列表会带着理由
拒绝，所以绕过提问的客户端照样写不进去。

## Alternatives considered

- **只在面板拦。** 最短的路，也是一条脚本、第二个客户端或者一次手工编辑就能破的规矩。
- **只在 host 拦。** 正确，但用户遇到的是保存被拒，而不是被问一句，那正是这套方法想避开的说教口吻。
- **只提醒不拦。** 把逼人取舍的装置降级成建议，而建议每次都输给方便。

## Consequences

这个数字出现在三处：格式模块、host 的写入函数、面板。测试覆盖了其中两个会拒绝的地方。改数字是
格式模块里的一行，另外两处都从那里读。
