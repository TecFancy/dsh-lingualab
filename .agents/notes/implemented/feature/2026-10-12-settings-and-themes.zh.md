# Agent Note: 设置抽屉与配色主题

Status: implemented

## Problem

这一页的颜色全部取自 dsh，自己没有任何偏好可调，用户没法让它更护眼。精听一练就是一个小时，页面又以文字为主：舞台上的那一句、
字幕栏、收藏卡片。dsh 的黑白灰作为默认值没问题，但有的用户在书桌前想要更暖的页面，夜里想要更冷的，或者想要更深的文字和更清楚的边框；
舞台上的字号也是一个尺寸，不管屏幕多大、眼睛怎么样。

页面里还有一个偏好无处安放。提前起播（每句从开头前一点开始放）是设一次就不再动的习惯，却放在「更多」菜单里，挨着 A-B 标记，
而那些是边听边用的手势。

有两条限制决定了做法。页面做的任何事都必须留在页面里：重画 dsh 的插件是恶意的邻居，和页面不去抢空格键是同一个道理。
而且白天还是夜里由 dsh 决定，所以默认值必须继续跟着它走。

## Decision

**一个设置抽屉放这一页的偏好。** 它从顶栏最右边的滑块图标打开，首页和练习页都有，是五步法抽屉的兄弟：同样的滑入加遮罩，
同样的 Escape，同样把键盘还给页面。打开其中一个会关掉另一个。里面分三组：外观（明暗和主题）、字幕（舞台上那一句的字号）、
播放（提前起播，和「更多」里是同一个状态，「更多」里仍保留一份）。每个控件改了立刻生效，没有保存按钮。
在抽屉里按的键留在抽屉里，因为里面有读方向键的单选组。

**一套主题，就是页面本来就在读的那十一个宿主 token 各给一个值。** 样式表里的每个颜色都是 `var(--dsw-alias-…, 回退值)`，读的是同一批十一个 token，
所以一套主题就是它们的一张调色板，写成页面根元素上的 inline 自定义属性。自定义属性会继承，所以覆盖对页面内部的一切生效，
对页面外部的一切不生效；同一个元素上的 `--ll-*` 派生值是对这些 token 做的 `color-mix`，不需要自己的规则就会跟着变。
样式表里没有一条颜色规则需要为主题而改。

**每套主题有浅色和深色两份调色板，「明暗」在两者之间选。**「跟随 dsh」取宿主的白天或夜里，读的是 dsh 放在 `<body>` 上的
`data-ds-dark-theme` 属性，用 `MutationObserver` 盯着；「浅色」「深色」则固定一种。一个纯函数
`resolveThemeVars(theme, appearance, hostDark)` 返回要应用的变量和 `color-scheme`，或者返回 `null`。默认主题加「跟随 dsh」时返回 `null`：
什么也不设，页面和主题出现之前逐字节一样。六套主题是「默认」（dsh 自己的黑白灰，只有固定了明暗才会真的涂上）、「墨蓝」、「松绿」、
「纸张」、「暮紫」和「高对比」。

**主题卡片显示的是当前生效的配色。** 每张卡片是一个缩小的页面，按那套主题自己的颜色、当前显示的明暗来画（一页、一行字、一行弱化的字、
一个品牌色圆点和一条进度条），所以卡片说的就是选了之后的样子，「明暗」一变它也跟着变。

**舞台字号只缩放舞台上的两行。** 小、中、大把 `--ll-stage-scale` 设成 0.85、1 和 1.2，英文行和中文行在原来的 `clamp()` 上乘它，
所以响应式的形状还在。页面其余部分仍是宿主给的大小。

**设置存在这个浏览器里。** `localStorage` 的键 `dsh-lingualab:settings` 下放一个 JSON，读写都包在 `try` 里，读回来时逐个字段处理：
不是可选项的值回到它自己的默认值，不会连累其他字段。换一台设备按默认来，抽屉的底部也这么写着。

**不在这次范围内：** 自由取色；按集分别设主题；把设置同步到其他设备；以及重画页面以外的任何东西。

## Alternatives considered

- **另起一套 `--ll-*` 颜色系统。** 页面读自己的变量，主题去设这些变量。看上去更整齐，但意味着样式表里每一处 `var(--dsw-alias-…)` 都要重写，
  还会破坏让默认值安全的那条性质：以宿主 token 为源头，默认主题就恰好是宿主的样子，因为什么都没覆盖。两套颜色系统也会在
  第一次有规则取错了的时候开始各走各的。
- **用 `body[data-ds-dark-theme]` 做选择器。** 明暗可以全写在样式表里，不用 JavaScript。但用户的「明暗」固定必须压过宿主的属性，
  这就要把这个选择当作属性放到页面根元素上；而且卡片要把调色板当数据来画预览。在 JavaScript 里解析，就只有一张表，页面和卡片都读它。
- **借进度文件通过 host 同步设置。** 用户在每台设备上都能拿到自己的主题。但进度文件按每个键取最新时间戳合并，还跟着素材库文件夹一起走，
  外观偏好会跟着传给持有这份副本的任何人；而且为了一个很容易重设的东西多出一条路由和一条合并规则。
  不同的设备本来就可能想要不同的样子（明亮的书桌、昏暗的卧室）。
- **自由取色。** 自由度最大，但每种明暗十一个互相配合的颜色，没有谁能挑好，选出一个看不清的搭配就成了页面的 bug。
  配上一套高对比的精选调色板，每个选择都读得清。
- **提前起播只留在「更多」里。** 它在那里也还在。但那个菜单放的是边听边用的手势，设一次就不再动的习惯应该和其他偏好放在一起。

## Consequences

- 主题除了根元素颜色的渐变之外不需要改样式表，所以新增一套主题就是 `features/settings/lib/themes.ts` 里表中加一行，
  再加两条 locale 文案。新样式必须继续只读那十一个 token，不能写死颜色，否则主题会漏掉它。
- 页面根元素现在带着 inline `style`（只在某个主题生效时才有）、一个 `data-ll-stage-size` 属性，以及一个很短的背景和文字颜色过渡，
  页面的「减少动态效果」规则会和其他过渡一起把它清零。
- 页面依赖一条它自己并不拥有的宿主约定：`<body>` 上有 `data-ds-dark-theme` 就表示深色。dsh 要是改了，在更新 `useHostDark` 之前，
  「跟随 dsh」会一直读成浅色。固定明暗的两种不受影响。
- 主题会设置 `color-scheme`，所以页面里的原生控件和滚动条跟着一起变。
- 提前起播现在有两个入口，绑在同一个状态上，在任何一处改了，另一处也看得到。
- 设置按设计只存在每个浏览器里，所以有两台设备的用户要设两次。
