# Agent Note: 设置抽屉与配色主题

Status: implemented

## Problem

页面的颜色全部取自 dsh，自己没有任何可调的偏好，用户没法让它看起来更舒服。精听一练就是一个小时，而页面以文字为主：
舞台上的那一句、字幕栏、收藏卡片。dsh 的黑白灰作为默认值没问题，但有的用户在书桌前想要更暖的色调，夜里想要更冷的，
或者想要更深的文字和更清楚的边框；舞台上的字号也只有一种，不管屏幕多大、视力如何。

页面里还有一个偏好没有合适的位置。提前起播（每句从开头之前一点开始播放）是设一次就不再动的习惯，却放在「更多」菜单里，
挨着 A-B 标记，而 A-B 标记是边听边用的操作。

有两条限制决定了做法：

- 页面做的任何改动都必须限于页面之内。插件如果改动 dsh 本身的样式，就是在干扰宿主，这和页面不占用空格键是同一个道理。
- 白天还是夜间模式由 dsh 决定，所以默认值必须继续跟随 dsh。

## Decision

**用一个设置抽屉存放页面的偏好。**

- 抽屉从顶栏最右边的滑块图标打开，首页和练习页都有。它和五步法抽屉是同一类：同样带遮罩滑入，同样响应 Escape，
  同样以相同的方式把键盘交还给页面。打开其中一个会关掉另一个。
- 里面分三组：
  - 外观：明暗和主题。
  - 字幕：舞台上那一句的字号。
  - 播放：提前起播，和「更多」里的是同一个状态，「更多」里仍保留这一项。
- 每个控件改了立即生效，没有保存按钮。
- 在抽屉里按的键只在抽屉里处理，因为里面有用方向键操作的单选组。

**一套主题，就是给页面本来就在读的那十一个宿主 token 各设一个值。**

- 样式表里的每个颜色都写成 `var(--dsw-alias-…, 回退值)`，读的是同一批十一个 token。所以一套主题就是这些 token 的一张调色板，
  以 inline 自定义属性的形式写在页面根元素上。
- 自定义属性会继承，所以覆盖只对页面内部生效，不影响页面外部。同一个元素上的 `--ll-*` 派生值是对这些 token 做的 `color-mix`，
  不需要单独的规则就会跟着变。
- 为了支持主题，样式表里没有一条颜色规则需要修改。

**每套主题有浅色和深色两份调色板，由「明暗」选择用哪一份。**

- 「跟随 dsh」取宿主当前的白天或夜间模式，读的是 dsh 放在 `<body>` 上的 `data-ds-dark-theme` 属性，用 `MutationObserver` 监听变化；
  「浅色」「深色」则固定为其中一种。
- 纯函数 `resolveThemeVars(theme, appearance, hostDark)` 返回要应用的变量和 `color-scheme`，或者返回 `null`。
  默认主题加「跟随 dsh」时返回 `null`：什么也不设，页面和加入主题之前逐字节相同。
- 六套主题是「默认」（dsh 自己的黑白灰，只有固定了明暗时才会实际应用）、「墨蓝」、「松绿」、「纸张」、「暮紫」和「高对比」。

**主题卡片显示实际生效的配色。** 每张卡片是一个缩小的页面，用那套主题自己的颜色、按当前显示的明暗绘制
（一个页面、一行文字、一行弱化的文字、一个品牌色圆点和一条进度条）。所以卡片展示的就是选中之后的样子，「明暗」一变，卡片也跟着变。

**舞台字号只缩放舞台上的两行。** 小、中、大分别把 `--ll-stage-scale` 设成 0.85、1 和 1.2，英文行和中文行在原来的 `clamp()` 上乘以这个值，
所以响应式的缩放方式保持不变。页面其余部分仍用宿主给的字号。

**设置存在当前浏览器里。**

- 存放位置是 `localStorage` 的键 `dsh-lingualab:settings` 下的一个 JSON 值，读写都包在 `try` 里。
- 读回来时逐个字段处理：不在可选范围内的值退回这个字段自己的默认值，不影响其他字段。
- 换一台设备就从默认值开始，抽屉底部也写明了这一点。

**不在这次范围内：** 自由取色；按集分别设主题；把设置同步到其他设备；以及改动页面以外的任何样式。

## Alternatives considered

- **另建一套 `--ll-*` 颜色系统。** 页面读自己的变量，主题去设这些变量。看上去更整齐，但样式表里每一处 `var(--dsw-alias-…)` 都要重写，
  还会失去让默认值安全的那个性质：以宿主 token 为源头时，默认主题因为什么都没覆盖，恰好就是宿主的样子。而且只要有一条规则用错了系统，
  两套颜色就会开始不一致。
- **用 `body[data-ds-dark-theme]` 作 CSS 选择器。** 明暗可以全写在样式表里，不用 JavaScript。但用户在「明暗」里固定的选择必须优先于宿主的属性，
  这就无论如何都要把选择作为属性放到页面根元素上；而且卡片绘制预览时需要把调色板当作数据。在 JavaScript 里解析，就只有一张表，页面和卡片都读它。
- **借助进度文件，通过服务端（host）同步设置。** 用户在每台设备上都能用到自己的主题。但进度文件按每个键取最新时间戳合并，还随媒体库文件夹共享，
  外观偏好会传给持有这份副本的任何人；而且要为一个很容易重新设置的东西多加一条路由和一条合并规则。
  不同的设备本来就可能需要不同的外观（明亮的书桌、昏暗的卧室）。
- **自由取色。** 自由度最大，但每种明暗下十一个要互相协调的颜色，没有人能挑好；一旦选出看不清的搭配，就成了页面的 bug。
  一组精选调色板再加一套高对比的，能保证每种选择都看得清。
- **提前起播只放在「更多」里。** 它在「更多」里仍然保留。但那个菜单放的是边听边用的操作，设一次就不再动的习惯应该和其他偏好放在一起。

## Consequences

- 主题除了根元素颜色的渐变过渡之外，不需要改样式表。所以新增一套主题，只要在 `features/settings/lib/themes.ts` 的表里加一行，
  再加两条 locale 文案。新样式必须继续只读那十一个 token，不能写死颜色，否则主题覆盖不到。
- 页面根元素现在带有 inline `style`（只在某个主题生效时才有）、一个 `data-ll-stage-size` 属性，以及一个很短的背景色和文字颜色过渡；
  页面的「减少动态效果」规则会把它和其他过渡一起清零。
- 页面依赖一条并不由它掌控的宿主约定：`<body>` 上有 `data-ds-dark-theme` 就表示深色。如果 dsh 改了这条约定，在更新 `useHostDark` 之前，
  「跟随 dsh」会一直按浅色处理。固定明暗的两种模式不受影响。
- 主题会设置 `color-scheme`，所以页面里的原生控件和滚动条也跟着变。
- 提前起播现在有两个入口，绑定同一个状态，在任何一处修改，另一处都能看到。
- 设置按设计只存在各个浏览器里，所以有两台设备的用户要设置两次。
