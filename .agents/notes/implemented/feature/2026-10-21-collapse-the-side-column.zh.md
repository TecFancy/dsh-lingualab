# Agent Note: 右栏可以收起

Status: implemented

## Problem

在 iPad 上，练习栏只有 440 到 630px 宽。宿主的侧栏占了 56px 或 280px，右栏（字幕或收藏）又从剩下的宽度里占走 260 到 440px，
于是舞台用的是[布局那篇 note](../architecture/2026-10-14-layout-answers-to-the-practice-column.zh.md)里的窄布局：画面大约 300 乘 170，
播放卡片折成更多行，竖屏且侧栏展开时舞台只有 278px。在 iPad 上，用户很多时候只是在听舞台上的那一句，用不着旁边的列表，
却没有办法把它占的宽度要回来。

顶栏也有同样的问题，只是小一些。它的按钮连同文字大约要 480px，所以在 540px 的顶栏里（iPad 竖屏，侧栏展开），剧集标题只剩
40px 左右。顶栏的按钮只有 28px 高，不到手指需要的 44px。

## Decision

- **三种状态，两件事。** 右栏是收起、字幕或收藏。显示哪个视图仍然是 `Column`，是这一次访问的状态；收起与否是另一个开关，
  即设置里的 `sideCollapsed`。各种操作是 `pages/lingualab/lib/side-column.ts` 里的纯函数，由 `useSideColumn` 执行，
  所以收起从不忘记视图，`N` 在展开的右栏上仍是原来的意思：切换视图。
- **一个开关，一个键。** 顶栏「收藏」旁边一个面板图标（带 `aria-expanded`，标题里写着按键），以及 `\`：页面别的键都不用它，
  在美式布局上它挨着方括号（变速）。在 `\` 要配 AltGr 的布局上，它是组合键，不归页面，那时用按钮。这个键写进了 keymap 并带测试，
  也列在「更多」的快捷键一览里。
- **右栏收起时，`N` 和「收藏」按钮直接展开到收藏。** 用户按的是收藏，所以先展开到字幕，或者切换一个看不见的视图，都不对。
  受保护的句子要显示它的卡片时，也会展开右栏。「收藏」按钮只在收藏真的显示在屏幕上时才是按下的样子。
- **收起就是不画。** 没有窄条：右栏不渲染，这一行全归舞台。展开时重新挂载，字幕列表在 layout effect 里、绘制之前落在正在播的那一句，
  不管「跟随」开没开：它不在的时候没有在跟随。从收藏切回字幕时也是这样落位。宽度没有动画，这一行只变一次。
- **按设备记住。** `sideCollapsed` 和主题、舞台字号一起存在 `dsh-lingualab:settings` 下；只有存着的 `true` 才收起，
  缺失或损坏的值按默认的展开处理。
- **画面跟着这一行变大。** 练习栏宽过 600px 时，画面的宽度份额是 64%，在宽的栏里多出的宽度只是两边的空白。右栏收起时
  （`.dsh-lingualab-body` 带 `is-side-collapsed`），份额是整个宽度（`--ll-pic-share:1`、`--ll-pic-w:100%`）；
  720px、405px 的舞台、高度上限和 `is-picture-squeezed` 的测量照样限制它。代替画面的卡片取同样的宽度，仍归 `useCardFit` 管。
- **按钮写「收藏」。** 它原来写「笔记」，而它打开的右栏写的是「收藏」；现在用右栏自己的词。
- **顶栏看自己的宽度。** 它是一个宽度容器（`ll-top`）。顶栏不到 720px 宽时，返回按钮和「收藏」按钮只留图标（和计数），
  给标题腾出大约 110px；它们的名字留在 `aria-label` 和 title 里。按钮都是 `flex:none`，只有标题让位，图标不会被挤小。
- **触屏上 44px，样子不变。** 在 `(hover:none) and (pointer:coarse)` 下，顶栏的按钮各有一个透明的 `::after`，
  它的 inset 恰好把每一边补到 44px，且不会小于零，与画面上那些小胶囊用的是同一种做法。32px 的按钮两边各要 6px，按钮间距是 8px，
  所以相邻的点按区域不重叠。
- 新的样式规则在 `shared/lib/styles-side.ts`，接在 `STYLES` 的响应式规则之后，因为 `styles.ts` 已经到了体量上限；
  图标出于同样的原因放在单独的文件里，用的是共享的 `Svg`。

## Measured

真实的页面，由真实的 host 半边伺服一个测试库（一集视频，另一集有两段、标题 60 个字符），在 Chrome 里，宿主侧栏画成一条，
舞台上是一句 80 个字符左右的句子（栏窄时两行）。画面尺寸是宽乘高，先展开后收起；所有情况都没有滚动。

- 1440 乘 900：侧栏 56px 时 557 乘 313，收起后 612 乘 344；侧栏 280px 时 443 乘 249，收起后 612 乘 344。
- 1180 乘 820：侧栏 56px 时 428 乘 241，收起后 509 乘 286；侧栏 280px 时 299 乘 168，收起后 509 乘 286。
  收起时播放卡片 166px 高，展开时窄栏把它折成 238px。
- 820 乘 1180：侧栏 56px 时 430 乘 242，收起后 691 乘 389；侧栏 280px 时舞台只有 278px 宽，画面 206 乘 116，收起后舞台 539px，
  画面 467 乘 263。
- 1180 乘 820、侧栏 280px 并打开调整时间：303 乘 170，收起后 384 乘 216，紧凑面板 201px，没有滚动。
- 1180 乘 820 下的「准备视频」卡片：展开时 428 或 520px 宽，收起时 720px，两种情况都是 lean 一步，没有滚动。
- 539px 的顶栏，带分段按钮和两句收藏：标题有 145px，没有溢出；763px 时标题有 249px，所有文字都在；899px（1180、侧栏 280px）时
  按钮保持 32px。
- 触屏模拟：按钮仍是 28px 和 32px；点按区域是 46 乘 46（只留图标的按钮）、46 高（更宽的按钮）和 44 乘 44（图标按钮）。
- `\` 和开关都能收起、展开，选择在重新加载后仍在，右栏收起时按 `N` 打开收藏，收起时 `↑` `↓` 和回车仍然能选句、播放，
  收起状态下往前走 25 句之后展开，列表落在正在播的那一句。点开关之后键盘仍在页面上，所以空格照样播放。

没有测：真实的 dsh-web 和真实的 iPad（Safari 的高度、SF Pro、真实的触摸）。这套测试用的是 Chrome 的引擎。

## Alternatives considered

- **给 `Column` 加第四个值（'collapsed'）。** 一个状态代替两个，但那样 `N` 就得记住要回到哪个视图，而记住的设置会带上视图，
  视图是这一次访问的选择，不是设备的。
- **收起时留一条 40px 左右的窄条。** 它让右栏只差一次点按，但占的正是缺的宽度，而顶栏的开关本来就在那里。
- **宽度做动画。** 动画的每一帧舞台都要重排（画面、卡片的行数、调整时间的布局），这正是收起想消除的跳动；变一次看起来更安静。
- **右栏保持挂载，用 CSS 隐藏。** 这样能保留列表的滚动位置，但隐藏的列表不会跟随滚动，展开时停在上次离开的地方。
  重新挂载并落在正在播的那一句，才是用户要的，而且不费什么。
- **把收起存进 host 的进度文件。** 这是设备的偏好（iPad 要宽度，桌面未必），所以和其他设置一起留在浏览器里。
- **用视口断点去掉按钮文字。** 顶栏的宽度取决于宿主的侧栏，和练习栏一样；样式表的测试只允许浏览层问视口。
- **触屏上把顶栏按钮做成 44px 高。** 那会改变顶栏的样子和高度，而透明的外延已经给了点按区域。
- **接下来的两步。** 栏窄时让右栏浮在舞台上、栏窄时默认收起，写在[练习栏窄时，侧栏浮在舞台上并默认收起](../../proposed/feature/2026-10-21-side-column-over-a-narrow-stage.zh.md)；
  不用列表在舞台上找到一句，写在[在舞台上拖动定位句子](../../proposed/feature/2026-10-21-locate-a-sentence-on-the-stage.zh.md)。
  两者都等收起用过一段时间再说。

## Consequences

- 右栏的新功能走 `side-column.ts`：改变视图或收起的操作是那里的一个纯函数并带测试，`useSideColumn` 只在收起状态变化时写设置。
- 右栏里画的东西在收起时都会卸载，所以它放在 React 里的状态收起就没了（列表的滚动位置是有意丢掉的）。
- 顶栏的新按钮应当是 `flex:none`，只要它是顶栏里的 `.dsh-lingualab-chip` 或 `.dsh-lingualab-icon-btn`，触屏点按区域就自动有了。
