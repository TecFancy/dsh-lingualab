# Agent Note: 一个标记，两处画法——包图标与左栏那一行

Status: implemented

[English](2026-11-18-one-mark-two-renderings.md) | 简体中文

## Problem

这个插件原本只有一处标记：`HeadphonesIcon`，一个 16 单位的描边图形，用在它注册进宿主「更多」菜单的那一行上。
其他地方都是匿名的。「插件」页画的是宿主的通用占位 tile，插件市场的卡片回退到作者的 GitHub 头像——
同一个插件在三个地方看起来是三样东西，而且没有一样说得清它是做什么的。

包图标在这里不是装饰。`package.json#icon` 由宿主读取、内联成 data URL、画进 `<img>`；市场卡片经注册表读同一个字段。
这条渲染路径决定了这个文件不能用 `currentColor`，也不能用页面的主题变量：两者都到不了一张图片里。
按本仓库其余图标的写法来写这个标记，它在深色下会黑底黑字，而仓库里没有任何东西会读这个文件来发现这件事。

## Decision

**一份图形，两种画法。**

- 仓库根的 `icon.svg` 是包图标：耳机，耳罩之间一条字幕线，白色填充在 `#3B54C4` 的圆角 tile 上，36 单位画布。
  它由 `package.json#icon` 声明，作为 `./icon` 导出，并列进 `files` 随包发出去。
- `HeadphonesIcon` 保持同一个形状，作为 16 单位的描边图形，也补上同一条字幕线，于是菜单行和 tile
  一眼能认出是同一个插件。
- `assets/icon-512.png` 与 `assets/icon-180.png` 是位图副本，给需要 PNG 的商店页用。插件本身不引用它们；
  它们存在是因为注册表的 `icon` 字段只收位图，而从 SVG 重新生成是一条命令的事，不是重画一遍。
- `check-host` 增加第六节：图标已声明、已导出、随包发、不含 `currentColor` 与 `var(--…)`、画在 36 单位画布上。
  这两条检查会先剥掉注释，因为这个文件用正文解释这条规矩，而一道把自己解释读成违规的检查，
  会把注释赶出它本该待着的文件。

颜色是单一的 `#3B54C4`，不是渐变。渐变是第一版，36px 的 tile 上还撑得住，但 14px 的菜单行里浅端在白底上糊掉，
整个标记读成一团；平涂在两种尺寸下都保得住边缘。

## Alternatives considered

**保留描边图标，让宿主画占位 tile。** 否掉：占位 tile 是每个没标记的插件都会拿到的那一块，
于是在读者决定要不要装它的那两个界面上，这个插件仍然是匿名的。

**给 tile 另画一张更丰富的插画。** 否掉：一个插件两个标记只会让这一对更难认，不会更容易，
而那一行在 14px 下只放得下一个形状。字幕线是唯一在两种尺寸下都活下来的加法。

**用 `currentColor` 让 tile 跟随主题。** 否掉：宿主把图标当图片画，`currentColor` 在那里解析成黑色。
标记会在深色下消失，而且只有浏览器能看出来。

**只发 SVG。** 否掉：注册表的 `icon` 字段只收 PNG/JPEG/WebP，拒收 SVG，想要位图 tile 的商店页会没有东西可指。

## Why

这个标记用一个形状说清了插件做什么——在听，以及你正在听的那一句——而且它在菜单里、「插件」页上、市场里是同一个形状。
守着这件事的是那道检查：这个文件在仓库里没有第二个读者，没有它，一次 `currentColor` 改动或一条漏掉的 `files`
会静默发出去，最后只表现为某个人浏览器里一块看不见的 tile。
