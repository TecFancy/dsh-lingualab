# Agent Note: 手动选择一集的字幕

Status: implemented

## Problem

一集用哪几个字幕文件，由 host 决定：先看文件名，文件名说不清时，再读文件开头几 KB 的内容（`src/host/pairing.ts`）。
页面从来不问用户。这带来两个问题。

- **配错了，页面上没有办法改。** 规则猜错时，唯一的办法是去磁盘上改文件名。2026-10-12 的 S01E01 文件夹就是例子：
  `MDJT S01E01-EN.srt` 旁边放着一个没有标记的双语字幕 `MDJT S01E01.srt`，打开后只有英文，选集列表却显示「EN + ZH」。
  这一种情况是规则里一个分支的 bug，会单独修掉；但下一种规则没想到的命名，还会用同样的方式出错。
- **每多一种命名习惯，就多一条规则。** 字幕网站的文件名有 `.chs`、`.eng`、`.chs&eng`、`.简体`、`-EN` 等等，
  规则只能靠加标记或加猜测来跟上。规则已经有意不认这些近似的标记，因为列表一长，配对就变得难以预料；
  剩下的全靠内容判断，而内容判断分不清两个英文文件。

2026-10-12 提出的问题是：要不要改成让用户手动选字幕。下面的评估当天就被采纳了，三部分也都在当天做完。

## Decision

**手动选择覆盖自动配对，不替代它。** 没人看过的每一集，仍然由规则给出答案：首页卡片和上面的「EN + ZH」徽章、
选集列表、拖入导入时的分组（拖进来的一批文件里，哪个字幕归哪段音频）都要在打开之前就有答案。
规则就停在现在这一档，也就是标记加内容判断；它处理不了的命名，交给手动选择，不再加新的标记。

- **两个槽，每个三种状态。** 英文槽和中文槽各自是「自动」（缺省，就是现在的行为）、「某个文件」或「不用」。
  两个槽选同一个双语文件，就是双语的情况；页面本来就只读一次，再逐行拆开。
- **候选是文件夹里的字幕文件。** 文件夹剧集列出文件夹顶层的所有字幕文件，不只是按词干规则归到这一段的，
  这样名字起歪了的文件也能选中。单文件剧集列出它所在目录的字幕文件；选中的文件名存进这一集的记录，
  媒体路由本来就放行记录里的文件名，所以放宽的范围只限于用户自己选的文件。
- **按段选。** 同一个文件夹里的场景是分开剪的，各有各的文件。没有分段的文件夹，整个文件夹一份选择。
- **存在 host 上，挨着它选的文件。** 文件夹剧集的选择存在剧集文件夹里一个隐藏的 `.lingualab-subtitles.json`，
  按段记，写入先写临时文件再改名。它和 `notes.md` 一样跟着文件夹走。单文件剧集的选择存在插件状态里它的那条记录上。
  库扫描会读文件夹里的这个文件，所以首页徽章显示的就是实际会放的字幕。
- **文件不在了就回退，并且说一声。** 选中的文件不在了，那个槽按「自动」处理，页面显示「选的字幕文件不在了，先按文件名配对」。
  选择本身保留，文件回来了（比如同步还没完成）就接着用它。
- **页面上只有一个入口。** 控制栏「中文显示」旁边加一个「字幕」按钮，点开是一个小弹层，里面是这两个槽。
  列表里每个文件都标上内容判断的结果（含中文或不含中文），「自动」一项显示它现在实际对应的文件。
  保存后 host 返回这一集最新的描述，页面重新读字幕；字幕的键本来就包含文件名，所以不用为这次改动写特例。
- **下游都不用改。** 合并、「中文显示」的四档、调整时间（写进选中的文件）和收藏（按时间记）都只认 `subtitleEn` 和 `subtitleZh`，
  不关心它们是怎么定下来的。

有两处小改动和它一起做，记在这里免得漏掉：

- **先修 S01E01 那个分支。** 一个有英文标记的文件加一个没有标记的文件，应该配成英文和中文，选集列表的提示本来就是这么说的。
  这是一个 bug 修复，自带测试，不用等其余部分。
- **「中文显示」存进设置。** 这个档位现在是页面状态，每次打开都从「变淡」开始，所以「只看英文」每次都要重新选。
  它挪进设置这个 feature，和主题、舞台字号放在一起。

## Alternatives considered

- **只靠手动选择，去掉自动配对。** 删的代码最多，但每一集新素材打开时都没有字幕，要等人去选；首页徽章什么也说不了；
  而导入分组无论如何都要用词干规则。规则在它管用的地方很便宜，而大多数文件夹它都管用。
- **把选择存在浏览器里。** 每集一条 `localStorage` 是改动最小的办法，但换一个浏览器或清了缓存，放的字幕就不一样了，
  host 算徽章时也看不到它。选择说的是库里的文件，所以和文件存在一起。
- **把选择存进进度文件。** 进度文件已经在 host 上，但它在库的根目录，合并规则（每个键取 `updatedAt` 最新的，浏览器缓存也用同一条）
  是为每几秒就变一次的播放位置设计的。选字幕很少发生，而且只属于一个文件夹；放在那个文件夹里的文件，会跟着文件夹一起走。
- **存进视频缓存目录 `.lingualab/`。** 那个目录是缓存：为了腾空间把它删掉必须是安全的，而用户做的选择不是缓存。
- **提供一个按钮，把文件改成规则认识的名字。** 能一劳永逸地修好这个文件夹，但要给用户的素材改名，插件从来没这么做过
  （导入连覆盖都不会），而且别的播放器期望的名字也可能不一样。
- **继续加标记。** 每个标记都不大，但字幕来源每多一个，列表就长一截；文件名什么也没说的文件，规则仍然只能猜。
  手动选择让规则失败的那些文件夹不用再猜。

## Settled details

评估时留下了两个问题，计划被采纳时都定了下来。

- **入口放在控制栏。** 它属于屏幕上这一集，而「设置」抽屉里的东西都是浏览器偏好，对每一集都生效。
- **先不做「应用到所有段」。** 每一段单独选。场景文件夹的命名通常是统一的，规则很少只在某一段出错、其余段都对；
  等哪个文件夹真的需要，再加这个操作。

做的时候又定了一条。

- **句子列表只发给读出它的那几个文件。** 保存之后，页面重新打开同一集，再把播放位置放回去。第一版把位置放回到了旧的句子列表上：
  新文件还在读的时候，旧列表仍在屏幕上；新列表到了以后，播放器又从 0 开始。现在媒体库按来源文件给读到的句子列表打上记号，
  记号对上之前什么也不发，位置就会等新字幕读完再放回去。
