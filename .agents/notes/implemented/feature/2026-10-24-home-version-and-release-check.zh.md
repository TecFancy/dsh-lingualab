# Agent Note: 首页会说明现在跑的是哪个构建

Status: implemented

## Problem

这个插件是用 `link:` 装到这台机器的检出上的，所以别处没有版本号可读；磁盘上的 manifest 也不是答案：
拉过代码但还没重启的时候，它已经写着下一个版本，而进程里跑的仍旧是旧代码。在 iPad 上通过隧道打开时，
页面上没有任何办法说清眼前是哪个构建，除非去开一个 shell 敲 `git log`。

面板也说不出有没有更新的版本。仓库发的是 `vX.Y.Z` 标签和 GitHub Release，但它是私有库，也没上 npm，
所以既查不了注册表，浏览器不带凭据的请求也问不出来。

## Decision

宿主那一半在加载时读一次自己的版本：manifest 里的 `version`、`git rev-parse` 给出的短提交，以及
`git status --porcelain` 报告的有没有未提交改动。这份快照供 `/lingualab/update` 使用，也顺带放在
`/lingualab/config` 的返回里，首页用它本来就要发的那个请求就能拿到。放在加载时读而不是每次请求读，
才让这个号码指的是真正在跑的代码。

发版检查执行 `git ls-remote --tags origin 'v*'`，问的是检出自己的远端，拿最新的 `vX.Y.Z` 标签和正在跑的
版本比。它只读：不取、不拉、不装，也不动工作区和引用。查到的答案缓存一刻钟，失败的缓存一分钟，
重试时带 `?refresh=1` 跳过缓存。

「最新」指的是最新的发布标签，不是最新的提交。开发构建可能比上一个发布还新，这种情况会如实报出来，
而不是说成「已是最新」。查不了的时候就说查不了，绝不退回到「最新」。

没有升级按钮。宿主重启不了自己；拉代码会在一个还在跑旧服务端的宿主底下把前端换掉；而且现在用的这份
检出本来就是开发用的。

## Alternatives considered

**GitHub Releases API 或 `gh`。** 它还能给出发布说明，但私有库要让运行中的进程带着 token，为了一行
页面上的标签去管一份凭据，不划算。

**让浏览器直接问。** 私有库只答带凭据的请求，把 token 放进页面，比不显示这个状态更糟。

**只比本地标签。** 便宜、离线也能用，但它回答的是「比上次 fetch 之后新没新」，不是我们要问的问题。

**`git fetch` 后比 `origin/main`。** 那回答的是「合进来了什么」，而且为了一个只读状态却要写 `.git`。

**把版本号打进前端产物。** 构建产物要和 `lib/` 逐字节比对，发版只抬 manifest、不重建，嵌进去的版本
要么过期，要么把这道检查弄挂。

## Consequences

这一行只在首页，首页的每种状态都在，位置在拖放区和「继续练习」之上。代价是加载时多一次 Git 进程，
每看一次页面再一次，缓存一刻钟。

机器上没有 Git、这份副本不是检出、远端连不上，都会让检查说自己答不了。页面照旧显示它知道的那个版本。

升级的路子没变：`npm run ship` 发版，重启 `dsh-web` 才让服务端那一半生效。现在页面能告诉你什么时候
值得这么做了。
