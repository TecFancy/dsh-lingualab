# Agent Note: 给右栏的展开收起加动画，并重排顶栏那一排按钮

Status: implemented

## Problem

0.15.0 让右栏可以收起了：右栏要么不渲染，要么排在舞台旁边，收起时宽度还给舞台。展开和收起都在一帧里完成。这是有意的：
[右栏可以收起](2026-10-21-collapse-the-side-column.zh.md)那篇 note 没有采用宽度动画，
因为动画的每一帧舞台都要重新排版（画面、播放卡片的行数、调整时间的布局），而那正是收起想消除的跳动。

用了一天之后，这个切换看起来像一次跳跃。眼睛正看着列表里的某一句，按下 `\` 给舞台腾地方，视线落到画面上时画面已经变完了；
右栏回来时又是一下子出现。两个状态像两个不同的页面，而不像同一行里有一块被藏了起来。行窄时抽屉是滑进来的，但离开时只有一帧。

顶栏有同一类问题，只是发生在空间上，而不是时间上。顶栏右侧的收藏、右栏开关、五步和设置之间都是 8px，
看不出前两个作用于右栏、后两个是这一集的进度和页面的设置。这一排是按「放得下什么」排的，而不是按「哪些东西属于一起」排的。

方案在 2026-10-21 写下，2026-10-23 分两步做完：先做右栏的动画，再重排顶栏。

## Decision

**右栏用 200ms 滑进滑出，舞台和画面在同一个过渡里跟着变。**

- 右栏放在一个包装层里（`ui/PracticeSideSlot.tsx`），由 `usePresence(open, SIDE_MS)` 驱动。过渡的是包装层的宽度和不透明度；
  旁边的舞台是 `flex:1`，在同样的帧里把宽度让出来或收回去。
- 里面的列表从头到尾保持完整宽度（`--ll-side-w`，即 `clamp(300px,34cqw,440px)`），由包装层裁掉。
  过渡中的每一帧，字幕行都不会重新换行，右栏看起来是整块滑出，而不是变窄。
- 收起时列表还会留 200ms，内容不变，但已经点不到（`pointer-events:none`），读屏也会跳过（`aria-hidden`）。
  之后才卸载，所以展开时仍然重新挂载，列表仍然定位到正在播放的那一句。
- 画面跟着一起变：`--ll-pic-share` 和 `--ll-pic-w` 用 `@property` 注册过，`is-side-collapsed` 改变它们时是过渡，不是跳变。
- 行窄时，抽屉离开的方式和进来时一样：向右滑出，遮罩同时淡出，两者一起卸载。body 带 `is-side-narrow`，
  包装层的 `is-floating` 看行宽而不看开没开，所以正在离开的抽屉保持绝对定位，不会在第一帧掉回文档流。
- 系统开了「减少动态效果」时，页面的规则把所有过渡置零，`usePresence` 也不等待，所以和以前一样直接切换。

**顶栏右侧分成两组，中间一条竖线。** 收藏和右栏开关是「右栏」组；五步和设置是「进度与设置」组，放在最右边。
每组是一个带名字的 `role="group"`，两组之间是一条 1px 的竖线，颜色用按钮描边的令牌。组内间距仍是 8px，
触屏 44px 点按区域就是按这个间距算的。左边（返回、标题、分段）不变。没有加「更多」菜单：第二组只有两个按钮，
收进菜单会让每个按钮多点一下。

## Measured

在链接了这个分支的 dsh web 0.2.1-rc.2 实例里，用一集素材的副本（496 句）。浏览器面板是后台页面，帧被节流，
逐帧量出来的时长不可信；所以用 `document.getAnimations()` 取到过渡，停在 100ms 再读：

- 1400 乘 900，展开：包装层有 200ms 的 `width` 和 `opacity` 两个过渡；100ms 时宽 306px（终点 381px），
  舞台 814px（从 1120 往 739 走），里面的列表一直是 382px。收起停在 100ms：包装层 75px，舞台 1045px，
  包装层带 `aria-hidden` 和 `pointer-events:none`，列表仍是 382px；过渡结束后包装层卸载。
- 画面（这一集没有画面，手动设成显示）：展开右栏时，`--ll-pic-share` 在 100ms 是 0.711，正从 1 走向 0.64。
- 1000 乘 800（这一行宽 944px）：抽屉绝对定位盖在舞台上；离开时仍是绝对定位，100ms 时向右平移了 290px，
  遮罩不透明度 0.2；两者一起卸载。
- 顶栏宽 900 和 700 时：两组和竖线都在，组内 8px；700 时收藏只剩图标，没有溢出。五步抽屉仍然贴着页面右边打开。
  console 没有报错。

方案要求先在真 iPad 上录性能记录，再决定用宽度过渡还是淡入淡出。这份记录还没有录；选了宽度过渡，是因为在电脑上
它跑起来列表没有重新换行，而退路只需要改包装层的样式（见 Consequences）。

## Alternatives considered

- **保持直接切换。** 这是原来的决定，也最省事；没有采用，是因为这个要求是在实际用过之后提出来的，跳一下正是用户注意到的问题。
- **只做淡入淡出，宽度直接跳变。** 比宽度动画开销小，但两个状态之间差 260 到 440px，右栏看起来仍是突然弹出，舞台也仍然会跳。
  如果 iPad 撑不住宽度过渡，这就是退路。
- **给舞台做动画，不给右栏做。** 出现和消失的是右栏；只给舞台做动画，会让没有变化的那一部分动起来。
- **右栏保持挂载，只给它的宽度做动画。** 能保留滚动位置，但藏起来的列表无法跟随正在播放的句子，收起那篇 note 正是因此让它卸载。
- **让列表跟着包装层一起变窄。** 少一层元素，但每一帧都要把看得见的字幕行全部重新换行。
- **把顶栏的文字再多藏一些。** 省出的是像素，不是层次。
- **把顶栏的控件全放进一个「更多」菜单。** 顶栏是清爽了，但收藏和右栏开关每次练习都要用，放进菜单就每次都要多点一下。

## Consequences

- 宽度过渡的每一帧都要重新排版舞台，这正是收起那篇 note 担心的开销，还没有在 iPad 上录过。如果在那里掉帧，
  就只过渡包装层的不透明度，让宽度在最后一次到位；包装层和 `SIDE_MS` 都不用变。
- `PracticeSideSlot.tsx` 里的 `SIDE_MS` 和 `styles-side.ts` 里的 `.2s` 是同一个数写了两遍，要一起改。
- 展开时，画面的过渡在点击那一刻开始（`is-side-collapsed` 去掉时），包装层的过渡晚两帧（`usePresence` 加上 `is-open` 时），
  前台页面里大约是 33ms。收起时两者在同一次渲染里开始。
- `--ll-pic-share` 和 `--ll-pic-w` 注册之后，它们的每一次变化都是过渡，包括窗口缩放时容器查询改它们的那一次。
- 仓库的组件测试渲染的是静态标记，所以包装层的计时是通过 `presenceDelay` 和它的各个状态来测的，而不是真的挂载再推进时间。
- `settingsOpen` 和 `settingsTitle` 两个文案在两种语言里都一样；设置按钮改用 `settingsTitle`，
  这样加上两个组名之后，`locale.ts` 仍在它的体量档位里。
