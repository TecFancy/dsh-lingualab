# Agent Note: 入口挪进左栏的「更多」菜单

Status: implemented

## Problem

这一页的入口原来是「应用」页上的一张卡片。那一页是自部署 Web App 的启动台：每张卡片点开都在新标签页
打开一个网址，整格都是这个行为。LinguaLab 是壳里自己的一页，于是它成了那堆卡片里唯一一张行为不同的，
而卡片网格表达不出这种不同。

把入口放在另一个包手里，也让「能不能进」变成了别人的事：没有装 `dsh-apps-panel` 的 profile 里，
页面虽然注册了，却一个入口也没有。

左栏还是不该为每个页面长一行，因为一行无论你会不会专门去点，都要占宽度。

## Decision

入口改成 `sidebar.panellist.actions` 里的一行，这个列表就是左栏「更多」菜单的内容。这一行由本插件
自己注册：文案来自自己的字典，行本身用宿主菜单的按钮画，选中时调 `ctx.layout.selectPanel('lingualab')`。

这一行的 `order` 是 -10。那个菜单里其余几行都是插件的杂务，唯一一行用来打开页面的应该排在最前面。

同一次改动里把「应用」页默认清单里的那张卡片撤掉，于是一个页面还是一个入口，没有变成两个。

## Alternatives considered

- **卡片留着，再加这一行。** 一个页面两个门。挪走的原因本来就是一个页面该有一个入口，而那张卡片站错了房间。
- **把页面放回左栏，注册回 `sidebar.panellist`。** 一下就能点到，代价是左栏为这个偶尔才打开的页面多占
  第五行。这是上一篇笔记否掉的选择，这次也不重新翻案。
- **让 `dsh-apps-panel` 留着卡片，改成向本插件要卡片。** 上一篇笔记已经否掉了那个跨插件扩展点。把入口收到
  自己手里是删掉这个约定，而不是把它做复杂。

## Consequences

- 这一行要求宿主声明了 `sidebar.panellist.actions`，也就是 0.2.1-rc.3 及以后。更老的宿主上，注册落不到
  任何地方，页面没有入口；插件没写 `engines` 字段，所以不会有提示。
- 进这一页仍然是两下，和原来点卡片一样，只是这两下不再经过启动台，于是卡片网格和它的内嵌探测都不用在
  路上跑一遍。
- `lingualab` 这个字符串不再是两个包之间的约定：它只是本插件的 `main` key，`dsh-apps-panel` 的默认清单里
  也没有再指名它的条目。
