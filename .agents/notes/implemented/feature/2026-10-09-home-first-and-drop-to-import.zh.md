# Agent Note: 先进首页挑一集，文件拖进来就能导入

Status: implemented

## Problem

第一次打开时，页面是一个空的播放器。空状态用的全是插件自己的术语：「媒体目录」、文本框里的绝对路径、
十三条候选路径，而且每一条都标着不存在。用户只是想听一听，却得先弄懂什么是媒体目录，手工建好，
再把文件拷进去，页面才能做任何事。有了素材也好不了多少：选一集要点顶栏上那个小标题，打开一层浮层，
在两个标签之间选，再一级一级浏览目录。

练习本身也不顺手：

- 控制栏上有十三个控件，每分钟都要用的两个（播放、循环本句）和每次练习只用一回的（A、B 点、重复次数）挤在一起。
- 收藏一句要弹出输入框。收藏一集的第八句时还会弹出选择器，问七句里删掉哪一句，而那一句还在播放。

## Decision

**页面先进首页，练习是第二个视图。**

- 首页上最大的是接着要听的那一集，其余剧集排成一行一行，点一下就打开，再往下是添加素材的入口。
- 打开一集就切到练习视图，练习视图的返回按钮回到首页。
- 原来选集用的那层浮层去掉了，选择器只保留「浏览已有的文件」，用来打开放在媒体目录之外的素材。

**文件拖进来就能导入。**

- `POST /lingualab/import` 把一个文件作为原始请求体接收，剧集文件夹和文件名放在查询参数里。
- 页面按服务端（host）配对字幕的同一条规则给一次拖入的文件分组：字幕归到文件名是它前缀的那个音频，取最长匹配；
  只有一个音频和一个字幕时，不论叫什么都算一对。
- 先发音频，再发它的字幕，每个文件一次请求。
- 所以空库显示的是一个拖放区和一个按钮，完全不提文件夹。

**这是插件唯一往媒体目录里写东西的地方，范围很窄。**

- 从不覆盖：同名文件已存在就报告 `exists`，原文件不动。
- 只接收库扫描本来就读的扩展名。
- 文件名由服务端清洗。文件夹建好之后再确认它在根目录之内，所以指向别处的符号链接无法把写入引到外面。
- 内容先写进同一文件夹里的隐藏临时文件，写完整了才链接到位，中断的上传不会留下一个看起来像音频的残缺文件。
- 单个文件上限 2 GB，页面检查一次，服务端再检查一次。服务端除了看声明的长度，还对数据流计数，所以谎报大小的请求体也会被拦下。
- 同时最多两个上传，第三个得到 `429`，页面等一会儿再试。

**谁能调用这条路由，由宿主自己的请求信任决定，不靠文件检查。**

- 插件的每一条路由，包括只读的，都要经过 `connection.admit`（`Host` 是回环地址、`Origin` 匹配、会话 cookie 带签名），
  不满足就回 `401` 或 `403`。
- 宿主只对 `/api` 和 RPC 通道做这项检查，插件自己注册在 web 服务器上的路由不在其中。所以少了这一步，
  把主机名重新绑定到 127.0.0.1 的网页就能以同源身份调用导入和配置路由，连预检请求都不需要；本机的任何其他进程也一样。
- 导入路由上的自定义请求头保留，作为第二道检查，用来确认请求来自面板自己的代码；它不是访问控制。
- 没有 connection 服务时，插件一律拒绝，不会放行。

**练习视图的控制栏上只留六个控件。** 上一句、播放、下一句、变速、循环本句和中文显示留下；A、B 点和重复次数，
连同完整的快捷键列表，一起收进「更多」菜单。

**收藏一句是开关，不是表单。** 控制栏和每一行字幕上都有星标，点一下收藏这一句，再点一次或者按 `S` 就取消。
笔记放在抽屉里，有「还在练」「已记住」和全部三个视图。一句记住了就打勾，它从第一个视图里消失，但不会被删除。

**取消七条上限。** 笔记文件的格式不变。服务端仍然拒绝超过 500 条的列表，这只是为了防止失控的前端写出无限大的文件。

**页面记住听到哪里。**

- 每集一份，存在当前浏览器的 `localStorage` 里。练习视图开着时每五秒写一次，离开时再写一次。
- 首页用它显示「接着上次」那张卡片；打开一集时，等音频就绪后跳到记录的位置。
- 跳转完成之前不写书签，所以刚打开的一集不会覆盖它马上要用的书签。

## Alternatives considered

- **保留以文件夹为先的空状态，把说明写得更清楚。** 新用户仍然要先建目录、再拷文件，之前什么都用不了。
  问题从来不在说明写得好不好，而在于需要说明。
- **自带一集生成的示例。** 第一分钟能用起来，但学不到真实的流程，还需要语音合成或者附带音频。
  拖一个真实文件进来步数一样，走的也正是之后一直要用的流程。
- **保留上限，把替换选择器做得不那么打扰。** 不管怎么包装，这条规则都会在最糟的时刻要求用户做决定。
  笔记列表上的筛选同样能给出上限想要的那份短的待练清单，又不会在一句话播到一半时提问。
- **大小不同时允许导入覆盖已有文件。** 这种靠猜的规则一旦猜错，就会删掉别人的音频。报告 `exists` 后不动文件，
  没有哪种失败情形值得拿省下的那一次点击来换。
- **用 multipart 表单上传。** 一整集音频要在某一端全部缓冲进内存。原始请求体直接流进磁盘，上限固定。
- **把书签存到服务端。** 换浏览器也能接着听，代价是多一条写入路由，还要在 profile 里给一个丢了也无所谓的东西留位置。

## Consequences

- 「素材目录只读」这条规则不再毫无例外。现在的规则更窄，也有检查：插件只写交给它的新文件，
  从不替换已有文件，也从不写到媒体库根目录之外。扫描、浏览、打开这几条路径仍然全部只读。
- 剧集文件夹以音频文件名命名，所以两次拖入同名但不相干的文件会共用一个文件夹，第二次报告 `exists`。
  改名由用户自己处理。
- 原来不超过七条的笔记文件保持原样，不做任何迁移。
- 书签每个浏览器一份。换一个浏览器，每一集都从头开始，首页上也看不到进度。
- 可能出现五百条收藏。抽屉里的几个视图让这么长的列表也能翻看，要不要删减由用户自己决定。
