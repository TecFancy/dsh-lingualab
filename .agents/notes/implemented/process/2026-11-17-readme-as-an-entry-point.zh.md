# Agent Note: README 只做入口，长文放进 `docs/`

Status: implemented

## Problem

`README.md` 长到了 313 行，`README.zh.md` 长到 276 行。它同时在做四件事：介绍这个插件、讲清练习流程、
记录服务端契约、记下发版流程。前两件是刚来的人要看的，后两件是已经决定动手改仓库的人查一次的参考资料。

混在一起对两种读者都不好。新来的人要翻过一张十七行的路由表和一张上报字段表，才知道这个面板是干什么的；
路由表后来也更难找，因为它夹在叙述中间。这份文件还是靠不断追加长起来的：每加一个功能就往「做什么」里补一段，
因为没有别的地方可放。

仓库其实已经有对应的结构。`scripts/check-docs.mjs` 本来就是为 `docs/` 目录写的检查：目录下每份文档都要能从
README 链到，不许有 `INDEX.md`，每份文档开头恰好一个 H1。它此前一直在一个空目录上通过。

## Decision

**README 负责介绍和指路，`docs/` 负责讲清楚。**

- `README.md` 保留介绍、压缩后的「做什么」、当前状态、文档表、Figma 设计稿链接，以及六行的使用统计摘要。
  全文不到 100 行。
- 五份文档承载长文，每份都是中英一对：`docs/usage.md`（首页、添加素材、剧集与分段、视频、练习、笔记与复习、
  设置）、`docs/telemetry.md`、`docs/releasing.md`、`docs/host-routes.md`、`docs/repository-layout.md`。
- README 里的文档表就是索引。仍然没有 `INDEX.md`，`docs:check` 仍然会把没人链接的文档判为失败，
  所以新加的文档没人链就是检查失败，而不是一个没人读的文件。
- 中文那份是重写，不是再翻一遍。上一轮已经改掉了大部分直译腔，但还有几处漏网：`chip` 被译成「芯片」，
  `raise the version` 被译成「抬高版本号」，还有几段仍然把三件事塞进一句话里。

## Alternatives considered

**只留一份 README，把文字收紧。** 否掉了：问题不在措辞。路由表和上报字段表是参考资料，
再怎么改也不该出现在介绍里。

**拆进 `docs/`，再加一份 `INDEX.md`。** 否掉了：现有检查有意禁止 `INDEX.md`，因为手工维护的索引会和目录树脱节。
README 里的表加上链接检查，导航效果一样，还少一个要同步的文件。

**把参考资料搬进仓库自带的技能。** 否掉了：技能是给已经在仓库里干活的 agent 看的，而且要占上下文预算。
README 和 `docs/` 是给刚来的人看的，不打开就不花任何代价。
