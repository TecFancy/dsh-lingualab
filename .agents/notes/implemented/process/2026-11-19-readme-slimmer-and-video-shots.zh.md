# Agent Note: README 把参考资料交给 `docs/`，截图补上视频

Status: implemented

[English](2026-11-19-readme-slimmer-and-video-shots.md) | 简体中文

## Problem

上一轮已经把 README 从 313 行砍到 78 行，用法、上报、发版、路由和目录结构的长文都搬进了 `docs/`（2026-11-17）。但有两节留了下来，而且两节都是参考资料，不是介绍：「当前状态」讲服务端和前端各做什么、面板怎么注册、改动从哪个分支发布；「设计稿」放 Figma 链接、页面怎么取宿主令牌，还有窄屏抽屉和一张 iPad 截图。全文近四分之一还在讲插件内部怎么接起来，而不是它是什么、怎么用。

使用统计那一段也是 README 里唯一一处把 `docs/` 里的表整段重复的地方：五行载荷规则，只有正在决定要不要打开统计的人才用得上。

截图的问题正好相反。面板的视频能力——视频在句子上方播放、准备一次就能看、更省带宽的流畅版、盲看时只看画面——四张图里一张都没有，于是无论看 README 还是插件市场卡片，都容易以为 LinguaLab 只能做音频精听。市场卡片尤其如此：它读的是 `screenshots.json`，根本不看 README。

## Decision

- 把「当前状态」搬到 `docs/status.md`，把「设计稿」搬到 `docs/design.md`，中英各一对，并在 README 的文档表里各加一行。iPad 截图、Figma 链接和令牌规则跟着 `docs/design.md` 走，入口注册那一段跟着 `docs/status.md` 走。
- README 只保留四项介绍性内容：开头的介绍和练习页截图、安装说明加一行统计提示、带视频截图的「做什么」，以及文档表加深色收藏截图。
- 从生成的演示视频剧集里补两张截图：`video-practice-light.webp`（画面上方播放，右栏是字幕）和 `video-large-light.webp`（画面占满整个舞台）。两张都加进 `screenshots.json`，排在首页那张之后、紧挨着，让两张视频截图连续展示，共同呈现视频学习能力，后面再接收藏和 iPad 两张；README 里只放前一张。
- 演示素材全部自己生成：用代码画一张日出的插画，再做成缓慢推近的视频；旁白用 ffmpeg 的 `flite` 滤镜合成；字幕为本仓库编写。不用任何影视素材，画面里也不出现截图那台机器的路径。

## Alternatives considered

**为了那张 iPad 图把「设计稿」留在 README。** 否掉了：那张图是抽屉布局的佐证，不是介绍；窄屏细节是用户决定安装之后才会去查的东西。图现在放在讲布局的那份文档里。

**用视频截图替掉练习页首图。** 否掉了：音频精听仍然是默认路径，第一张图该展示面板最基础的功能。视频在介绍它的那条清单后面单独配图。

**截准备视频的卡片，而不是正在播放的画面。** 否掉了：卡片讲的是要装什么，而带字幕的播放画面才是「视频学习」的样子。准备过程中的几种状态写在 `docs/usage.md` 里。

**只把截图加进 `screenshots.json`。** 否掉了：README 才是访客首先看到的页面，它没展示的能力，访客就只能凭文字介绍判断。

## Why

README 要在首屏回答「这是什么、从哪儿开始」，参考资料供已经决定使用或修改这个插件的用户查阅，在文档表中给出入口即可。截图是访客唯一能看到视频能力的地方，而市场卡片不读 README，所以 README 和市场卡片都要补上视频截图。
