# Agent Note: 跨半边契约靠两座桥进客户端

Status: implemented

## Problem

两个半边说的是同一套词：路由路径、载荷形状、笔记 markdown 格式。host 按这些形状提供数据，面板
按这些形状渲染，所以定义必须放在两个半边之外。但客户端半边是按 FSD 树检查的，某一层从根外面导入
就是分层违规，检查工具拦得对。

## Decision

契约放在 `src/shared/`，另有两个只做一件事的模块，`src/client/shared/protocol.ts` 与
`src/client/shared/notes-format.ts`，替客户端树把它转出来。客户端里所有代码导入桥，只有桥导入
内核。每座桥都在自己的文件头里写明它为什么存在。

## Alternatives considered

- **让客户端文件直接导入内核。** Steiger 不管，因为目标落在被分析目录之外。代价是这个边界上有多少
  处导入就有多少扇门。
- **把契约搬进客户端树，让 host 反过来导入。** host 会依赖一个受 FSD 管辖的目录，关系倒过来了，
  而且一次只关乎 host 的改动看起来会像一次分层决定。
- **两边各写一份类型。** 保证漂移，而且漂到某个载荷字段改名时才暴露。

## Consequences

新增一个共用形状，有一个家，最多加一座桥。读者想知道「客户端能看到 host 的什么」，只需要看这两
个文件。
