# Agent Note: 两端共用的契约经转发文件进入前端

Status: implemented

## Problem

服务端（host）和前端（client）用的是同一套定义：路由路径、请求与响应的形状、笔记的 markdown 格式。
服务端按这些形状提供数据，面板按这些形状渲染，所以这些定义必须放在两端之外。
但前端是按 FSD 目录树检查的，某一层从根目录外面导入，就是分层违规，检查工具拦下它是对的。

## Decision

契约放在 `src/shared/`。另有两个只做转发的模块 `src/client/shared/protocol.ts` 与
`src/client/shared/notes-format.ts`，把契约重新导出给前端。前端的代码都从这两个转发文件导入，
只有转发文件直接导入 `src/shared/`。每个转发文件都在文件头里写明它为什么存在。

## Alternatives considered

- **让前端文件直接导入 `src/shared/`。** Steiger 不会拦，因为导入目标在被分析的目录之外。
  代价是有多少处导入，两端的边界上就有多少个入口。
- **把契约搬进前端目录，让服务端反过来从那里导入。** 服务端就会依赖一个受 FSD 约束的目录，依赖方向反了，
  而且一次只涉及服务端的改动，看起来会像是在做分层决定。
- **两端各写一份类型。** 两份一定会慢慢不一致，而且要等到某个字段在一端改了名才会暴露。

## Consequences

新增一个共用的形状，只有一个存放位置，最多再加一个转发文件。想知道「前端能看到服务端的哪些东西」，
只需要看这两个文件。
