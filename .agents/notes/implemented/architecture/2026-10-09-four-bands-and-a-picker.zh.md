# Agent Note: 练习页分四条横带，素材靠浏览来挑

状态：已落地

## Problem

收到两条抱怨，根源是同一个：

- 页面是一摞分量相同的卡片（播放器、字幕、媒体目录、笔记、五步），视线不知道该先落在哪里。
  一个两个月才改一次的设置，和每天都要写的笔记摆在同一层。
- 选「练什么」只能靠一个原生 `<select>` 选剧集标题，给它提供选项的扫描只看子文件夹；
  媒体库根目录也只能往输入框里手动输入绝对路径。

## Decision

**页面分成四条横带：**

- 48 像素高的顶栏：返回、当前剧集，以及「笔记」「五步」「媒体目录」三个小按钮。
- 舞台：固定显示正在练的那一句，连同播放控制条。
- 字幕列表：唯一会滚动的区域。
- 32 像素高的快捷键提示行。

原来的标题和副标题删掉了：在练习页上，剧集名就是标题。除了字幕列表，没有别的东西会滚动，
所以「再听这一句」按钮不会和它对应的句子一起滚走。

**不在听的时候才用的东西，一律做成浮层。** 选剧集、记笔记、设置媒体目录，用完就关。
宽页面上，笔记浮层把字幕列表挤窄，而不是盖住它；窄页面上改成盖住列表。两种情况下，正在练的句子都留在舞台上。

**素材靠浏览来挑：**

- `GET /lingualab/places` 列出选择浮层可以浏览的根目录，包括每个工作区和媒体库本身，只返回 id，不返回路径。
- `GET /lingualab/browse` 列出一个目录的内容：子目录、音频文件、字幕，以及每个音频旁边配到了哪些字幕（只按文件名判断）。
- `POST /lingualab/open` 把其中一项设为当前素材，可以是扫描已经认识的文件夹剧集，也可以是单个音频文件。
  单个音频文件会记进插件自己的 profile，文件内容经 `GET /lingualab/file-media/<id>/<文件>` 提供。

**零散的音频文件也是素材。** 直接放在媒体库根目录里的文件单独列成一组，也能单独打开。
扫描保持只读，只负责列出它们；让它们能被提供的索引，在打开的那一刻才写下。

**设置里保留手动输入路径作为后备。** 一个不在任何工作区之下的挂载点，没法从哪里浏览过去，
所以媒体目录浮层仍然接受绝对路径。只是页面不再一上来就要求填它。

## Alternatives considered

- **保留卡片，只重做样式。** 更省事，但真正的问题还在：五块分量相同的东西，
  而且听的时候要看的那一块会滚走。
- **把笔记放进一个常驻的右栏。** 要占掉字幕列表一半的宽度，留给一个每小时才看几次的东西；
  上一版已经表明，这样会让扫读字幕变得很难受。
- **保留 `<select>`，在旁边加一个「浏览」对话框。** 要维护两套选择方式，
  而且下拉框仍然看不出一集有没有字幕。
- **让浏览器把要浏览的路径发过来。** 那样一条插件路由就变成了别人服务器上的通用文件浏览器，
  白名单也就形同虚设。
- **把文件剧集的笔记写在音频旁边。** 这个插件的规矩是素材目录只读；
  在音频旁边多放一个 `S01E03.notes.md` 违反这条规矩，同一份数据也会多出第二个存放位置。

## Consequences

- 前端（client）不能再用路径指定一个文件；一律传 place id 加相对路径，由服务端（host）在 `realpath` 之后重新校验。
- 文件剧集的笔记和它的索引条目都存放在插件的 profile 条目里（`openState`），
  也就是写 `libraryRoot` 的同一个地方。笔记因此有两个存放位置：文件夹剧集用 markdown，文件剧集用 profile 里的 JSON。
  这是「不往用户的素材目录里写东西」的代价。
- 选素材是一次请求，不是本地状态：服务端确认之前浮层不关，
  所以被拒绝时，原因显示在列表所在的位置，不会跟着浮层一起消失。
- 键盘多了一个「当前行」的概念：`↑`/`↓` 只移动选中的行，不动音频，按 `Enter` 才播放。
  往后翻着预览时，不会丢掉正在播放的位置。
