# Agent Note: 布局看练习栏自己的大小，不看窗口

Status: implemented

## Problem

练习页在一栏里叠了四样东西：画面、句子、调时间面板和播放卡片。它是照桌面窗口排的，到了 iPad 上有两处坏掉。

第一处是高度。在 1180 乘 760（横屏的 iPad）下，这一栏只有 711px 高，调时间面板打开时，画面（208px）、面板（350px）和卡片
（264px）加起来要 822px，句子还一点没分到。句子是唯一能伸缩的一项，被挤到 40px，而它的文字至少要 140px，于是压在画面和面板
上，卡片落到屏幕下面，播放键够不着。在 1024 乘 700 下，面板收起来时句子也放不下。

第二处是断点问的问题不对。它们是视口媒体查询，可宿主的侧栏占 56px 或 280px，右侧字幕栏又占掉剩下的约三分之一，所以窗口有
1024 或 1180px 时练习栏只有 440 到 630px。那条唯一的 `max-width:860px` 规则从来没生效过。栏这么窄时，画面只有 300 乘 169，
叠在上面的小胶囊挤成一团；调时间面板的两张边缘卡各只有约 174px，时间值、步进按钮和播放位置按钮都折行；键盘提示在没有键盘的
设备上白占一行，而按钮只有 36 乘 30。

第一次修复（v0.11.2）把断点改成了问栏，但留下两件事。在 1024 乘 700 下调时间面板打开时，句子、面板（379px）和卡片（264px）
仍比栏多出 147px，所以滚动容器要滚动；而且只要面板打开、栏高又不到 1000px，画面就一律被隐藏，这包括所有 iPad，也包括 900px 高
的桌面窗口。右侧字幕栏里的跟随开关也伸出了 260px 宽的字幕栏。

## Decision

**练习栏是一个尺寸容器，关于栏内内容的规则都问这一栏自己。** 它与右侧字幕栏同处的那一行是一个宽度容器，只管字幕栏的那一条规则。

- **两个命名容器。** `.dsh-lingualab-practice` 是 `container:ll-practice/size`（它有确定的尺寸：它是固定高度那一行里的 flex 子项，
  所以尺寸隔离不花代价），`.dsh-lingualab-body` 是 `container:ll-body/inline-size`。字幕栏变窄到 260px 的规则问 `ll-body`，
  其余的问 `ll-practice`。只有浏览层和减弱动效还用媒体查询，因为它们说的是窗口。第三个容器 `ll-video` 是画面的舞台，在它
  拿走剩余空间的时候才用（见下面的调时间模式）。
- **尺寸查询量的是内容盒。** 这一栏左右各有 24px 内边距、底部 20px，所以样式表里每个数都是栏宽减 48、栏高减 20。用来核对
  阈值的那个桌面（栏约 765 乘 851，按这个口径是 717 乘 831）在调时间面板收起时，一条宽度或高度规则都不触发。
- **播放卡片上面那一段自己滚动，卡片永远不动。** 卡片以上的内容都放在 `.dsh-lingualab-practice-main` 里，它是一个 flex 列，也是
  唯一的滚动容器；句子是 `flex:1 0 auto`，永远不会缩到文字以下。画面、句子和调时间面板放不下时，这一段滚动，不可能再重叠。
  卡片留在它下面，够得着。
- **矮的时候分几步收紧，滚动是最后手段，而不是常态。** 内容高度不到 700px 时，句子两侧的上下句先去掉，画面限制为栏高的
  30%（以前是窗口高的 42%，那个上限不跟着栏走），舞台让出一些内边距。画面的宽度取它在栏里的份额、720px、以及这个上限按
  16:9 允许的宽度三者中最小的，所以加上限会让它变小，形状不变。
- **调整时间是一种模式。** 调时间面板里有句子期间，页面给练习栏加上 `is-timing`。这是有意用类名，而不是对面板用 `:has()`：
  由唯一决定它的那个状态来设置，测试不需要布局引擎就能看到它，也不依赖面板是否挂载（面板在退出动画期间仍然挂着）。
  凡不是句子、面板和播放它的办法，一律退后：
  - 播放卡片折成进度条加一行，「变速 | 上一句、播放、下一句」，约 124px，以前是 264px。其余的按钮、按键提示和打开着的菜单都用
    类名隐藏，而不是卸载，所以面板一关，全部原样回来。变速按钮带 `is-speed`，是被留下的那一个；这一行在任何宽度下都是三列的
    网格，因为窄栏里那条把卡片两侧拆成一股折行流的规则，否则会把变速挤到第二行。
  - 句子两侧的上下句去掉，句子也不再被拉伸去占地方，所以它只有文字那么高。
  - 在播放的画面拿走剩下的空间。它的舞台是一个尺寸容器（`ll-video`），`flex:1 1 0`，画面是放得下的、与视频本身同形状的最大一个
    盒子，用的是大画面状态的办法：宽度取容器宽度、720px、以及容器高度乘比例三者中最小的（比例是 `--ll-video-ratio`，显示中的
    画面现在也带它；它平时的框仍是 16:9）。容器高度不到 120px 时不画；`<video>` 照常播放，和音频文件一样。代替画面的卡片或
    小标签（没有 `has-screen` 的舞台）在调时间期间不画，画面上的小胶囊（本地文件、流畅版）也不画：它们放不进一个小画面，
    对移动一个边缘也没有帮助。
  - 大画面保持原样。它本来就是拿走剩余空间的那一部分（它是整个舞台，它的句子也不在舞台上去抢地方），还有 160px 的下限，
    所以永远碰不到 120px 那条规则。把它藏起来，就让主动要大画面的读者面对一个什么也没有的舞台。
- **调时间面板在小空间里是同一种紧凑布局。** 它问的是 `(max-width:600px) or (max-height:760px)`，也就是栏宽不到 648px 或栏高不到
  780px。开头与结尾各占一行：标签，下面是它移动了多少；时间值（18px）；两个 50 毫秒的步进按钮；播放头按钮，高 44px（触屏上是
  52px，步进按钮是 44px）。底部是一行：还原、取消，以及占满剩余宽度的保存。迷你时间轴和按键提示去掉。文字长的按钮同时画出长文字
  和短文字（`timingAtPlayheadShort`、`timingSaveShort`），由样式表挑一个；完整的文字仍留作 `aria-label` 和 `title`。一行放不下四个
  部分时，播放头按钮占该行的第二行：内容宽度不到 372px 时，触屏上不到 392px 时。这一行大约需要 341px（触屏 365px），阈值留了
  24px 的余量，给时间值里多出的一个小时（`1:05:12.345`）。又宽又高的栏仍是两张卡加迷你时间轴。这一种布局取代了 v0.11.2 里
  分两步叠放的卡片（520px 与 440px），所以窄栏只有一种布局，而不是三种。面板高约 205px（触屏 233px），以前是 379px。
- **窄宽度。** 不到 600px 时，画面和各种卡片占满整栏，流畅版的小胶囊换行（触屏上没有悬停提示，截掉的字就读不到了），卡片的
  按钮排成居中的几行。
- **字幕栏是 260px 宽时，跟随开关写成「跟随」。** 两个词都画出来，由样式表挑一个；完整的词仍是复选框的 `aria-label`。这一行里
  栏头的内边距、间距和分段控件都收紧了一点，所以带三位数计数的分段控件和开关放得下，没有任何东西伸出字幕栏的边。
- **触屏看的是指针，不是宽度。** `(hover:none) and (pointer:coarse)` 去掉键盘提示（所有 `kbd`、播放器下面的按键行、调时间面板里的
  按键、快捷键列表、编辑器与选择器的提示），并让播放卡片上的每个按钮（包括上一句和下一句）、调时间面板的步进按钮、播放头按钮、
  「取消」和「保存」都是 44px 高。卡片每多折一行按钮，就高约 12px。画面上的小胶囊保持原来的大小，触控区靠一圈看不见的外边距
  扩到 44px：真做成 44px 高，一个胶囊就要盖住 169px 高画面的四分之一。

## Alternatives considered

- **多加几个视口断点。** 侧栏和字幕栏让窗口宽度成了栏宽的一个很差的估计，错就错在这里；断点设在 1100，对一种侧栏状态是对的，对
  另一种就是错的。
- **用 resize observer 去设类名。** 在不支持容器查询的地方它也能用，但那是一段要和样式表保持同步的代码，在布局之后才跑，
  还会闪一下错的布局。容器查询在当前的 Safari、Chrome 和 Firefox 里都有。页面确实要设的那一个类名 `is-timing`，是页面本来就有的
  一个状态，不是一次测量。
- **整栏滚动，连卡片一起。** 那样栏恰好太矮的时候，播放键就在屏幕外，这正是被投诉的地方；而吸底的卡片又要有一层背景去盖住
  从它下面滚过的内容。
- **把画面和句子按比例缩小。** 跟着栏高走的字号，会让句子在 iPad 读者最需要它大的地方变小，缩小的画面也还是要占地方。
- **面板打开、栏又矮的时候就隐藏画面。** 这是 v0.11.2 的做法，它把所有 iPad 和 900px 高的桌面窗口里的画面都藏了，而这些地方
  放得下一幅小画面。现在画面是拿走剩余空间的那一部分，只有剩下的空间不到 120px 才让开。
- **只折面板，不动播放卡片。** 卡片还是 264px 的话，面板降不到约 230px 以下，画面在 1024 乘 700 下也回不来；调时间期间，
  循环、跟读、画面和菜单都不是读者会去碰的东西，所以让它们先等一等。
- **窄栏里把开头与结尾两张卡叠起来（v0.11.2）。** 两张叠放的卡各占两行，一共 232px，而栏总共只有 631px；每个边缘一行是 96px，
  不到一半，同一种布局也同时适用于又矮又宽的栏和又窄又高的栏。

## Settled details

- **量出来的，不是猜的。** 阈值来自把真实的组件和真实的样式表渲染成标记，在浏览器里按每个尺寸（iPad 竖屏 820 乘 1180 与
  744 乘 1133，横屏 1180 乘 760 与 1024 乘 700，每个都配宿主侧栏 56、224、280px，外加桌面 1440 乘 900），触屏和非触屏各一遍，
  再读回高度。没有在真机上量：Safari 自己的工具栏要占高度，上面的数字没算进去，所以真的 iPad 会矮一点，更早碰到滚动。
- **收起面板时，页面还是原来的样子。** 调时间面板收起、没有触屏时，播放卡片、画面和句子在每个尺寸下的高度都与 v0.11.2 完全一样
  （1440 乘 900 的桌面上画面是 443 乘 249）。只有触屏不同，差别就是 44px 的按钮。
- **在 1024 乘 700、宿主侧栏展开时调时间，放得下。** 栏是 483 乘 651。句子只有一行时，卡片 126px，句子 135px，面板 205px
  （触屏 233px），画面 269 乘 151（触屏 219 乘 123），不用滚动。句子有两行时，句子 214px，画面放不下，就不画，句子上面的那一块
  空着，同样不用滚动。这块空着的地方，是画面容器要付的代价：它在布局完成之前不可能知道还剩多少空间。
- **面板打开时，画面最多变化一次。** 面板是从无到有地长出一个网格行，所以留给画面的空间只会变小，穿过 120px 时隐藏一次。
  面板打开的瞬间，画面先从平时的大小跳到放得下的最大盒子（这时空间里还没有面板），然后再缩小。关闭时平时的布局立刻回来，
  而面板还在退出。
- **长句子在该滚的地方仍会滚动。** 两行英文加一行中文，舞台要约 250px；栏放不下句子、面板和卡片时（栏高不到约 570px），
  剩下的交给滚动容器。
- **播放卡片上的按钮用指针时是 32px，用手指时是 44px。** 给鼠标也做成 44px，会给本来就是矮栏里最高的那张卡片添两行。
