# Agent Note: 布局看练习栏自己的大小，不看窗口

Status: implemented

## Problem

练习页在一栏里叠了四样东西：画面、句子、调时间面板和播放卡片。它是照桌面窗口排的，到了 iPad 上有两处坏掉。

第一处是高度。在 1180 乘 760（横屏的 iPad）下，这一栏只有 711px 高，调时间面板打开时，画面（208px）、面板（350px）和卡片
（264px）加起来要 822px，句子还一点没分到。句子是唯一能伸缩的一项，被挤到 40px，而它的文字至少要 140px，于是压在画面和面板
上，卡片落到屏幕下面，播放键够不着。在 1024 乘 700 下，面板收起来时句子也放不下。

第二处是断点问的问题不对。它们是视口媒体查询，可宿主的侧栏占 56px 或 280px，右侧字幕栏又占掉剩下的约三分之一，所以窗口有
1024 或 1180px 时练习栏只有 440 到 630px。那条唯一的 `max-width:860px` 规则从来没生效过。栏这么窄时，画面只有 300 乘 169，
叠在上面的小胶囊挤成一团；调时间面板的两张边缘卡各只有约 174px，时间值、步进按钮和播放位置按钮都折行；键盘提示在没有键盘的
设备上白占一行，而按钮只有 36 乘 30。

第一次修复（v0.11.2）把断点改成了问栏，但留下两件事。在 1024 乘 700 下调时间面板打开时，句子、面板（379px）和卡片（264px）
仍比栏多出 147px，所以滚动容器要滚动；而且只要面板打开、栏高又不到 1000px，画面就一律被隐藏，这包括所有 iPad，也包括 900px 高
的桌面窗口。右侧字幕栏里的跟随开关也伸出了 260px 宽的字幕栏。

这两次修复量的都是没有算上 Safari 自己那一圈的视口尺寸。真的 iPad 上的 Safari 要从高度里扣掉状态栏和工具栏（紧凑标签布局约
74px，单独标签栏约 110px，后者是新版 iPadOS 的默认），所以 iPad mini 横屏是 1133 乘 670 或 634，不是 1133 乘 744；iPad Air 11 寸
是 1180 乘 746 或 710；iPad Pro 11 寸是 1194 乘 760 或 724；iPad Pro 13 寸是 1366 乘 950 或 914。调时间面板收起、画面在播放、句子是
两行英文加一行中文时，画面（180px）、句子和卡片（264px，触屏 230px）在 1133 乘 634 下比栏多要最多 74px（触屏 40px），1133 乘 670
下 49px，1180 乘 710 下 25px，1194 乘 724 下 17px，所以滚动容器要滚，而这个视图本不该用到它。音频文件、调时间面板打开时（画面本来
就会让位）和更大的 iPad 都没有溢出。

## Decision

**练习栏是一个尺寸容器，关于栏内内容的规则都问这一栏自己。** 它与右侧字幕栏同处的那一行是一个宽度容器，只管字幕栏的那一条规则。

- **两个命名容器。** `.dsh-lingualab-practice` 是 `container:ll-practice/size`（它有确定的尺寸：它是固定高度那一行里的 flex 子项，
  所以尺寸隔离不花代价），`.dsh-lingualab-body` 是 `container:ll-body/inline-size`。字幕栏变窄到 260px 的规则问 `ll-body`，
  其余的问 `ll-practice`。只有浏览层和减弱动效还用媒体查询，因为它们说的是窗口。第三个容器 `ll-video` 是画面的舞台，在它
  拿走剩余空间的时候才用（见下面的调时间模式）。
- **尺寸查询量的是内容盒。** 这一栏左右各有 24px 内边距、底部 20px，所以样式表里每个数都是栏宽减 48、栏高减 20。用来核对
  阈值的那个桌面（栏约 765 乘 851，按这个口径是 717 乘 831）在调时间面板收起时，一条宽度或高度规则都不触发。
- **播放卡片上面那一段自己滚动，卡片永远不动。** 卡片以上的内容都放在 `.dsh-lingualab-practice-main` 里，它是一个 flex 列，也是
  唯一的滚动容器；句子是 `flex:1 0 auto`，永远不会缩到文字以下。画面、句子和调时间面板放不下时，这一段滚动，不可能再重叠。
  卡片留在它下面，够得着。
- **矮的时候分几步收紧，滚动是最后手段，而不是常态。** 内容高度不到 700px 时，句子两侧的上下句先去掉，画面限制为栏高的
  30%（以前是窗口高的 42%，那个上限不跟着栏走），舞台让出一些内边距。画面的宽度取它在栏里的份额、720px、以及这个上限按
  16:9 允许的宽度三者中最小的，所以加上限会让它变小，形状不变。
- **在播放的画面会给句子和卡片让位，调时间面板收起时也一样。** 句子是文字，卡片是播放的办法，所以整个页面里画面是唯一有空间可让的
  部分。播放中的画面的舞台（`is-shown.has-screen`）用画面本来的大小作 `flex-basis`，由栏本身算出来：画面所占宽度份额、720px、高度
  上限三者中最小的那个，换算成高度（份额和上限是变量，舞台和画面都读它们，所以数字仍然只写一处），再加 `flex-shrink:1` 和
  `min-height:0`。它和调时间的那个一样是尺寸容器（`ll-video`），画面是它给出的空间里最大的 16:9 盒子（宽度取份额、720px 与
  `100cqh * 16 / 9` 三者最小的；没有 300px 的下限，也没有自己的高度上限）。句子舞台是 `flex:1 0 auto`，卡片是 `flex:none`，所以只有
  画面能缩，滚动容器又回到最后手段。空间够它原来的大小时，舞台就是原来的盒子（基准值就是原来的画面高度，舞台写了
  `box-sizing:content-box`，所以不管宿主怎么设置，内边距都在它外面），凡是原本放得下的都不动。不到 120px 时，同一个测量像调时间
  模式那样把舞台收起来：`usePictureRoom` 现在只要画面在「显示」状态下播放就运行（以前只在面板打开时运行），去掉舞台的规则也不再要求
  `is-timing`。仍然只在调时间时生效的是让位后句子舞台的 `flex:1 1 auto`：收起面板的栏里，长句子绝不能缩到文字以下。画面上的小胶囊
  （本地文件、流畅版）在画面不到 160px 时不画（`ll-video (max-height:159px)`，这是对舞台高度的唯一一条查询，它管的是画面上画什么，
  从不管画面画不画），因为它们大约要这么多空间才不互相挤到，231 乘 130 的截图就是这样。
- **代替画面的卡片分几步让位，靠试出来。** 卡片是文字加按钮，高度取决于它是哪一张、带了什么（流畅版的提议、用户自己的文件）：普通的准备卡是
  249px（高栏里是 342px），而 1133 乘 634 的栏只给它留 96px，所以不像画面那样能由栏算出一个基准值。`useCardFit`（放在页面切片里；选择和类名是
  `card-fit.ts` 里的纯函数）给滚动容器加一个类，从完整的卡片一直试到什么都不画，留下第一个让滚动容器没有东西可滚的步骤（`scrollHeight` 不大于
  `clientHeight`，按整像素）：
  - 完整的卡片没有类，就是样式表本来的样子，所以放得下的卡片画得和以前一模一样；
  - `is-card-compact` 把它收紧（内边距 12px，间距 6px，图标 28px）；
  - `is-card-lean` 去掉次要的部分（图标、解释的那句话、备注、流畅版的提议和用户自己的文件），留下卡片说了什么、该按什么，正文最多两行（约
    125 到 170px）；
  - `is-card-line` 是不换行的一行：标题、卡片讲的是什么（文件，或者进度条加百分比）和按钮，哪里放不下就用省略号截断（44px，触屏上按钮是 44px，
    所以是 58px）；
  - `is-card-hidden` 整个舞台都不画，和被挤掉的画面一样。

  每次试都从完整的卡片开始，所以答案只取决于空间和卡片，从不取决于上一步。不需要像画面那样加滞回带（画面要加，是因为它量的就是自己的盒子）：
  沿着某条边拖动栏的大小，两个方向上都在同一个高度换步。类设在滚动容器上，而 React 从不给这个元素写 class，所以钩子没有状态，也不引起渲染；试
  的过程是同步的，在绘制之前跑完，所以画出来的只有答案。哪一步都放不下时，说明太高的是句子或调时间面板，藏起卡片也没用，所以留一行，准备视频的
  入口还在屏幕上。`VideoStage` 给装着卡片的舞台加上 `has-card`，它是钩子找到卡片的把手（也是样式表在隐藏那一步用的），所以各个 widget 彼此不必
  知道对方。调时间面板打开时卡片不画，也就不量。触屏在每一步都保留 44px 的按钮，因为那是 `min-height`，没有哪一步会设它。
- **调整时间是一种模式。** 调时间面板在页面上期间（里面有句子，退出时还会多留一会儿），页面给练习栏加上 `is-timing`。这是有意用
  类名，而不是对面板用 `:has()`：由页面里唯一的那个在场状态，同时决定栏和面板，测试不需要布局引擎就能看到它。只有布局跟着这个
  在场状态走，行为（按键、舞台上的按钮）跟着会话走。凡不是句子、面板和播放它的办法，一律退后：
  - 播放卡片折成进度条加一行，「变速 | 上一句、播放、下一句」，约 124px，以前是 264px。其余的按钮、按键提示和打开着的菜单都用
    类名隐藏，而不是卸载，所以面板一关，全部原样回来。变速按钮带 `is-speed`，是被留下的那一个；这一行在任何宽度下都是三列的
    网格，因为窄栏里那条把卡片两侧拆成一股折行流的规则，否则会把变速挤到第二行。
  - 句子两侧的上下句去掉，句子也不再被拉伸去占地方，所以它只有文字那么高。
  - 在播放的画面拿走剩下的空间。它的舞台是一个尺寸容器（`ll-video`），`flex:1 1 0`，画面是放得下的、与视频本身同形状的最大一个
    盒子，用的是大画面状态的办法：宽度取容器宽度、720px、以及容器高度乘比例三者中最小的（比例是 `--ll-video-ratio`，显示中的
    画面现在也带它；它平时的框仍是 16:9）。代替画面的卡片或小标签（没有 `has-screen` 的舞台）在调时间期间不画，画面上的小胶囊
    （本地文件、流畅版）也不画：它们放不进一个小画面，对移动一个边缘也没有帮助。
  - 画面不到 120px 时不画，它的舞台也不留。尺寸容器在子元素不画的时候缩不了自己（原来用容器查询把画面藏起来，舞台那个
    `flex:1` 的盒子却留了下来：两行句子的上方有约 80px 的空白），所以只有这一个决定要靠测量。`usePictureRoom`（放在页面切片里，
    因为它跨了三个部件）用不会随画面收起而变的东西算出画面能分到的空间：滚动容器去掉内边距后的高度，减去句子舞台需要的高度
    （按它的各行、行间距和内边距量，不按它自己的盒子量，因为这个盒子正是被这个状态拉伸的），再减去调时间横栏，再减去画面舞台
    自己的内边距。绝不读画面自己的盒子，那会自己追自己：收起，空间出现，显示，空间又没了。画面从 120px 起画，让开之后要到
    128px 才回来，所以把窗口拖在边缘上也不会闪。页面给练习栏加 `is-picture-squeezed`，样式表把画面舞台藏起来（`display:none`），
    句子舞台改成 `flex:1 1 auto`；舞台本来就把内容居中，所以句子落在这块空间的正中，读起来是句子周围的呼吸空间，而不是上方的
    一个洞。`<video>` 照常播放，和音频文件一样。测量在首次绘制之前跑，盯着滚动容器、舞台的各行（每换一句就整行替换，所以
    盯的集合每次变化都重建）和调时间横栏（面板从第一帧起就是完整高度，所以答案一出来就是最终的），并且只在面板里有句子且画面在播放时才开。没有
    `ResizeObserver` 时一律当作放得下。原来 119px 的那条容器查询没有了：第二条对边界有自己想法的规则，只差一个取整的像素，就会
    在两者不一致的地方把空盒子带回来。
  - 大画面保持原样。它本来就是拿走剩余空间的那一部分（它是整个舞台，它的句子也不在舞台上去抢地方），还有 160px 的下限，
    所以永远碰不到 120px 那条规则。把它藏起来，就让主动要大画面的用户面对一个什么也没有的舞台。
- **调时间面板在小空间里是同一种紧凑布局。** 它问的是 `(max-width:600px) or (max-height:760px)`，也就是栏宽不到 648px 或栏高不到
  780px。开头与结尾各占一行：标签，下面是它移动了多少；时间值（18px）；两个 50 毫秒的步进按钮；播放头按钮，高 44px（触屏上是
  52px，步进按钮是 44px）。底部是一行：还原、取消，以及占满剩余宽度的保存。迷你时间轴和按键提示去掉。文字长的按钮同时画出长文字
  和短文字（`timingAtPlayheadShort`、`timingSaveShort`），由样式表挑一个；完整的文字仍留作 `aria-label` 和 `title`。一行放不下四个
  部分时，播放头按钮占该行的第二行：内容宽度不到 372px 时，触屏上不到 392px 时。这一行大约需要 341px（触屏 365px），阈值留了
  24px 的余量，给时间值里多出的一个小时（`1:05:12.345`）。又宽又高的栏仍是两张卡加迷你时间轴。这一种布局取代了 v0.11.2 里
  分两步叠放的卡片（520px 与 440px），所以窄栏只有一种布局，而不是三种。面板高约 205px（触屏 233px），以前是 379px。
- **窄宽度。** 不到 600px 时，画面和各种卡片占满整栏，流畅版的小胶囊换行（触屏上没有悬停提示，截掉的字就读不到了），卡片的
  按钮排成居中的几行。
- **字幕栏是 260px 宽时，跟随开关写成「跟随」。** 两个词都画出来，由样式表挑一个；完整的词仍是复选框的 `aria-label`。这一行里
  栏头的内边距、间距和分段控件都收紧了一点，所以带三位数计数的分段控件和开关放得下，没有任何东西伸出字幕栏的边。
- **触屏看的是指针，不是宽度。** `(hover:none) and (pointer:coarse)` 去掉键盘提示（所有 `kbd`、播放器下面的按键行、调时间面板里的
  按键、快捷键列表、编辑器与选择器的提示），并让播放卡片上的每个按钮（包括上一句和下一句）、调时间面板的步进按钮、播放头按钮、
  「取消」和「保存」都是 44px 高。卡片每多折一行按钮，就高约 12px。画面上的小胶囊保持原来的大小，触控区靠一圈看不见的外边距
  扩到 44px：真做成 44px 高，一个胶囊就要盖住 169px 高画面的四分之一。

## Alternatives considered

- **多加几个视口断点。** 侧栏和字幕栏让窗口宽度成了栏宽的一个很差的估计，错就错在这里；断点设在 1100，对一种侧栏状态是对的，对
  另一种就是错的。
- **用 resize observer 去设类名。** 在不支持容器查询的地方它也能用，但那是一段要和样式表保持同步的代码，在布局之后才跑，
  还会闪一下错的布局。容器查询在当前的 Safari、Chrome 和 Firefox 里都有。页面为布局设的类名 `is-timing`，是页面本来就有的
  一个状态，不是一次测量。例外是 `is-picture-squeezed`，它管的是容器查询做不到的那一件事（把自己正在量的盒子收起来）；它是唯一的
  测量，在绘制之前跑，除这一个数之外的数仍都在样式表里。
- **整栏滚动，连卡片一起。** 那样栏恰好太矮的时候，播放键就在屏幕外，这正是被投诉的地方；而吸底的卡片又要有一层背景去盖住
  从它下面滚过的内容。
- **把画面和句子按比例缩小。** 跟着栏高走的字号，会让句子在 iPad 用户最需要它大的地方变小，缩小的画面也还是要占地方。
- **面板打开、栏又矮的时候就隐藏画面。** 这是 v0.11.2 的做法，它把所有 iPad 和 900px 高的桌面窗口里的画面都藏了，而这些地方
  放得下一幅小画面。现在画面是拿走剩余空间的那一部分，只有剩下的空间不到 120px 才让开。
- **只折面板，不动播放卡片。** 卡片还是 264px 的话，面板降不到约 230px 以下，画面在 1024 乘 700 下也回不来；调时间期间，
  循环、跟读、画面和菜单都不是用户会去碰的东西，所以让它们先等一等。
- **只用画面自己舞台上的容器查询来藏画面（v0.11.3）。** 它把舞台的盒子留了下来，里面什么也没画。把盒子改成 `flex:0 0 auto` 倒是能
  收起来，可画面的大小就是由这个盒子来的，盒子和画面会互相决定对方；测量只用不会变的东西，把这个环断开了。
- **窄栏里把开头与结尾两张卡叠起来（v0.11.2）。** 两张叠放的卡各占两行，一共 232px，而栏总共只有 631px；每个边缘一行是 96px，
  不到一半，同一种布局也同时适用于又矮又宽的栏和又窄又高的栏。
- **由页面把量出来的空间写成变量，来定画面大小。** 这不需要新的 CSS 想法，但测量在布局之后才跑，每次句子多出一行，就会先画一帧
  滚动容器在滚动的样子，再换成较小的画面。容器在同一次布局里就给画面定好大小；测量只留给容器做不了的那一个决定。
- **让舞台字号跟着栏高走。** 不需要：画面让位之后，句子和卡片在量过的每个尺寸下都放得下，字号里加一个高度项，只会在画面还能吸收
  缺口的地方改变文字。这也是上面那个「按比例缩小」的做法，会让句子在用户最需要它大的地方变小。
- **矮一点的栏里收紧卡片和舞台的内边距。** 大约能省 24px，让画面在一个尺寸（1133 乘 634、用指针、侧栏展开、两行）下保住，代价是
  多一个阈值，它会改变本篇里今天放得下的那些尺寸。没有这样做；那里改为让画面让开。
- **栏一矮就隐藏画面。** 那是 v0.11.2 对调时间犯的错；130 到 200px 的画面，正是 iPad 有空间放的。
- **像画面那样让卡片靠 flex 收缩。** flex 基准值要从一个尺寸开始，而卡片没有栏能给的尺寸（它多高由内容决定），所以舞台会缩到内容以下，把按钮截掉；
  画面能缩，是因为它是形状已知的盒子，卡片不是。
- **栏一矮就像藏画面那样藏卡片。** 卡片是要求准备视频的唯一入口，而画面是栏可以没有的东西；藏起卡片就是去掉那个按钮，所以它是最后一步。
- **用容器查询按栏高选步骤。** 句子是一到三行（每行约 40px），播放卡片又按宽度换行，所以栏的高度很难说明卡片有多少空间。试的办法直接读空间。

  测试环境是 Chrome 的引擎，字体也不是 SF Pro。
- **在 1024 乘 700、宿主侧栏展开时调时间，放得下。** 栏是 483 乘 651。句子只有一行时，卡片 126px，句子 135px，面板 205px
  （触屏 233px），画面 269 乘 151（触屏 219 乘 123），不用滚动。句子有两行时，句子 214px，画面放不下，就不画，句子上面的那一块
  收起来，句子舞台拿走剩下的约 80px，把句子居中放在里面，同样不用滚动。以前这里会在句子上方留一个空盒子，因为画面容器在布局完成
  之前不可能知道还剩多少空间；现在由测量去知道。
- **布局在每个方向上只走一步，动的只有卡片的外观。** 调时间面板在设置 `is-timing` 的那次提交里就占满它的高度，一直占到去掉
  `is-timing` 的那次提交；淡入和上浮的是里面的卡片。所以画面第一帧就落在最终大小上，或者被收起，`usePictureRoom` 只根据最终
  高度判断一次（画面穿过 120px 时隐藏一次，要回来得到 128px）。v0.11.5 之前面板是从无到有地长出一个网格行：画面先跳到放得下的
  最大盒子，在 240 毫秒里缩小，旁边是两行句子时最后还被收起；关闭时平时的布局立刻回来，而那一行还在收缩，布局动了两次。现在关闭
  按相反的顺序：卡片淡出，栏仍留在调时间模式里，等退出结束，栏在卸载面板的同一次提交里离开这个模式。两者跟着页面里同一个
  `usePresence`（面板以属性接收 `mounted` 和 `shown`，页面从面板所在的切片读退出时长），所以两个计时器不会差一帧。按键和舞台上的
  按钮跟着会话走，而会话立刻结束：卡片淡出期间按键已经归页面，面板是 inert 的。
