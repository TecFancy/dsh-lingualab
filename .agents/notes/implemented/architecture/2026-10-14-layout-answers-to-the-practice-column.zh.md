# Agent Note: 布局按练习栏自己的大小来定，不按窗口

Status: implemented

## Problem

练习页在一栏里叠了四样东西：画面、句子、调时间面板和播放卡片。这个布局是按桌面窗口设计的，到了 iPad 上有两处出了问题。

第一处是高度：

- 在 1180 乘 760（横屏的 iPad）下，这一栏只有 711px 高。调时间面板打开时，画面（208px）、面板（350px）和卡片（264px）
  加起来要 822px，句子还一点空间都没分到。
- 句子是唯一能伸缩的一项，被挤到 40px，而它的文字至少要 140px。结果句子压在画面和面板上，卡片落到屏幕下面，播放键够不着。
- 在 1024 乘 700 下，即使面板收起，句子也放不下。

第二处是断点判断的依据不对：

- 断点用的是视口媒体查询，可宿主的侧栏占 56px 或 280px，右侧字幕栏又占掉剩下的约三分之一，所以窗口宽 1024 或 1180px 时，
  练习栏只有 440 到 630px 宽。唯一的那条 `max-width:860px` 规则从来没有生效过。
- 栏这么窄时：
  - 画面只有 300 乘 169，叠在上面的小胶囊挤成一团。
  - 调时间面板的两张边界卡片各只有约 174px，时间值、步进按钮和播放头按钮都折行。
  - 键盘提示在没有键盘的设备上白占一行，而按钮只有 36 乘 30。

第一次修复（v0.11.2）把断点改成按栏判断，但留下了两个问题：

- 在 1024 乘 700 下打开调时间面板时，句子、面板（379px）和卡片（264px）仍比栏多出 147px，所以滚动容器要滚动。
- 只要面板打开、栏高又不到 1000px，画面就一律被隐藏。这包括所有 iPad，也包括 900px 高的桌面窗口。

另外，右侧字幕栏里的跟随开关也伸出了 260px 宽的字幕栏。

这两次修复测量时用的视口尺寸，都没有扣掉 Safari 自己占用的界面。真实 iPad 上的 Safari 要从高度里扣掉状态栏和工具栏：
紧凑标签布局约 74px，单独标签栏约 110px（后者是新版 iPadOS 的默认设置）。所以横屏时的可见尺寸是：

- iPad mini：1133 乘 670 或 634，不是 1133 乘 744。
- iPad Air 11 寸：1180 乘 746 或 710。
- iPad Pro 11 寸：1194 乘 760 或 724。
- iPad Pro 13 寸：1366 乘 950 或 914。

在调时间面板收起、画面在播放、句子是两行英文加一行中文时，画面（180px）、句子和卡片（264px，触屏 230px）需要的高度比栏多出：

- 1133 乘 634 下最多 74px（触屏 40px）；
- 1133 乘 670 下 49px；
- 1180 乘 710 下 25px；
- 1194 乘 724 下 17px。

所以滚动容器要滚动，而这个视图本来不该用到滚动。音频文件、调时间面板打开时（画面本来就会让位）和更大的 iPad 都没有溢出。

## Decision

**练习栏是一个尺寸容器，凡是关于栏内内容的规则，都按这一栏自己的尺寸判断。** 练习栏和右侧字幕栏所在的那一行是一个宽度容器，
只用于字幕栏的那一条规则。

- **两个命名容器。**
  - `.dsh-lingualab-practice` 是 `container:ll-practice/size`。它有确定的尺寸（它是固定高度那一行里的 flex 子项），
    所以尺寸隔离没有代价。
  - `.dsh-lingualab-body` 是 `container:ll-body/inline-size`。
  - 字幕栏变窄到 260px 的规则按 `ll-body` 判断，其余规则按 `ll-practice` 判断。
  - 只有浏览层和减弱动效还用媒体查询，因为它们针对的是窗口。
  - 第三个容器 `ll-video` 是画面的舞台，只在画面占用剩余空间时使用（见下面的调时间模式）。
- **尺寸查询量的是内容盒。** 这一栏左右各有 24px 内边距、底部 20px，所以样式表里的每个数都是栏宽减 48、栏高减 20。
  核对阈值时用的桌面窗口（栏约 765 乘 851，按这个口径是 717 乘 831），在调时间面板收起时不会触发任何一条宽度或高度规则。
- **播放卡片上方的部分自己滚动，卡片始终不动。**
  - 卡片以上的内容都放在 `.dsh-lingualab-practice-main` 里，它是一个 flex 列，也是唯一的滚动容器。
  - 句子是 `flex:1 0 auto`，永远不会缩到比文字还矮。
  - 画面、句子和调时间面板放不下时，这一部分滚动，不会再互相重叠。
  - 卡片留在它下面，始终够得着。
- **高度不够时分几步收紧，滚动是最后手段，不是常态。** 内容高度不到 700px 时：
  - 当前句前后的两句先去掉。
  - 画面高度限制为栏高的 30%（以前是窗口高的 42%，那个上限不随栏变化）。
  - 舞台减少一些内边距。

  画面的宽度取三者中最小的：它在栏里的份额、720px、这个高度上限按 16:9 换算出的宽度。所以加上限只会让画面变小，形状不变。
- **正在播放的画面会给句子和卡片让位，调时间面板收起时也一样。** 句子是文字，卡片是播放的手段，所以整个页面里只有画面有空间可让。
  - 播放中的画面舞台（`is-shown.has-screen`）用画面原本的大小作 `flex-basis`，这个大小由栏本身算出：取画面所占宽度份额、720px、
    高度上限三者中最小的，换算成高度。份额和上限是变量，舞台和画面都读取它们，所以这些数字仍然只写在一处。舞台还带
    `flex-shrink:1` 和 `min-height:0`。
  - 舞台和调时间时的那个一样，是尺寸容器（`ll-video`）。画面是舞台给出的空间里能放下的最大 16:9 区域：宽度取份额、720px 与
    `100cqh * 16 / 9` 三者中最小的；没有 300px 的下限，也没有自己的高度上限。
  - 句子舞台是 `flex:1 0 auto`，卡片是 `flex:none`，所以只有画面能缩小，滚动容器又回到最后手段的位置。
  - 空间足够画面原来的大小时，舞台就和原来一样大：基准值就是原来的画面高度；舞台写了 `box-sizing:content-box`，
    所以不管宿主怎么设置，内边距都在基准值之外。凡是原本放得下的布局都不变。
  - 剩余空间不到 120px 时，和调时间模式一样，由同一个测量把舞台收起：`usePictureRoom` 现在只要画面在「显示」状态下播放就运行
    （以前只在面板打开时运行），去掉舞台的规则也不再要求 `is-timing`。
  - 仍然只在调时间时生效的，是让位后句子舞台的 `flex:1 1 auto`：面板收起时，长句子绝不能缩到比文字还矮。
  - 画面不到 160px 时，不画画面上的小胶囊（本地文件、流畅版），规则是 `ll-video (max-height:159px)`。这是对舞台高度的唯一一条查询，
    它只决定画面上画什么，从不决定画面画不画。胶囊大约需要这么多空间才不会互相挤到，231 乘 130 的截图就是这种情况。
- **代替画面的卡片分几步让位，每一步靠试出来。** 卡片由文字和按钮组成，高度取决于是哪一张卡片、带了什么内容（流畅版的提议、
  用户自己的文件）。普通的准备卡是 249px（高栏里是 342px），而 1133 乘 634 的栏只给它留 96px，所以没法像画面那样由栏算出一个基准值。
  `useCardFit`（放在页面切片里；挑选步骤和类名的逻辑是 `card-fit.ts` 里的纯函数）给滚动容器加一个类，从完整的卡片一直试到什么都不画，
  留下第一个让滚动容器不再需要滚动的步骤（`scrollHeight` 不大于 `clientHeight`，按整像素比较）：
  - 完整的卡片：不加类，就是样式表本来的样子，所以放得下的卡片和以前画得一模一样；
  - `is-card-compact`：收紧卡片（内边距 12px，间距 6px，图标 28px）；
  - `is-card-lean`：去掉次要部分（图标、解释性的那句话、备注、流畅版的提议和用户自己的文件），只留卡片要说的内容和该按的按钮，
    正文最多两行（约 125 到 170px）；
  - `is-card-line`：不换行的一行，包括标题、卡片针对的对象（文件，或者进度条加百分比）和按钮，放不下的地方用省略号截断
    （44px；触屏上按钮是 44px，所以是 58px）；
  - `is-card-hidden`：整个舞台都不画，和被挤掉的画面一样。

  这种逐步试的做法有几个要点：
  - 每次都从完整的卡片开始试，所以结果只取决于空间和卡片，与上一步无关。不需要像画面那样加滞回区间（画面需要，是因为它测量的
    正是自己的尺寸）：沿着某条边拖动改变栏的大小时，两个方向上都在同一个高度换步。
  - 类名设在滚动容器上，React 从不给这个元素写 class，所以这个 hook 没有状态，也不引起重新渲染。试的过程是同步的，在绘制之前完成，
    所以画出来的只有最终结果。
  - 哪一步都放不下时，说明太高的是句子或调时间面板，藏起卡片也没用，所以保留一行，让准备视频的入口留在屏幕上。
  - `VideoStage` 给装着卡片的舞台加上 `has-card`，hook 靠它找到卡片（样式表在隐藏那一步也靠它），所以各个 widget 不需要知道页面的存在。
  - 调时间面板打开时卡片不画，也就不测量。
  - 触屏在每一步都保留 44px 的按钮，因为那是 `min-height`，没有哪一步会改它。
- **调整时间是一种模式。** 调时间面板在页面上期间（里面有句子；退出时还会多留一会儿），页面给练习栏加上 `is-timing`。这里有意用类名，
  而不是对面板用 `:has()`：页面里只有一个「在场」状态，由它同时决定练习栏和面板，测试不需要布局引擎就能看到它。只有布局跟着这个
  在场状态变，行为（按键、舞台上的按钮）跟着会话变。除了句子、面板和播放句子的控件，其余一律退后：
  - 播放卡片折叠成进度条加一行「变速 | 上一句、播放、下一句」，约 124px，以前是 264px。其余的按钮、按键提示和打开着的菜单都用
    类名隐藏，不卸载，所以面板一关，全部原样回来。变速按钮带 `is-speed`，标明它是留下的那一个。这一行在任何宽度下都是三列网格，
    因为窄栏里有一条规则会把卡片两侧拆成一串可以折行的元素，不改成网格的话，变速按钮会被挤到第二行。
  - 当前句前后的两句去掉，句子也不再被拉伸去占空间，所以它只有文字那么高。
  - 正在播放的画面占用剩下的空间。它的舞台是一个尺寸容器（`ll-video`），`flex:1 1 0`；画面是能放下的、与视频本身同比例的最大区域，
    用的是大画面状态的做法：宽度取容器宽度、720px、容器高度乘比例三者中最小的。比例是 `--ll-video-ratio`，显示中的画面现在也带
    这个变量；画面平时的框仍是 16:9。调时间期间，代替画面的卡片或小标签（没有 `has-screen` 的舞台）不画，画面上的小胶囊
    （本地文件、流畅版）也不画：它们放不进小画面，对移动边界也没有帮助。
  - 画面分到的空间不到 120px 时不画，它的舞台也不保留：
    - 子元素不画时，尺寸容器没法缩小自己。原来用容器查询把画面藏起来，舞台那个 `flex:1` 的区域却留了下来，两行句子上方空出约
      80px。所以只有这一个决定要靠测量。
    - `usePictureRoom`（放在页面切片里，因为它涉及三个部件）用不随画面收起而变化的量，算出画面能分到的空间：滚动容器去掉内边距后的
      高度，减去句子舞台需要的高度（按它的各行、行间距和内边距测量，不按它自己的尺寸测量，因为它的尺寸正是被这个状态拉伸的），
      再减去调时间横栏，再减去画面舞台自己的内边距。
    - 绝不读画面自己的尺寸，否则会自己追自己：收起后空间出现，显示后空间又没了。
    - 画面从 120px 起才画，让开之后要等空间回到 128px 才重新显示，所以把窗口拖到临界尺寸附近时也不会闪烁。
    - 页面给练习栏加上 `is-picture-squeezed`，样式表把画面舞台藏起来（`display:none`），句子舞台改成 `flex:1 1 auto`。舞台本来就把
      内容居中，所以句子落在这块空间的正中，看上去是句子周围留有余白，而不是上方空了一块。`<video>` 照常播放，和音频文件一样。
    - 测量在首次绘制之前执行，监听滚动容器、舞台的各行（每换一句，这些行都会整体替换，所以每次变化都重建监听的集合）和调时间横栏
      （面板从第一帧起就是完整高度，所以测量结果一出来就是最终值）。只有在面板里有句子、而且画面在播放时，测量才开启。没有
      `ResizeObserver` 时一律当作放得下。
    - 原来 119px 的那条容器查询删掉了：如果再有一条对临界值有自己判断的规则，两者只要差一个取整的像素，空区域就会在它们不一致的
      地方回来。
  - 大画面保持原样。大画面本来就占用剩余空间（它就是整个舞台，它的句子也不在舞台上占空间），而且有 160px 的下限，
    所以永远碰不到 120px 那条规则。把它藏起来，主动选择大画面的用户就会面对一个空空的舞台。
- **小空间里，调时间面板只用一种紧凑布局。** 判断条件是 `(max-width:600px) or (max-height:760px)`，也就是栏宽不超过 648px
  或栏高不超过 780px。
  - 开头和结尾各占一行：标签，下面是它移动了多少；时间值（18px）；两个 50 毫秒的步进按钮；播放头按钮，高 44px（触屏上是 52px，
    步进按钮是 44px）。
  - 底部一行：还原、取消，以及占满剩余宽度的保存。
  - 迷你时间轴和按键提示去掉。
  - 文字较长的按钮同时渲染长文字和短文字（`timingAtPlayheadShort`、`timingSaveShort`），由样式表挑一种显示；完整文字仍留作
    `aria-label` 和 `title`。
  - 一行放不下四个部分时，播放头按钮换到这一行的第二行：内容宽度不到 372px 时，触屏上不到 392px 时。这一行大约需要 341px
    （触屏 365px），阈值留了 24px 的余量，给时间值里多出的小时位（`1:05:12.345`）。
  - 又宽又高的栏仍然是两张卡片加迷你时间轴。
  - 这种布局取代了 v0.11.2 里分两步叠放卡片的做法（520px 与 440px），所以窄栏只有一种布局，而不是三种。面板高约 205px
    （触屏 233px），以前是 379px。
- **窄宽度。** 不到 600px 时，画面和各种卡片占满整栏；流畅版的小胶囊换行显示（触屏上没有悬停提示，被截掉的字就读不到了）；
  卡片的按钮排成居中的几行。
- **字幕栏宽 260px 时，跟随开关显示为「跟随」。** 两种文字都渲染，由样式表挑一种；完整的文字仍是复选框的 `aria-label`。这一行里
  栏头的内边距、间距和分段控件都收紧了一点，所以带三位数计数的分段控件和开关都放得下，没有任何东西伸出字幕栏的边。
- **触屏按指针类型判断，不按宽度。** `(hover:none) and (pointer:coarse)` 时：
  - 去掉键盘提示：所有 `kbd`、播放器下面的按键行、调时间面板里的按键、快捷键列表、编辑器与选择器的提示。
  - 播放卡片上的每个按钮（包括上一句和下一句）、调时间面板的步进按钮、播放头按钮、「取消」和「保存」都是 44px 高。
    卡片的按钮每多折一行，卡片就高约 12px。
  - 画面上的小胶囊保持原来的大小，触控区靠一圈看不见的外边距扩到 44px：如果真做成 44px 高，一个胶囊就要盖住 169px 高画面的四分之一。

## Alternatives considered

- **多加几个视口断点。** 侧栏和字幕栏的存在，让窗口宽度很难用来估计栏宽，问题正出在这里；断点设在 1100，对一种侧栏状态是对的，
  对另一种就是错的。
- **用 resize observer 设置类名。** 在不支持容器查询的环境里也能用，但那是一段要和样式表保持同步的代码，在布局之后才执行，
  还会先闪一下错误的布局。当前的 Safari、Chrome 和 Firefox 都支持容器查询。页面为布局设置的类名 `is-timing`，是页面本来就有的
  一个状态，不是测量结果。例外是 `is-picture-squeezed`，它处理的是容器查询做不到的那件事（把自己正在测量的区域收起来）；
  它是唯一的测量，在绘制之前执行，除了这一个数，其余的数仍然都写在样式表里。
- **整栏滚动，连卡片一起。** 那样一来，栏恰好太矮时播放键就在屏幕外，这正是用户抱怨的地方；而改成吸底的卡片，又要加一层背景
  去遮住从它下面滚过的内容。
- **按比例缩小画面和句子。** 字号跟着栏高走，会让句子在 iPad 用户最需要它大的地方变小，缩小的画面也仍然要占空间。
- **面板打开、栏又矮时隐藏画面。** 这是 v0.11.2 的做法，它在所有 iPad 和 900px 高的桌面窗口里都把画面藏了，而这些地方其实
  放得下一个小画面。现在画面占用的是剩余空间，只有剩余空间不到 120px 时才让开。
- **只折叠面板，不动播放卡片。** 卡片还是 264px 的话，面板没法降到约 230px 以下，画面在 1024 乘 700 下也回不来；而调时间期间，
  循环、跟读、画面和菜单都不是用户会去用的东西，所以可以让它们先退后。
- **只靠画面舞台自己的容器查询来藏画面（v0.11.3）。** 这样会留下舞台的区域，里面什么也没画。把舞台改成 `flex:0 0 auto` 倒是能
  收起来，但画面的大小正是由舞台决定的，舞台和画面会互相决定对方的大小；测量只用不会变的量，打破了这个循环。
- **窄栏里把开头与结尾两张卡片叠起来（v0.11.2）。** 两张叠放的卡片各占两行，一共 232px，而栏总共只有 631px；改成每个边界一行，
  只要 96px，不到一半，而且同一种布局同时适用于又矮又宽的栏和又窄又高的栏。
- **由页面把测量出的空间写成变量，用来决定画面大小。** 这不需要新的 CSS 思路，但测量在布局之后才执行，每当句子多出一行，就会先画出
  一帧滚动容器在滚动的样子，再换成较小的画面。容器能在同一次布局里就定好画面的大小；测量只留给容器做不了的那一个决定。
- **让舞台字号跟着栏高变化。** 不需要：画面让位之后，句子和卡片在测过的每个尺寸下都放得下；字号里加一个高度项，只会在画面还能
  吸收空间不足的地方改变文字大小。这也就是上面「按比例缩小」的做法，会让句子在用户最需要它大的地方变小。
- **矮一些的栏里收紧卡片和舞台的内边距。** 大约能省出 24px，让画面在一个尺寸（1133 乘 634、用指针、侧栏展开、两行）下保住，
  代价是多一个阈值，而这个阈值会改变本篇中现在放得下的那些尺寸。没有采用；那个尺寸下改为让画面让开。
- **栏一矮就隐藏画面。** 那是 v0.11.2 在调时间时犯的错；130 到 200px 的画面，正是 iPad 有空间放下的。
- **让卡片像画面那样靠 flex 收缩。** flex 基准值需要一个起始尺寸，而栏给不出卡片的尺寸（卡片多高由内容决定），所以舞台会缩到
  比内容还矮，把按钮截掉；画面能缩小，是因为它是比例已知的区域，卡片不是。
- **栏一矮就像藏画面那样藏卡片。** 卡片是请求准备视频的唯一入口，而画面是栏里可以没有的东西；藏起卡片就等于去掉那个按钮，
  所以藏卡片是最后一步。
- **用容器查询按栏高选择步骤。** 句子有一到三行（每行约 40px），播放卡片又会按宽度换行，所以栏高很难说明卡片有多少空间。
  逐步试的办法直接读取实际空间。

  - 阈值的来源：把真实的组件和真实的样式表渲染成标记，在浏览器里按每个尺寸读回高度。尺寸包括 iPad 竖屏 820 乘 1180 与
    744 乘 1133，横屏 1180 乘 760 与 1024 乘 700，每个都配宿主侧栏 56、224、280px，外加桌面 1440 乘 900；触屏和非触屏各测一遍。

    滚动条按 iPad 的样子用悬浮式，触屏时套用样式表里的触屏那一段。

- **在 1024 乘 700、宿主侧栏展开时调时间，放得下。** 栏是 483 乘 651。
  - 句子只有一行时：卡片 126px，句子 135px，面板 205px（触屏 233px），画面 269 乘 151（触屏 219 乘 123），不用滚动。
  - 句子有两行时：句子 214px，画面放不下，就不画，句子上方的那块区域收起，句子舞台占用剩下的约 80px，并把句子居中放在里面，
    同样不用滚动。
  - 以前这里会在句子上方留一块空白区域，因为画面容器在布局完成之前无法知道还剩多少空间；现在由测量来得出。
- **布局在每个方向上只变化一次，动的只有卡片的外观。**
  - 调时间面板在设置 `is-timing` 的那次提交里就占满它的高度，一直保持到去掉 `is-timing` 的那次提交；淡入和上移的是面板里的卡片。
  - 所以第一帧里画面就落在最终大小上，或者被收起；`usePictureRoom` 只根据最终高度判断一次（画面低于 120px 时隐藏一次，
    要等到 128px 才回来）。
  - v0.11.5 之前，面板是从无到有地长出一个网格行：画面先跳到能放下的最大尺寸，在 240 毫秒里缩小，旁边是两行句子时最后还会被收起；
    关闭时平时的布局立刻回来，而那一行还在收缩，布局要变两次。
  - 现在关闭按相反的顺序进行：卡片淡出，练习栏仍留在调时间模式里；等退出结束，练习栏在卸载面板的同一次提交里离开这个模式。
  - 两者都跟随页面里的同一个 `usePresence`（面板以属性接收 `mounted` 和 `shown`，页面从面板所在的切片读取退出时长），
    所以两个计时器不会相差一帧。
  - 按键和舞台上的按钮跟随会话，而会话立刻结束：卡片淡出期间，按键已经交还给页面，面板是 inert 的。

  超出的部分交给滚动容器。
- **播放卡片上的按钮，用指针时是 32px，用手指时是 44px。** 如果给鼠标也做成 44px，矮栏里本来就最高的这张卡片会再多出两行。
