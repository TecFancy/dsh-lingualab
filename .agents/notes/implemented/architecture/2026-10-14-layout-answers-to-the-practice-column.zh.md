# Agent Note: 布局看练习栏自己的大小，不看窗口

Status: implemented

## Problem

练习页在一栏里叠了四样东西：画面、句子、调时间面板和播放卡片。它是照桌面窗口排的，到了 iPad 上有两处坏掉。

第一处是高度。在 1180 乘 760（横屏的 iPad）下，这一栏只有 711px 高，调时间面板打开时，画面（208px）、面板（350px）和卡片
（264px）加起来要 822px，句子还一点没分到。句子是唯一能伸缩的一项，被挤到 40px，而它的文字至少要 140px，于是压在画面和面板
上，卡片落到屏幕下面，播放键够不着。在 1024 乘 700 下，面板收起来时句子也放不下。

第二处是断点问的问题不对。它们是视口媒体查询，可宿主的侧栏占 56px 或 280px，右侧字幕栏又占掉剩下的约三分之一，所以窗口有
1024 或 1180px 时练习栏只有 440 到 630px。那条唯一的 `max-width:860px` 规则从来没生效过。栏这么窄时，画面只有 300 乘 169，
叠在上面的小胶囊挤成一团；调时间面板的两张边缘卡各只有约 174px，时间值、步进按钮和播放位置按钮都折行；键盘提示在没有键盘的
设备上白占一行，而按钮只有 36 乘 30。

## Decision

**练习栏是一个尺寸容器，关于栏内内容的规则都问这一栏自己。** 它与右侧字幕栏同处的那一行是一个宽度容器，只管字幕栏的那一条规则。

- **两个命名容器。** `.dsh-lingualab-practice` 是 `container:ll-practice/size`（它有确定的尺寸：它是固定高度那一行里的 flex 子项，
  所以尺寸隔离不花代价），`.dsh-lingualab-body` 是 `container:ll-body/inline-size`。字幕栏变窄到 260px 的规则问 `ll-body`，
  其余的问 `ll-practice`。只有浏览层和减弱动效还用媒体查询，因为它们说的是窗口。
- **尺寸查询量的是内容盒。** 这一栏左右各有 24px 内边距、底部 20px，所以样式表里每个数都是栏宽减 48、栏高减 20。用来核对
  阈值的那个桌面（栏约 765 乘 851，按这个口径是 717 乘 831）在调时间面板收起时，一条宽度或高度规则都不触发。
- **播放卡片上面那一段自己滚动，卡片永远不动。** 卡片以上的内容都放在 `.dsh-lingualab-practice-main` 里，它是一个 flex 列，也是
  唯一的滚动容器；句子是 `flex:1 0 auto`，永远不会缩到文字以下。画面、句子和调时间面板放不下时，这一段滚动，不可能再重叠。
  卡片留在它下面，够得着。
- **矮的时候分几步收紧，滚动是最后手段，而不是常态。** 内容高度不到 700px 时，句子两侧的上下句先去掉，画面限制为栏高的
  30%（以前是窗口高的 42%，那个上限不跟着栏走），舞台和调时间面板让出一些内边距，面板还去掉迷你时间轴。画面的宽度取
  它在栏里的份额、720px、以及这个上限按 16:9 允许的宽度三者中最小的，所以加上限会让它变小，形状不变。调时间面板打开时，
  相邻的上下句一律去掉，高度不到 1000px 时显示着的画面让开位置（它照常播放，只是 `<video>` 不画出来，音频文件本来就是这样）；
  再高就缩成一条放得下。大画面就是整个舞台，留在原处，设了 160px 的下限。
- **窄宽度。** 不到 600px 时，画面和各种卡片占满整栏，流畅版的小胶囊换行（触屏上没有悬停提示，截掉的字就读不到了），卡片的
  按钮排成居中的几行。不到 520px 时，开头与结尾两张边缘卡上下叠放，每张分两行，播放位置按钮挨着时间值；不到 440px 时，
  播放位置按钮单独占一行。
- **触屏看的是指针，不是宽度。** `(hover:none) and (pointer:coarse)` 去掉键盘提示（所有 `kbd`、播放器下面的按键行、调时间面板里的
  按键、快捷键列表、编辑器与选择器的提示），并让调时间面板的步进按钮、「设为播放位置」、「取消」和「保存到字幕文件」都是 44px 高。
  画面上的小胶囊保持原来的大小，触控区靠一圈看不见的外边距扩到 44px：真做成 44px 高，一个胶囊就要盖住 169px 高画面的四分之一。

## Alternatives considered

- **多加几个视口断点。** 侧栏和字幕栏让窗口宽度成了栏宽的一个很差的估计，错就错在这里；断点设在 1100，对一种侧栏状态是对的，对
  另一种就是错的。
- **用 resize observer 去设类名。** 在不支持容器查询的地方它也能用，但那是一段要和样式表保持同步的代码，在布局之后才跑，
  还会闪一下错的布局。容器查询在当前的 Safari、Chrome 和 Firefox 里都有。
- **整栏滚动，连卡片一起。** 那样栏恰好太矮的时候，播放键就在屏幕外，这正是被投诉的地方；而吸底的卡片又要有一层背景去盖住
  从它下面滚过的内容。
- **把画面和句子按比例缩小。** 跟着栏高走的字号，会让句子在 iPad 读者最需要它大的地方变小，缩小的画面也还是要占地方。
- **栏一矮就隐藏画面。** 调时间面板收起时，矮栏仍然放得下一幅画面加一行句子；只有调时间面板把地方占满，所以只在那时让画面让开。

## Settled details

- **量出来的，不是猜的。** 阈值来自把真实的组件和真实的样式表渲染成标记，在浏览器里按每个尺寸（iPad 竖屏 820 乘 1180 与
  744 乘 1133，横屏 1180 乘 760 与 1024 乘 700，每个都配宿主侧栏 56、224、280px，外加桌面 1440 乘 900），触屏和非触屏各一遍，
  再读回高度。没有在真机上量：Safari 自己的工具栏要占高度，上面的数字没算进去，所以真的 iPad 会矮一点，更早碰到滚动。
- **长句子仍然会滚动。** 两行英文加一行中文，舞台要约 250px；在 1180 乘 760、画面显示、调时间面板收起时，句子只有一行则画面
  和句子一起放得下，句子长则溢出约 50px。这一点交给滚动容器。
- **播放卡片上 32px 的按钮仍是 32px。** 做成 44px 会给本来就是矮栏里最高的那张卡片添两行，所以留给以后重新设计卡片时再改。
