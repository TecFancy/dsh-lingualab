# Agent Note: 剧集素材放在工作区里，绝不进 git

Status: implemented

## Problem

- 素材存放在家里的 NAS 上，宿主运行在云服务器上，两者通过 Tailscale 连接，不在同一个局域网。
  如果每集都从 NAS 实时读取，整个学习过程中的每一次播放都要占用家里的上行带宽。
- 媒体库的体积也远超任何适合放进 git 仓库的东西：一季音频就有两三个 G，视频有几十个 G。
- 同时，打开这一页就要能直接播放，前面不能再加一步下载。把这件事搬进 dsh，全部意义就在于「打开就能练」。

## Decision

剧集按集手动拷进工作区，放在 `notes/learning/english/media/<剧集>/` 下。面板通过宿主自己的路由从磁盘读取并提供这些文件。
音频目录里有一个自己的 `.gitignore`，所以素材对插件可见，对仓库不可见：markdown、字幕和清单照常提交，音频不提交。

## Alternatives considered

- **由宿主从 NAS 转发。** 不需要本地副本，但每拖动一次进度条，都要经过家里的上行带宽发一次请求，
  而精听时最常做的动作就是拖动。不采用。
- **一次性把整个库拷上来。** 省掉每集手动拷贝那一步，代价是在剩余空间不到三十 G 的磁盘上占用几个 G，
  而其中大部分剧集几个月内都不会去练。
- **把音频提交进 git。** 仓库每集要增加二十兆，再加上视频就是几十个 G。直接不采用。

## Consequences

素材目录可以是空的，这是正常状态，不是故障，所以页面显示的是路径和提示，而不是报错。视频文件留在 NAS 上，
用外部播放器观看，这也是第一版不内嵌视频的原因。
