# Agent Note: 剧集素材留在工作区，绝不进 git

Status: implemented

## Problem

素材在家里的 NAS 上，宿主跑在云服务器上，两头靠 Tailscale 相连，不是同一个局域网。每集都从
NAS 现拉，意味着整个学习过程里每一次播放都压在家里的上行带宽上。而这个媒体库也远大于任何该进
git 仓库的东西：一季音频就是两三个 G，视频是几十个 G。

同时，打开这一页就得能直接播，前面不能加一步下载。把这件事搬进 dsh 的全部意义就在于「打开即练」。

## Decision

剧集一集一集手动拷进工作区，放在 `notes/learning/english/media/<剧集>/` 下。面板通过宿主自己的
路由从磁盘读它们。音频目录自带一条 `.gitignore`，于是素材对插件可见、对仓库不可见：markdown、
字幕和清单照常入库，音频不入。

## Alternatives considered

- **由宿主从 NAS 转发。** 不用本地副本，但每一次拖动进度条都变成一次跨家庭上行的请求，而精听过程
  里最多的动作就是拖动。否掉。
- **一次性全量拷上来。** 省掉每集那一步，代价是在只剩不到三十 G 的盘上占几个 G，而其中大部分剧集
  几个月内不会碰。
- **把音频放进 git。** 仓库每集长二十兆，加上视频就是几十个 G。直接否掉。

## Consequences

素材目录可以是空的，这是正常状态而不是故障，所以页面显示的是路径和提示，而不是报错。视频文件留在
NAS 上，用外部播放器看，这也是第一版不做内嵌视频的原因。
