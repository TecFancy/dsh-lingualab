# Agent Note: 入口挪到启动台，左栏那一行随之撤掉

状态：已落地

## Problem

这一页原来在左栏占一行，order 是 40，排在插件、自动化任务、应用、技能下面。左栏当时一共五行，
而每多一个带页面的插件就再多一行：不管用户会不会专门导航到这一页，左栏都要为它占用宽度。

「应用」页本来就是放这类页面的地方：一个列出用户会打开的东西的启动台。语言实验室正是其中之一，
而且它是那里唯一一个另外还有自己入口的条目。

## Decision

撤掉 `sidebar.panellist` 那段注册，`main` 继续挂在 `lingualab` 这个 key 上。入口改成「应用」页上
的一张卡片：`dsh-apps-panel` 的注册表里有一条，`panel` 字段写着这个 key，点卡片调用的是
`ctx.layout.selectPanel('lingualab')`，和左栏那一行调用的完全相同。

`retainMainPanels` 会保留每个归到 `main` 条目下的 key，所以撤掉那一行之后，选中的面板不会退回到会话。

## Alternatives considered

- **两个入口都保留。** 同一个页面有两个入口。左栏还要继续为一行占用宽度，而那一行唯一的作用就是链接到
  启动台已经列出的页面。
- **加一个配置开关，在两者之间选。** 前端（client）得先读到插件配置，才能决定要不要注册那一行，
  于是多一次往返，那一行也会晚一点出现。换来的只是一个没人遇到的场景：这个插件都装在有启动台的环境里。
- **让启动台向这个插件请求一张卡片。** 那是一个只有一个调用方的跨插件扩展点，而且它把条目挪进了代码，
  而启动台注册表的用意，正是让主人不改 bundle 就能修改清单。

## Consequences

- 左栏图标（`src/client/icons/rail.tsx`）与文案里的 `panel` 键都不再使用，已删掉。
- 这个插件从此必须有 `dsh-apps-panel` 才能进入。在没有它的 profile 里，页面虽然注册了，却没有入口；
  README 的「当前状态」一节写明了这一点。
- `lingualab` 成了两个互不 import 的包之间的约定。这个字符串由本插件负责，启动台那一侧的对应部分
  写在 `scripts/check-host.mjs` 里。
