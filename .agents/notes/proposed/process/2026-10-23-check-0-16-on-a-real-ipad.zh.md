# Agent Note: 在真 iPad 上检查 0.16.0

Status: proposed

## Problem

这个插件主要在 iPad 上用，但从 0.12.0 起，为 iPad 做的每一项功能都是在电脑浏览器里量的：用的是 Chrome 的引擎，
视口设成 iPad 的尺寸，触屏靠模拟，字体不是 SF Pro，没有 Safari 的工具栏，也没有真的手指。每篇 note 都各自写明了这一点，
没验的项现在散在八篇 note 里：

- [布局按练习栏自己的大小来定，不按窗口](../../implemented/architecture/2026-10-14-layout-answers-to-the-practice-column.zh.md)
- [把跟读做成复读机完整的核心闭环](../../implemented/feature/2026-10-14-shadowing-as-the-repeater-loop.zh.md)
- [调整时间时切到上一句或下一句](../../implemented/feature/2026-10-12-step-to-neighbour-while-retiming.zh.md)
- [右栏可以收起](../../implemented/feature/2026-10-21-collapse-the-side-column.zh.md)
- [在进度条上精细拖动](../../implemented/feature/2026-10-21-fine-scrubbing-on-the-progress-bar.zh.md)
- [练习栏窄时，侧栏浮在舞台上并默认收起](../../implemented/feature/2026-10-21-side-column-over-a-narrow-stage.zh.md)
- [给右栏的展开收起加动画，并重排顶栏](../../implemented/feature/2026-10-21-animate-the-side-column-and-regroup-the-top-bar.zh.md)
- [点一下就选好倍速](../../implemented/feature/2026-10-23-pick-a-speed-in-one-tap.zh.md)

散在各篇 note 里的清单不会有人去做。另外还有两个后续计划在等它：在舞台上拖动定位句子，要看舞台上的触屏手感；
按静音结束跟读停顿，要看录音在 Safari 里的表现。

## Proposal

**用真 iPad 对着部署好的 0.16.0，按下面的清单过一遍。** 用户在 2026-10-23 晚上来做。

怎么做：

- 在 Safari 里打开部署好的站点，不是本机的那个。在结果的开头写下 iPad 的型号和 iPadOS 版本。
- 每一项都写了要做什么、怎样算通过。通过就打勾，不通过就在旁边写下看到了什么；看得见的问题，拍张照或录一段屏就够了。
- 过的时候不修。结果交回给 agent，由它对照每一项所属的 note 逐个修。
- 过完之后，每篇相关 note 里「还没在设备上验过」的那句话换成实际看到的结果，这篇 note 带着结果挪到 `implemented/`。

**1. 开始之前**

- [ ] 站点是 HTTPS 打开的。不是的话 Safari 会拒绝麦克风，所有录音相关的项都会因此失败。
- [ ] 页面是 0.16.0：点倍速按钮弹出选择框，而不是升一档。

**2. 布局（横屏和竖屏，宿主侧栏收窄和展开各一次）**

- [ ] 横屏，宿主侧栏先窄后宽：练习页整体不滚动，句子看得清，播放卡片上的按钮不重叠。
- [ ] 竖屏同样检查一遍。
- [ ] 横屏、宿主侧栏展开时打开调整时间的面板（「更多」里的「调整这一句的开头和结尾」）：面板、句子和播放卡片都放得下，不用滚动。
- [ ] 长句子在 SF Pro 下换行正常，没有被截掉的词。
- [ ] 竖屏时的顶栏：返回、标题、「右栏」组和「进度与设置」组都放得下，两组之间的竖线看得见，每个按钮都容易用手指点中。

**3. 右栏**

- [ ] 横屏时，点顶栏的开关，右栏在五分之一秒里滑出、滑回，舞台和画面跟着变，不卡顿。如果卡，记下卡到什么程度：退路是只做淡入淡出。
- [ ] 竖屏（或横屏且宿主侧栏展开）时，展开的右栏是盖在舞台上的抽屉，带一层变暗的遮罩。点遮罩，抽屉连同遮罩一起滑出；
  整个过程中舞台保持宽布局。
- [ ] 把 iPad 在竖屏和横屏之间转动，右栏在抽屉和排在舞台旁边之间切换。
- [ ] 用开关收起右栏后刷新页面，右栏仍然收起。

**4. 倍速**

- [ ] 倍速按钮在上方弹出选择框；每个档位都容易点中，不会碰到旁边的档位。
- [ ] 点一个档位，切到这个倍速并关上选择框；点别的地方，选择框关上，倍速不变。
- [ ] 调整时间的面板开着时，倍速按钮仍然能弹出选择框。

**5. 进度条**

- [ ] 沿着进度条拖动滑块：滑块跟着手指走。拖动时把手指往上移开进度条：标签先显示半速，再显示四分之一，滑块走得更慢。
- [ ] 标签在手指旁边看得清，不会被手指挡住。
- [ ] 靠近屏幕底边拖动时，不会触发 iPad 自己的上滑手势（回主屏或切换应用）。
- [ ] 松手后从标签显示的时间开始播放。

**6. 调整时间的面板**

- [ ] 面板头部的两个按钮切到上一句和下一句。先改过一端再切，头部会短暂显示「已保存」，字幕文件里是新的时间。

**7. 跟读、录音和耳机**

- [ ] 打开「跟读」后，在「更多」里打开「录下我说的」，只询问一次麦克风权限；允许之后，跟读时能录下一遍。
- [ ] 「对比」先播这一句，再播录下的那遍，中间不用点。
- [ ] 麦克风停下之后，句子回放的音量正常（iOS 有时会让它变小）。
- [ ] 戴 AirPods：播放和暂停能传到页面，下一曲和上一曲切换句子。
- [ ] 锁屏界面：控件显示的是上一曲和下一曲，不是快退快进若干秒；说话停顿期间按钮显示暂停，在这时按下会结束跟读。

## Alternatives considered

- **让每篇 note 里的那句话留在原处。** 不用新建文件，但散在八处的几句话已经一个星期没人去做，也没法一次做完。
- **Playwright 里的 WebKit，或者云端真机服务。** WebKit 比 Chrome 接近一些，但没有真的手指、没有 Safari 的工具栏、
  没有 AirPods 和锁屏，而待验的正是这些。云端真机要把站点开放给它，而且同样没有耳机。
- **Mac 上的 iPad 模拟器。** 要有一台 Mac，而且麦克风的路径和真机不同，也没有 AirPods。
- **只检查最新的几项功能。** 快一些，但录音和耳机是最早留下、也是插件最核心的待验项。
