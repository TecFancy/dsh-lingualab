# Agent Note: 保留文件，让笔记的保存变安全

Status: proposed

## Problem

页面保存的东西都是素材库里的普通文件：每集一个 `notes.md` 记收藏的句子（备注、单词和评级），媒体库根目录的
`.lingualab-progress.json` 记每集或每段听到哪里和五步勾选，还有字幕文件本身，调整时间的横栏会把改动写回去。
2026-10-12 提出的问题是：要不要用一个 SQLite 数据库替换它们。一个应用一旦要存记录、查记录、频繁写记录，数据库通常就是答案。

评估的结论是 SQLite 在这里不值它的代价，但也找到了 `notes.md` 写入方式上的两个真实弱点。两个结论当天都被采纳：文件保留，
「Decision」一节里的两处修复已经列入计划，还没有做。这篇 note 留着 SQLite 的评估，免得以后从头再想一遍。

## Assessment

SQLite 能带来的：

- **跨整个库的查询。** 现在整个库的复习队列是把每一集的 `notes.md` 都读出来再解析（`src/host/review.ts`）。
  有一张收藏句子的表，「所有还在练的句子」就是一条查询；每句的历史（每次评级和日期，也就是间隔重复的基础）也容易加。
- **原子、并发安全的写入。** `notes.md` 用 `writeFileSync` 原地重写（`src/host/notes.ts`），写到一半崩溃可能留下截断的文件；
  两个标签页保存同一集，后存的会覆盖先存的。SQLite 的事务和 WAL 模式两样都能处理。
- **能长大的结构。** 新字段（复习日期、来源段、标签）是加一列，而不是改一行用竖线分隔、还得让旧代码读得懂的格式。

它的代价：

- **agent 失去它的输入。** `notes.md` 不只是存储。方法里有两步（次日复习和周日复习）在会话里做，agent 读的就是这个文件；
  人也会打开它浏览或者手改收藏。换成数据库，就得提供导出，或者给 agent 一个工具，才能让这两个读者拿回现在有的东西，
  而导出又是同一份数据的第二个副本，要保持同步。
- **文件不再能随身带走。** 现在一个剧集文件夹是自包含的：拷到另一台机器，笔记跟着音频一起走。整个库一个数据库会把两者分开；
  每个剧集文件夹一个数据库，又丢掉了大部分查询上的好处。
- **host 半边多一个运行时依赖。** `lib/index.js` 是一个提交进仓库的单文件产物，没有原生模块。`better-sqlite3` 是原生模块，
  要针对 harness 跑的那个 Node 版本编译；内置的 `node:sqlite` 不用编译，但会把插件绑在较新的 Node 版本上，
  而且它的 API 有很长一段时间都标着实验性。
- **数据量很小。** 一集收藏几十句，一季几百句，把每个 `notes.md` 都解析一遍只要几毫秒。现在没有哪个功能是因为文件而慢的。

## Decision

**markdown 和 JSON 文件继续作为唯一的数据来源，不用 SQLite。** 评估找到的两个弱点是真实的，都在文件这一侧修：

- **笔记的写入是原子的。** 写 `notes.md` 改成和进度文件一样（`src/host/progress.ts`）：先写到旁边的临时文件，再改名盖掉旧文件。
  这样崩溃时留下的要么是旧文件、要么是新文件，不会是半个。
- **过时的笔记保存会被拒绝。** 页面记住它读到的 `notes.md` 内容的哈希，每次保存都带上，像调整时间的横栏对字幕文件做的那样
  （`src/host/timing.ts`）。如果这期间文件变了（另一个标签页、手改、agent），host 回一个「过时」的答复，不覆盖它；
  页面重新读取笔记并说明原因。保存成功时答复里带上新的哈希，所以同一个标签页连续保存不受影响。

每处修复都配测试，放在 `src/host/notes.test.ts` 和 `src/host/routes.test.ts`：写到一半失败时旧文件完好无损；带着旧哈希的保存不会动更新过的文件。

## Alternatives considered

- **SQLite 作为唯一的存储。** 查询和事务的好处全拿到，代价是 agent 的输入、手改和按文件夹携带，再加一个原生或绑版本的依赖。
  只要 agent 还直接读 `notes.md`，就不采用。
- **SQLite 为主，每次写入都导出 `notes.md`。** 两个读者都保住了，但数据有两份；人手改 `notes.md` 时，改的是会被覆盖的那一份。
- **SQLite 作为从文件派生的索引。** 启动时或文件变化时从各个 `notes.md` 重建，从不直接写它，删掉也没关系。它保住了 agent 的输入和文件夹的可携带性，
  所以哪天整个库的查询真的慢了，就该用这种形式。现在用不着。
- **每集一个 JSON 文件代替 markdown。** 比竖线格式好解析、好扩展，但人和 agent 都更难读，而用 markdown 本来就是为了好读。
- **保留文件，什么也不改。** 截断和两个标签页互相覆盖的风险都还在。

## When to revisit

- 加了间隔重复，要记下每一次复习的历史，一行已经放不下。
- 库大到读一遍所有 `notes.md` 来做整库复习明显变慢（先量一下，别凭感觉）。
- agent 有了查询页面数据的工具，不再需要读 `notes.md`。
- 不止一台设备经常写同一集，按文件合并成了问题。
