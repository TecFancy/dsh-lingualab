# Agent Note: 把跟读做成复读机完整的核心闭环

Status: proposed

## Problem

这个面板的用途，是替代实体复读机来练听力和口语。复读机做的是一个闭环：放一句，留出时间让你说，把你说的和原声对比，
再往下走。听的那一半大多已经有了：单句循环（`L`）、带次数的 A-B 循环、十档变速不变调，还有提前起播。说的那一半只做了第一步。

跟读现在的行为（`features/media-player/model/store.ts` 里的 `onTime`）：模式打开、又没开循环时，一句话播放期间英文是模糊的，
播完就停住，退回句首，同时设上 `revealed`，所以一停英文就揭开了。按播放再听一遍；切句会到下一句并开始播放。
由此有四个缺口，2026-10-14 对照 v0.11.5 核实过：

1. **没有录音。** 跟读那一步的提示（`stepTipShadow`）写着「开跟读，录一遍对比」，可源码里哪儿都没有录音。
   拿自己的声音和原声对比，正是人们买复读机的理由。
2. **揭晓和文案对不上。** `shadowHint` 和 README 都说「你先说，再按 R 揭晓」；store 却在停住时就揭开了，
   读者还没开口，答案已经在屏幕上。
3. **跟读和循环互斥。** 只有 `loopMode` 为 `none` 时才会停，次数也只给 A-B 循环用。复读机最基本的程序
  「每句放两遍，每遍后停一下让你复述，再到下一句」设不出来，所以每一句都要用手去点。
4. **没有实体按键。** 页面没有 Media Session 处理。iPad 不接键盘时，`Space`、方向键和 `R` 都不存在；
   耳机或 AirPods 上的按键对句子也不起作用。

v0.8 以来的版本都花在布局、视频、主题和调整时间上。每一项都是合理的配套工作，但都没有推动上面这个闭环。
这篇 note 定下之后衡量新东西的标尺：一项改动值得做，要么是增加了每分钟耳朵在听、嘴在说的时间，要么是让手离开屏幕。
文本是答案，不是材料。

## Proposal

分四块，按这个顺序做。每一块都能单独发布，读者不打开时，默认行为保持不变。

1. **把跟读做成按句执行的程序。** 跟读模式下，「更多」菜单里给三个设置：每句播几遍（1、2 或 3），每遍之后留出的复述停顿
   （关、与这句一样长、这句的一倍半，后两种再加一秒），以及要不要自动进入下一句。默认值（播一遍、不停顿、不自动下一句）
   就是现在的行为。决策放进一个和 `planLoop` 并排的纯函数（`planShadow`：给定时间、句子、第几遍和设置，告诉你是播、等、
   退回、下一句还是停），不用浏览器就能测试；store 只负责执行。每次重播都带上提前起播，和循环一样。`Space`、切句或点进度条，
   都会干净地结束程序当前这一遍。打开停顿和自动下一句后，页面就能完全不用手地跑下去；这也足够接近同步影子跟读，
   不必为它单独做一个模式。
2. **揭晓放在一次盲说之后。** 英文在第一遍播放和它的复述停顿里都保持遮住，从第二遍起揭开；只播一遍时，在停顿结束时揭开。
   开了自动下一句时，揭开的句子会在屏幕上停留它那段停顿，再开始下一句。`R` 和按钮仍然随时可以揭开。提示和 README
   改写成实际发生的事。
3. **录音并对比。** 跟读设置里加一个麦克风开关。打开后，每段复述停顿都用 `MediaRecorder` 录下来；停顿结束时，页面先把原句
   再放一遍，接着放你的录音。一个「对比」按钮（以及一个按键）之后还能重放这一对。每句只保留最后一次录音，存在内存里，
   只属于当前打开的这一集，关掉就丢：从不写盘，从不发给 host，从不打分。录音在原素材暂停时，用一个临时的音频元素播放；
   那一个 `<video>` 元素仍然是原素材唯一的时间线。每次录完都关掉麦克风流，因为 iOS 在麦克风打开期间会压低播放音量。
4. **通过 Media Session 接实体按键。** `play` 和 `pause` 切换播放，`previoustrack` 和 `nexttrack` 切句，`seekbackward`
   重放这一句，元数据写上剧集名和第几句。这样 AirPods、有线耳机的按键、iPad 锁屏和会发媒体键的蓝牙遥控器，就承担起
   复读机实体按键的角色。它不是键盘监听，所以不碰「不许抢宿主键盘」那条规矩。

## Alternatives considered

- **用识别器给发音打分。** 第一版的 note 把它放下了，理由是它会「在习惯养成之前，就把听的习惯变成打分循环」；
  习惯仍然是重点，而分数会引人回去读文本，而不是再听一遍。口语上的反馈留在和 agent 的对话里。不在这份计划之内。
- **用分级提示（首字母、实词挖空）代替模糊。** 它们会在耳朵该工作的时候把眼睛拉回文本上，这正是这篇 note 要防的跑偏。
- **靠检测静音来结束复述停顿。** 比固定停顿顺手，但麦克风得一直开着、实时分析音频，而且结束时间不可预期的停顿，
  在不用手的时候更难依赖。等录音做出来、用过一阵再回头看。
- **整段录音，而不是一句一句录。** 复读机是按句对比的；一段长录音很难在里面找位置，也没法挨着它所属的那一句。
- **把录音存进 IndexedDB 或剧集目录。** 要处理配额、清理，还要为本来就该扔掉的东西讲清隐私。把录音发给 agent
  是以后另外的决定。
- **单独做一个同步影子跟读模式。** 不停顿加自动下一句的程序，已经是遮着英文一句接一句地放；第二个模式就是第二套要学的规则。

## Settled details

- **顺序。** 程序和揭晓（第 1、2 块）先做：它们修掉现在错的文案，也让页面不用手就能用。录音（第 3 块）最大，
  而且依赖程序创造出来的停顿。Media Session（第 4 块）很小，跟哪一块一起发都行。
- **控件放在哪里。** 「跟读」芯片留在播放行上；它的设置放进「更多」，挨着提前起播，播放行不变长。录音做出来之后，
  步骤卡片上跟读那条提示才名副其实。
- **第 3、4 块完成前要在真 iPad 上核实。** Safari 里 `MediaRecorder` 录的是 `audio/mp4`；关掉麦克风后播放音量能恢复；
  AirPods 的 Media Session 动作能到达页面；线上站点走 HTTPS，因为 `getUserMedia` 拒绝不安全的来源（localhost 例外）。
