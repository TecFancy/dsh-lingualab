# Agent Note: 调整时间时切到上一句或下一句

Status: proposed

## Problem

调整时间的面板一次只改一句。一个字幕文件不准，很少只错一处：往往是连续一段句子都晚了差不多的时间。要修好它们，
就得改一句、保存、关掉面板、切到下一句、再打开面板，一段里每一句都这么来一遍。面板打开时方向键用来微调边界，
所以页面上平常切句子的办法（`←` / `→`）用不了；面板不用的键也都被故意吞掉，免得误按一个键把正在改的句子换掉。

2026-10-12 提出的问题是：面板能不能自己切到上一句或下一句。下面的评估当天就被采纳了：这个功能已经列入计划，还没有做。

## Proposal

**面板里按 `↑` 和 `↓` 切到上一句和下一句**，面板头部再放两个小按钮给鼠标用。这两个键现在在面板里是空着的（被吞掉了），
所以不会改变任何现有按键的含义。

- **没改过：直接切。** 面板在相邻那一句上重新打开，循环跟着过去，播放头放到那一句的开头，和在那里打开面板一样。
- **改过：先保存，再切。** 当前这一句像按 `Enter` 一样保存，等字幕重新读回来后，面板在相邻那一句上打开。页面要在这次重新读取之间
  记住「在第 *i* ± 1 句上重新打开」，因为重新读取会换掉整个句子列表，按设计这会结束当前的编辑。保存不会改变句子的数量，
  所以这个序号之后仍然指向正确的那一句。如果保存被拒绝（文件已经变了，或者这一集不在库里），面板留在原处并显示原因，和现在一样。
- **被推动的相邻句，打开时已经是新位置。** 这次修改推动了下一句的开头时，这个推动会一起保存，所以下一句打开时就是新的开头，可以接着往下改。
- **列表两端什么也不做。** 在这一集或这一段的第一句、最后一句上，对应的键不起作用，按钮也是禁用的。
- **不能保存的剧集照样能切。** 这种剧集的面板本来也会打开，用来听；在句子之间切换对这种用途照样有用。

面板底栏加一条提示（`↑ ↓ 上一句 / 下一句`），做的时候也要同步更新调整时间那篇 note 里关于面板按键的描述。

## Alternatives considered

- **把好几句没保存的改动攒起来一起保存。** host 已经接受一次写入里最多六处修改，所以批量是做得到的。但跨句的草稿要处理草稿句之间的推动，
  而文件一旦变了，整批都会被拒绝，一下子丢掉好几句的工作。逐句保存让每一步都小、出错也能恢复。
- **切走时丢掉没保存的改动，或者先问一句。** 丢掉会让一次按键就丢了工作；弹确认框又会给这个本来要快的流程加一道对话框。
  保存代价更低，因为存下的边界还能用同样的办法挪回去。
- **只做「保存并到下一句」（`Shift+Enter`）。** 能覆盖最常见的往后走，但下一句一听发现上一句挪过头时，没法回去。
- **对一段句子整体偏移。** 一段句子偏得完全一样时更快，但调整时间那篇 note 已经把它放下了：实际的偏差是逐句的；
  而「字幕到处都晚一点」的情况，「更多」里的提前起播不改文件就能解决。

## Settled details

评估时留下了两个问题，计划被采纳时都定了下来。

- **切换时保存了，就说一声。** 面板在相邻那一句上重新打开后，短暂显示「已保存」（收藏面板已经在用的那条文字）。
  这次切换写了字幕文件，看不见的写入，用户事后容易起疑。这条提示不会拖慢切换，也不用手动关掉。
- **保留当前聚焦的那一端。** 一段不准的句子，通常错在同一端（每一句的开头都晚一点），所以面板重新打开时，聚焦的还是原来那一端。
  手动打开面板时仍然从开头开始，和现在一样。
