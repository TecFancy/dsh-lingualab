# Agent Note: 给右栏的展开收起加动画，并重排顶栏那一排按钮

Status: proposed

## Problem

0.15.0 让右栏可以收起了：右栏要么不渲染，要么排在舞台旁边，收起时宽度还给舞台。展开和收起都在一帧里完成。这是有意的：
[右栏可以收起](../../implemented/feature/2026-10-21-collapse-the-side-column.zh.md)那篇 note 没有采用宽度动画，
因为动画的每一帧舞台都要重新排版（画面、播放卡片的行数、调整时间的布局），而那正是收起想消除的跳动。

用了一天之后，这个切换看起来像一次跳跃。眼睛正看着列表里的某一句，按下 `\` 给舞台腾地方，视线落到画面上时画面已经变完了；
右栏回来时又是一下子出现，也没有任何东西表明它定位到的那一句就是刚才在播放的那一句。变化太突然，两个状态像两个不同的页面，
而不像同一行里有一块被藏了起来。

顶栏有同一类问题，只是发生在空间上，而不是时间上。顶栏上有返回按钮、带分段行的标题、分段选择器、收藏按钮、右栏开关、五步和设置。
0.15.0 让返回和收藏在窄于 720px 时只显示图标，并给每个按钮补足 44px 的点按区域，但这一排按钮仍然没有分组：

- 两个作用于右栏的按钮夹在分段控件和步骤追踪器中间；
- 设置、五步和右栏开关之间的顺序，看不出它们各属于哪一部分。

这一排是按「放得下什么」排的，而不是按「哪些东西属于一起」排的。

## Proposal

- **给右栏加一个短过渡。** 展开和收起用 160 到 220 毫秒：右栏的宽度和不透明度一起变化，舞台占的宽度在同一个过渡里跟着变，
  画面随着右栏一起变大或缩小，而不是等右栏变完再跳一下。在 `prefers-reduced-motion` 下仍然直接切换。
- **右栏消失之后仍然卸载。** 退场动画在一个包装层上执行，里面仍是当前那份列表；动画结束后移除包装层。重新挂载、定位到正在播放的
  那一句，这些行为都不变。
- **按「这个控件作用于什么」重排顶栏。**
  - 收藏按钮和右栏开关并成一组，与剧集控件（返回、标题、分段）分开，也与这一集的进度（五步）分开。
  - 五步和设置挪到最右边，自成一组，不常用的控件可以收进一个「更多」。
  - 44px 的点按区域、窄于 720px 时只显示图标、标题优先缩短，以及 `N`、`\` 的提示都保持不变。
- **先测量，再决定动画形式。** 那篇 note 反对的是每一帧的开销。在真实的 iPad 上，录一次右栏展开和收起时的性能记录。
  如果宽度动画能稳定在帧预算以内，就用它；做不到，就只做不透明度动画，让舞台在最后一次性变到位。记录这项工作的 note 要写清选了哪一种、为什么。

## Alternatives considered

- **保持直接切换。** 这是现在的决定，也最省事；不采用它，是因为这个要求是在实际用过之后提出来的，跳一下正是用户注意到的问题。
- **只做淡入淡出，宽度直接跳变。** 比宽度动画开销小，但两个状态之间差 260 到 440px，右栏看起来仍是突然弹出，舞台也仍然会跳。
- **给舞台做动画，不给右栏做。** 出现和消失的是右栏；只给舞台做动画，会让没有变化的那一部分动起来。
- **右栏保持挂载，只给它的宽度做动画。** 能保留滚动位置，但藏起来的列表无法跟随正在播放的句子，原来的决定正是因此没有让它保持挂载。
- **把顶栏的文字再多藏一些。** 省出的是像素，不是层次；按钮仍然按一个每次都要重新辨认的顺序排着。
- **把顶栏的控件全放进一个「更多」菜单。** 顶栏是清爽了，但收藏和右栏开关每次练习都要用，放进菜单就每次都要多点一下。
