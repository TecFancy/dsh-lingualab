# 文档与 note

写 note、改 README 或技能、定了一条新规矩不知道写在哪时读这份。

## 每份文档管什么

- **为什么这么做**：`.agents/notes/`。
- **现在是什么样**：`docs/` 和源码注释。README 只做介绍和指路，长文在 `docs/` 下，一份文档讲一件事。
  没有 `docs/INDEX.md`，README 里的文档表就是索引，`docs:check` 会把没人链接的文档判为失败。
- **怎么干活**：技能 `dsh-lingualab`。
- **每次会话都要知道的事**：`AGENTS.md`。

新增一份文档时，中英两份一起建，在 README 的文档表里加一行，再跑 `npm run bilingual:check -- --write` 记哈希。

## 新规矩写在哪

- 默认写进技能，其次写成一篇 note。
- `AGENTS.md` 只放每次会话都要知道的事。它每次都会被加载，写得越长，占的上下文越多，要紧的几条也越容易被忽略。
- 技能的 SKILL.md 也一样，只放每次加载都用得上的内容。只在某类改动里才用得上的细节，写进 `references/` 里对应的那份
  （没有合适的就新建一份），再在 SKILL.md「按需再读」的表里加一行。

## note 的写法

- 每篇 note 有三个文件：`.md`、`.zh.md`、`.i18n.yaml`。中文那份要真的翻译，不是英文的副本。
- 改了任何一份，就跑 `npm run bilingual:check -- --write` 重新记录哈希。
- 目录、命名和必须有的几节见 `.agents/notes/README.zh.md`。

## 中文怎么写

`npm run zh:prose` 查的是机械项：标点全角、中英之间一个空格、半角数字、第二人称只写你、专有名词大小写。句子像不像人话它读不出来，
这一半只能写的时候自己守。2026-10-22 把仓库里的中文改过一遍，用的就是下面几条。

- **标题写成一句结论。** 「每集 7 条的上限，两端都拦」改成「每集最多 7 条短语，服务端和面板都检查」，扫一眼标题就知道这一节要讲什么。
- **一段只讲一件事，讲不完就拆。** `docs/usage.md` 里讲添加素材的那一段，拆成三条一句话的清单，比一整段好读。
- **主语写人或具体的东西，谓语写看得见的动作。** 「用户只是想听一听，却得先弄懂什么是媒体目录」是在说事，
  「空状态提高了上手门槛」就不是。
- **照英文直译的词要换掉。** host 写服务端，client 写前端，slot 写插槽。`半边`、`你说的那遍`、`随路径变的替身` 这类说法，
  换成 `服务端和前端`、`刚才录下的那遍`、`随路径变化的替代值`。
- **用这个面板的人叫用户。** 不写「读者」。这是 10-21 的 PR #58 定的，英文那侧同样用 user。

改完跑 `node scripts/verify.mjs --fast`，它含 `zh:prose`。标题、清单、主语这几条它查不出来，提交前自己读一遍。
